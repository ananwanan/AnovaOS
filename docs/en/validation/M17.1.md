## Implemented scope

- The Rust `/bin/desktop` process owns a compositor and three existing, independently
  implemented C/C++/Rust GUI reference clients. A fourth connection/window belongs to
  the launcher. The existing GUI C ABI and native v1 records are unchanged.
- `init` starts the COM1 shell separately and waits for either child. Shell exit restarts
  only the shell; desktop exit leaves serial recovery available. Default boot is unchanged.
- Launcher buttons or keys `1`, `2`, `3` launch/stop the corresponding admitted client.
  Focus and dragging use the existing compositor. Key `r` replaces the session; `q` exits.
  Focus the launcher before using these shortcuts. Stop is immediate signal-15 termination,
  not an unsaved-buffer dialog or cooperative application shutdown.
- Every ordinary replacement/exit stops and reaps owned clients and the compositor.
  Client exits report actual reason/code. Compositor loss requests a fresh session.
  Automatic and requested restarts share a lifetime limit of three replacements.
  Persisted files are not modified; client buffers/surfaces are recreated, not restored.
- Compositor desktop placement uses visible rectangles, excluding hidden ABI-contract
  windows. It retains four clients/windows and maximum private surfaces of 320×240.

## Process boundary

`crates/abi/src/process.rs` defines a separate experimental syscall `0x101`.
RDI contains `(version << 32) | operation`, RSI an exact nonzero PID, and RDX the
16-byte native `WaitStatus` output address for POLL or zero for STOP. Version is 1.
Only the caller's immediate children qualify; PIDs are not reused. No path grants
display/input authority. Linux callers continue through the existing Linux dispatcher.

POLL returns WOULD_BLOCK without blocking the parent while a native child lives.
For an exited child it copies status before reaping; invalid output retains the zombie.
STOP is idempotent for an existing zombie, otherwise terminates an immediate native
child with signal 15. Live Linux children return UNSUPPORTED. Already exited children
retain the existing native-parent wait semantics. Peers, parents, descendants and
stale IDs return NO_CHILD. This is not a global task inspector or process-tree killer.

## Build and run

```sh
cargo xtask desktop-build
cargo xtask fetch
cargo xtask desktop-image
cargo xtask run --desktop
# Reuse an explicitly selected native-personality work disk:
cargo xtask run --desktop --disk build/disks/work.ext4
```

`desktop-build` builds native userland, the unchanged three GUI clients and a checked
native-only archive, without downloading the GCC/Rust Linux seed profiles. These clients
are **host-built** session inputs, not new guest-compilation evidence. Outputs and hashes
are under `build/desktop/`; the image is `build/images/anova-desktop.iso`.
`run --desktop` accepts only an optional disk, uses q35/TCG, one BSP, 3 GiB RAM,
800×600 standard VGA/PS2 and COM1. The default disk remains disposable ext2.
The opt-in kernel also admits the existing controlled writable ext4/JBD2 profile.

The prospective session has seven steady processes (init, shell, supervisor,
compositor, three clients). Ceilings remain 16 MiB heap, 32 task slots, 32 FDs/process,
128 open descriptions, 2,048 VFS nodes and four private GUI windows. These are declared
limits, not measured desktop resource peaks or build-concurrency acceptance.
