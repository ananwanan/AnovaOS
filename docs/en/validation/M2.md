## Limits and next task

Only the BSP exception/timer baseline is accepted. All external IRQ sources stay
masked; routing overrides/NMIs and device delivery remain untested. IST3 is
installed but actual NMI/machine-check delivery was not exercised. Time is a
coarse delivered-IRQ count and can lag while IF=0. No memory is reclaimed and
there is no allocator, user process or scheduling. M3 must establish explicit
memory ownership before replacing the retained boot stack/tables or adding a
frame allocator and heap. See [M2_CPU.md](../milestones/M2_CPU.md).

## Firmware I/O APIC identity follow-up (2026-11-14)

This section is independent of the 2026-10-21 evidence above. Source baseline:
`648a99ff95f1ee50759d859310461b6593d64a28` (`dev`); repair branch
`feat/fix-ioapic-boot`. The supplied `boot.log` stops at
`MADT/I/O APIC identity mismatch`, register ID 0 versus firmware ID 128.
The original VM is not rerun by this validation.

The repair uses the already checked MADT physical address to access each
controller. It reports both IDs, the address and `id_mismatch` only after every
redirection mask readback succeeds. It keeps the ID register unchanged and
retains LAPIC/BSP identity checks, firmware topology/address admission,
GSI range/overflow rejection and IF=0 serialization. All external IRQs remain
masked; programming/routing external interrupts requires separate acceptance.

The new `cargo xtask smoke --case ioapic-id-mismatch` selects an exclusive
QEMU-only feature. It changes just the first parsed MADT ID from 0 to 128
after normal ACPI validation. Controller addresses, GSI topology, actual MMIO
and per-pin mask operations are unchanged. The gate requires the reached
injection, register ID 0 at `0xfec00000`, GSI `0..24`, BSP destination 0,
`all_masked=true`, `id_mismatch=true`, the complete normal smoke checks and
QEMU exit 33. The normal 13 cases remain in `verify`, with this fourteenth
case added. Host negatives reject absent injection, wrong identity/address/
range/destination, missing mask/timer/completion evidence, wrong exit and timeout;
both LF and actual UART CRLF are accepted.

An initial harness experiment using QEMU `-acpitable` appended a second MADT
and correctly failed with `Duplicate MADT`; that protection was retained.
The final parsed-topology injection reproduced the original assertion before
the repair: `left: 0`, `right: 128`, QEMU exit 35, smoke command exit 1.
The failed test ISO SHA-256 was
`89f8cc7b48b8533e0b01af8002280aaeca2a50bd8caa2d39fb42880d52a29fac`.
Logs retain both experiments separately; no failed run counts as acceptance.

The local host is Ubuntu 24.04 under WSL2 with Rust/Cargo 1.90.0 and QEMU
8.2.2, using the locked OVMF/Limine inputs, q35/TCG, one vCPU and 256 MiB.
`cargo xtask doctor` passed. Strict host Clippy (`xtask`, `anova-platform`,
all targets) and separate kernel Clippy for normal, `test-ioapic-id-mismatch`
and `desktop-test` passed.

`cargo xtask test-host` passed all 271 tests (including 65 xtask tests).
Combining `test-ioapic-id-mismatch,test-panic` was rejected at compile time
with `Select only one boot injection feature` as required. Workspace formatting,
the bilingual documentation/link check (83 pairs, 175 Markdown files), file
purpose coverage (538 files) and `git diff --check` passed.

The first full `verify` attempt on the Windows-mounted workspace timed out
in the ordinary boot case during user-fault serial output, after the I/O APIC
masking and timer checks had passed. That result remains a failure. The rerun
uses an isolated checkout at `/tmp/anova-ioapic-20261114` on WSL's Linux
filesystem, the same baseline and exact kernel/xtask patch, and unchanged
