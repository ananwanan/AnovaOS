## Linux-host comparison

All three runtime profiles pass directly on native Linux, including the malformed
rt_sigreturn child, SIGILL group exit, thread exec/identity, wait status and PTY
foreground signals. Outputs are retained in build/logs/m9-native-*.out.
The same exact binaries also run under QEMU-user syscall tracing, with outputs
and traces under build/logs/compat-host-m9-*.

Native ptrace is prohibited in this environment. QEMU-user traces therefore
serve as syscall observations, not a native strace substitute for every child.
Same-architecture exec can leave QEMU-user. The native execution supplements that
boundary with complete final process/exit results.

Two explicitly recorded comparison limits are retained:

- Linux can permit W+X while AnovaOS deliberately rejects it. M9_HOST selects
  that known host policy for comparison; the guest gate still requires EACCES.
- QEMU-user 8.2.2 aborts internally on the deliberately malformed sigreturn.
  Only that host-emulator subcase is marked unavailable, with a distinct HOST
  marker. Native Linux and system QEMU execute it; the guest gate unconditionally
  requires bad_sigreturn=true. The failed emulator trace is preserved at
  build/logs/m9-qemu-user-bad-sigreturn.trace.

The shared-close fixture uses fd 20 to avoid QEMU-user internally reusing a low
host fd after a target close. It still checks an actual CLONE_FILES close across
threads. The earlier observation is preserved in m9-qemu-user-fd-reuse.trace.
Observed calls include clone, futex WAIT/WAKE/REQUEUE, mprotect, sigaction/masks,
rt_sigreturn, poll/ppoll, ioctl, setsid, tkill/kill, fork/exec and wait4. These
observations exposed the required real REQUEUE path rather than a success stub.

## Actual guest acceptance

Each of the three independent Ring 3 programs runs the full measured workload.
The kernel and host classifier require successful exits plus exact cleanup.

| Area | Required actual result |
| --- | --- |
| pthread/TLS | Two workers, private compiler TLS, mutex/condition rendezvous, 1,000 checked increments, join values and shared-fd close |
| futex/shared pages | Value mismatch/alignment/timeout errors; actual wait/wake/requeue; forked MAP_SHARED data and cross-process futex |
| Signal ABI | Real user handler, siginfo sender, rt_sigreturn, XMM7 restored after handler clobber, EINTR and SA_RESTART pipe read |
| Masks/time | Pending blocked signal and ppoll temporary-mask restoration; interrupted nanosleep with positive remainder |
| Readiness | Nonblocking empty pipe -> EAGAIN, finite timeout, child write wake, EOF/HUP and invalid-fd NVAL |
| Thread lifecycle | Nonleader exec becomes leader identity, caught action resets, missing interpreter -> ENOENT with caller alive, SIGILL kills group, thread exit_group and malformed sigreturn status |
| Stop/continue | Child stops itself, parent sends SIGCONT, child resumes and is waited successfully |
| PTY/termios | Real master/slave pair, initial lock rejection, canonical line/echo, raw bytes, output polling, foreground Ctrl+C and peer-close EIO |
| Dynamic runtime | Actual musl PT_INTERP, startup shared library, dlopen after worker creation, initialized per-thread dynamic TLS and named missing-library error |
| Protection | PROT_NONE retains backing; mprotect enables the chosen data page; W+X rejected; unmap succeeds |
| Reclamation | Each program restores physical frames and heap, with zero tasks and open descriptions/pipes |

Shared ownership metadata has a separate test that exhausts the actual 2 MiB
kernel heap through fallible allocations down to the allocator's minimum block.
Fork, exec and spawn fail with NO_MEMORY, original root/fds survive, all partial
resources roll back, and freeing pressure restores the exact heap/frame counts.
This tests the fallible Shared implementation rather than relying only on an
injected page-allocation budget. Its two host tests separately check single final
destruction, unique mutation and the allocator-returned-null path.

The 13 QEMU cases were boot -> exit 33, panic/OOM -> exit 35, timeout ->
watchdog after the reached TEST:HANG, and nine reached exception/protection
injections -> exit 37. Expected failures are accepted only by the verify
classifier; directly running those smoke cases still returns a failure.

A resumed UART run exposed a host-runner panic when a reread diagnostic file was
shorter than its previous matching cursor (`byte index 13438 is out of bounds`).
The UART and persistence runners now consume an ordered stdout pipe and match
raw bytes in an accumulated transcript. The diagnostic file is an output sink,
not the source of matching state. Final output is drained after guest exit, and
reader/log-write failures propagate. Two added host tests cover split markers,
incomplete UTF-8, an out-of-range cursor, EOF draining and failed log writes.
The complete UART and persistence sessions passed after this correction.

## Regression contract

The normal boot must return isa-debug-exit 33. Controlled panic/OOM must return
35; real exceptions must return 37 with the exact injection/vector/IST/error/
address evidence. Timeout must reach the actual TEST:HANG before watchdog
termination. A firmware/startup timeout cannot satisfy that negative case.

An initial eight-second timeout could expire before kernel entry with this M9
image/environment. Verify now uses a bounded 30 seconds for every scenario,
including the deliberate hang, while preserving the real-injection checks.
The unreached eight-second transcript remains in m9-timeout-8s-unreached.serial.log.
Multi-image verification builds user space once and rehashes its immutable build
snapshot before reuse; altered artifacts fail instead of being silently reused.

The declaration remains bounded: no SMP, general Linux/glibc, complete terminal
jobs, alternate signal stacks, robust/PI futexes, realtime signal queue, COW,
persistent-file mmap, networking or guest-hosted compiler is inferred from these
results. M10 is the next milestone.
