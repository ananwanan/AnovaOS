# M18.4: repeat and recovery evidence by component

**English** | [简体中文](../../zh-CN/validation/M18.4.md)

## Base optical image route

Two independent fresh JBD2 ext4 work disks produced byte-identical 25,620,480-byte ISOs
with SHA-256 `9ee587c3725309a63ad21b7c96057d1eaa3db8fce49afdbc4ae1a0bc3cd08a7b`.
Both rounds consumed the same authenticated guest-built kernel and checked boot, application
and initramfs inputs. Independent host extraction verified all 19 regular-file paths and
contents. Both final images booted and matched the retained kernel identity. This compares
image output under identical inputs. Independent kernel construction has its own
[M15.6](M15.6.md) and [M16 capacity](M16_CAPACITY.md) evidence.

The report distinguishes build, reboot, publication rejection, cancellation and pressure.
The pressure run reached 16,384 allocated blocks and rejected the write with `ENOSPC`.
Its next boot used the previous ISO, kept exact user bytes, released the reserve and
proved new writes could reuse the released capacity. The 21 ms COM1 observation is for
the actual cancellation test. See [M18.3](M18.3.md) for all six sessions, original logs,
budgets, relative evidence paths and input provenance.

## Compiler routes

The standalone LLVM profile built, archived and linked the same six upstream translation
units on two clean work disks. The archives and test executables matched exactly, with
SHA-256 `115729861d9765babf31151e3266946e04d8d743c4fc79814c88dd7ed32371d2` and
`d7de9798b1b32a14e06ee731f93857fd9587a056e33680ddc4e03dcf4d1e86b5` respectively.
Both reboot runs retained the previous archive, executable and work bytes through a real
syntax rejection and missing-library link failure. Relinking from the retained archive
produced byte-identical executables again. The [LLVM run](M18.2.md) retains dependencies,
measurements and actual diagnostic logs. LLVM cancellation, resource exhaustion and
publication failure need their own component-specific tests.

The [GCC prerequisite profile](M18.1.md) has separate evidence. Full GCC, rustc, Cargo,
LLVM backend, GUI-enabled kernel and multistage compiler repeat/recovery remain open.
