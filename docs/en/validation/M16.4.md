# M16.4: controlled ext4 writes

**English** | [简体中文](../../zh-CN/validation/M16.4.md)

Implemented 2026-10-27 on `feat/m16-ext4-write`, based on M16 foundation `e6c67af`
(itself descended from `dev` `616ff47`). This extends the [readonly checkpoint](M16.md).
Local verification is recorded below; remote CI, M16.1 budgets, JBD2/M16.5 and
work-volume migration/M16.6 have separate acceptance requirements.

## Admission and explicit activation

The ordinary kernel and `Filesystem::mount` keep ext4 readonly. The `ext4-write`
kernel feature, `Ext4::mount_writable`, or an explicit `mount_with_ext4_writes`
request enables **ext4-write-v1** only after a full bounded audit. A device-protected
readonly disk stays readonly even under the writable kernel.

The profile is e2fsprogs **1.47.0**, 4 KiB blocks, 256-byte inodes, local block
groups and linear directories, with COMPAT=0, INCOMPAT=`0x42` (extents/filetype),
and RO_COMPAT limited to sparse_super/large_file. Journal-bearing, recovery-required,
dirty, checksummed, 64-bit, flex/indexed, xattr and unknown-feature layouts are rejected.
The mount audits bitmap padding, reserved blocks/inodes, group/global free counts,
unique block ownership across all admitted inodes, directory types/link counts,
dot/dot-dot and rooted parent chains. It rejects leaked/double-owned allocations,
unsupported types, hard-linked regular files and non-root owners/special modes.

```sh
cargo xtask ext4-image --linux build/disks/work.ext4
cargo xtask run --ext4-write --toolchain --disk build/disks/work.ext4
cargo xtask foundation-write-test
```

Omit `--linux` and `--toolchain` for a native-ABI work image. Image creation uses
`create_new` on a regular file under `build/`, never an existing image or device.
Default ext2 creation/boot remains available. Exact creation options:

```sh
mke2fs -q -t ext4 -b 4096 -I 256 -g 256 -N 128 -m 0 \
  -O none,extent,filetype,sparse_super,large_file \
  -E lazy_itable_init=0 -d SOURCE work.ext4
```

The helper creates an 8 MiB image with immutable `.anova-abi`, a temporary directory,
first-party source/Makefile and a separate read-error fixture. No conversion or
default-disk promotion occurs.

## Semantics and resource bounds

| Operation | Implemented contract |
| --- | --- |
| File data | Create/exclusive create, overwrite/append, read, truncate and grow/shrink to 256 MiB; checked offsets; holes/unwritten extents return zeros; imported EOF padding and reused blocks never expose stale bytes. |
| Allocation | Multiple block/inode groups, matching free counters and used-directory counts; coalesced extents and bounded external extent leaves; final deletion frees data/tree blocks and inode. |
| Directories | Linear record reuse/growth, mkdir/rmdir, cross-parent file/directory rename, empty-directory and file replacement, correct dot-dot/parent links, cycle/type/nonempty rejection. |
| Lifetime | Rename/unlink retains old descriptor identity, dup/fork shared offsets and readonly shared mappings. A new name cannot alias a retained orphan. Final close/unmap reclaims; allocation failure keeps a pinned retryable identity. Deferred OOM cleanup does not turn a published unlink/rename into a reported failure. Replacement of a live cwd is rejected as busy. |
| Modes/times | Root-owned permission bits `000..777`, executable admission, second-resolution atime/mtime/ctime; chmod changes ctime, data changes mtime/ctime, explicit times preserve omitted fields. Reads use noatime. No multi-user/ACL/set-ID contract. |
| Unsupported | Hard-link/symlink creation, arbitrary Linux ext4 features, writable shared mappings and shrinking active mapped files remain unsupported. Native syscall v1 is unchanged. |

The writable audit accepts at most 16,384 inodes, 128 groups and 256 directory blocks
(1 MiB) per directory. Extent traversal retains the readonly depth/1,024 extent/64 tree-block
bounds; write reconstruction uses an inline root or at most four extent leaves.
Each operation stages at most **1,024 total changed 4 KiB blocks** (data plus metadata).
Allocation exhaustion or that staging ceiling returns `NO_MEMORY`; disk/inode/extent/directory
capacity exhaustion returns `NO_SPACE`. Smaller sequential writes can construct larger files.
The 16 MiB kernel heap, 2,048 node slots, 128 shared opens, 32 tasks/descriptors and
1 MiB readonly mapping-cache bound are unchanged. Format bounds are not a capacity benchmark.

## Ordering and failure boundaries

All fallible allocation, reads, bitmap changes, namespace updates and counter/tree
construction happen in an unpublished overlay. Preflight ENOSPC, OOM, invalid input
or read failure discards it: existing disk bytes, names, lengths and shared offsets
remain unchanged. VFS reserves cache/open capacity before creating persistent objects.

Commit persists and flushes a dirty superblock before data/metadata writes. It writes
data, flushes, publishes staged metadata/counters and flushes again. There is no
allocation during publication. A write/flush error poisons the mount: subsequent
operations/sync/shutdown fail, and the volume is never reported clean. Clean-marker
write/flush failure attempts to restore dirty state; an unavailable device cannot
guarantee that this repair reaches media.

**This is not a journal or crash-atomic transaction.** An I/O failure after publication
starts may leave partial changes and requires offline recovery; the original failed
image is retained. Old-output preservation is verified for preflight failures and
the declared failed compiler invocation, not arbitrary interrupted metadata commits.
`sync`/`fsync` flush but leave the volume dirty. Successful shutdown requires orphan
reclamation and a flushed clean marker. Only stopped clean images are required to
pass `e2fsck -fn`; passing clean reboot does not establish power-loss recovery.

## Local verification

The reproducible host tests use actual `mke2fs` images, persisted byte comparisons
and independent `e2fsck -fn`, not a mocked inode implementation. A thread-local
System allocator returns real allocation failures at every successive preflight
allocation for create, write, resize, rename, unlink and final reclamation. Separate
VFS tests inject final-close/final-unmap reclamation OOM and verify retry/pinning.
Device tests distinguish recoverable preflight reads from poisoned write/flush commits.

`foundation-write-test` builds the explicit writable kernel and inherited guest
GCC/make image. It verifies real Linux/musl file operations, directory/cwd moves,
fork/dup, mapping coherence, native heap exhaustion, actual ENOSPC, `make`/GCC and
BusyBox reads, failed source compilation retaining the prior executable, clean
shutdown/reboot, exact metadata and independent ELF hashes. Separate retained disks
inject completed virtio data-read, write and delayed-flush errors; a device-readonly
boot checks complete image immutability. QEMU uses q35/TCG, one BSP, 1 GiB RAM;
the main boot has a 240-second deadline and subsequent fault/reboot boots 120 seconds.
