# M5 validation record

**English** | [简体中文](../../zh-CN/validation/M5.md)

This document records measured native-process scheduling, CPU/FPU preservation,
blocking, lifecycle and reclamation results. Recorded 2026-10-21 (Asia/Shanghai),
branch `feat/m5-process-scheduler`, based on merged M4 `dev` revision
`9795803929c833569a87f9ec19c28d64caa09961`. The introducing commit identifies
this implementation. Design and exact ABI: [M5_PROCESSES.md](../milestones/M5_PROCESSES.md).

## Host and inputs

- x86_64 Ubuntu 24.04.3; Rust/Cargo 1.90.0, rustfmt 1.8.0-stable and Clippy 0.1.90.
- GCC 13.3.0, xorriso 1.5.6, QEMU 8.2.2 (`1:8.2.2+ds-0ubuntu1.18`).
- q35/TCG, qemu64, one CPU, 256 MiB, no network or data disk.
- Host Rust components were fetched from the official 1.90.0 distribution and
  SHA-256 verified against its channel manifest. Host QEMU/xorriso packages were
  apt-verified and extracted to a private tool directory with library/module/
  firmware wrappers. No repository change depends on those local paths.
- Bootloader, protocol and OVMF identities/checksums remain unchanged in
  `boot/dependencies.toml`. The cached inputs were checked by `doctor` and the
  image builder. Native ABI identities and exact ELF hashes are in generated
  `build/apps/manifest.toml` and included in the ISO.

## Actual multiprocess boot

The test ELF starts a parent and two workers with distinct live register values.
Thirty million-iteration assembly loops contain no syscalls and check GPRs,
both 64-bit lanes of XMM0–15, x87 stack/control and MXCSR after real timer
preemption. Both workers print their successful preservation result. A separate
child actually executes UD2; its parent receives reason=1/code=6 while both
workers continue and exit 0. This requires hardware entry and saved state,
not only simulated scheduler transitions.

A recorded complete boot reported:

```text
[SCHED:TEST] preemptions=122 preempt_switches=97 switches=176 sleeps=4 waits=19 idle_halts=7 forks=2 execs=1 spawns=55 reaps=57
```

Counters vary with timing. The gate requires at least two preemptive switches,
actual blocked waits/sleeps and idle HLT, at least two forks, a successful exec,
55 spawns, and reaps equal to spawns plus forks. Every one of these six user
case markers is required exactly once:

| Case | Required observed behavior |
| --- | --- |
| preemption-fpu-fault | Two CPU/FPU-preserving workers finish despite a child #UD |
| fork-private-fd | Child sees copied memory, changes its own page and closes only its own stdout; parent state stays live |
| fork-cpu-state | Fork occurs with live GPR/XMM/x87/MXCSR sentinels; both copies verify inherited state |
| exec-reset-retain-fd | New image has fresh BSS/FP controls while the previously closed stdout stays closed |
| wait-any-orphan-repeat | wait-any, target status, double-wait rejection, orphan reaping and 16 create/wait cycles |
| capacity-reuse | Parent plus 31 children fill all 32 slots, next spawn fails, all statuses reap, another child succeeds |

The parent also checks unknown module, invalid nested request/output pointers,
wrong layout size and sleep deadline overflow. C hello exercises yield/sleep/
close independently. Historical M4 applications, 11 isolation cases, exact copy
fault fixups and eight repeated Rust runs still pass before this suite.

Dedicated kernel tests limit user-page allocation to three pages during fork,
exec and spawn. All fail after partial work with NO_MEMORY, restoring exact
frame and heap usage. The old exec root and closed descriptor remain intact;
no child slot stays published. This is deterministic allocation-budget OOM,
not an assertion that those cases exhaust all RAM. M3's real frame exhaustion
and recovery tests remain in the boot gate.

For every complete session, resources are destroyed on the permanent kernel
root. The free-frame count and buddy-heap usage equal their pre-session values;
all slots are empty and descriptor ownership is gone. The classifier requires
these results plus QEMU exit 33 and rejects absent/altered process evidence.

## Boundaries and remote CI

This is a single BSP with user preemption and a non-preemptible kernel, one
thread per process, eager pages and fixed bounds. Images come from the native
module catalog. Only stateless console output descriptors exist. No filesystem,
input shell, persistent storage, Linux ABI, SMP, general threads/signals/COW or
guest-hosted compiler is claimed. Sleep uses delivered coarse timer ticks.

GitHub Actions is configured for the same checks; its remote status and PR are
reported with the delivery rather than inferred from local success.
