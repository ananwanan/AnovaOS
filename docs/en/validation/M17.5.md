# M17.5 graphical development validation

**English** | [简体中文](../../zh-CN/validation/M17.5.md)

## Reproduce

```sh
cargo xtask fetch
cargo xtask toolchain-build
cargo xtask rust-build
cargo xtask desktop-monitor-test
cargo xtask desktop-workflow-test
cargo xtask desktop-build-test
cargo xtask desktop-files-fault-test
```

The declared test boots use QEMU q35/TCG, one BSP, 3 GiB RAM, OVMF,
800×600 VGA, PS/2 input, an independent COM1 transcript and one fresh Linux
personality JBD2 disk per recipe. Reboot uses the same disk. C retains
the 35 s build ceiling. New C++ and Rust recipes have a 120 s build
ceiling, a 600 s per-boot watchdog and the existing 500 ms build observer.
The interaction ceiling is 5 s. Resource sampling at scheduler boundaries
measures allocator counts rather than precise process memory or CPU time.
The compiler test ceilings are 12 MiB allocated heap, 131,072 additional
4 KiB frames, 32 occupied task slots, 32 FDs in one process and 2,048 VFS
backing slots. The runtime has a 16 MiB heap, four PTYs, four GUI reservations
and one active build.

The observer enters all source text with physical QMP input, saves in Files,
builds in the launcher, runs the guest artifact in the graphical terminal and
uses Services to power off. Serial commands independently read source bytes
and verify live COM1. Stopped-disk copies retain staged observations, and
`debugfs` and `e2fsck -f -n` independently check the disk. Absolute host
paths and raw records are under the timestamped `build/desktop-workflow-test/`
directories. The [workflow contract](../milestones/M17_WORKFLOW.md) describes
the fixed recipes and the publication boundary.

An observation during compilation requires both a newly echoed key on scanout
and a COM1 status before the exact compiler leader exits. Cancellation is
sent to the live leader, followed by independent peer and COM1 input during
the cancellation recovery check. The C pressure case holds eighteen real
Linux children in the terminal while GCC runs and waits for their actual
release. The inherited long-output gate covers the separate 220,000-byte
fixture under actual peer/COM1 input.

Publication fault cases boot independent copies of the previously verified C
disk. A distinct source is saved graphically. QEMU injects one real write or
flush failure into the next persistent staging copy after a zero compiler
exit. The observer compares the old ELF on the stopped disk, runs it after an
ordinary guest recovery mount, clears the retained staging path and verifies
the new program's bytes and status after retry.

## Local results

On 2026-11-14, run `1794629185306963286` completed the six language boots on
Ubuntu 24.04 WSL2 with QEMU 8.2.2 and Rust 1.90.0. GCC and G++ were the locked
source-built 11.2.0 tools. C++ used two translation units, `std::string`,
`std::vector`, RAII and the actual C++ runtime. Rust used the checked upstream
rustc, matching musl std and the guest linker. The source was entered and
compiled inside AnovaOS for all three cases.

C printed `C-ANSWER-42`, C++ printed `CPP-42` and `RAII`, and Rust printed
`RUST-42` before and after reboot. The accepted source and ELF bytes matched
each shutdown/reboot pair. All three cancelled attempts reported signal 15.
The C pressure case built in 1,892 ms, observed peer pixels in 64 ms and COM1
in 241 ms with eighteen additional Linux children. Each closed attempt
reaped its tagged family and cleared volatile/persistent staging on the
healthy mount. Full SHA-256 values are retained with the run.
Independent C++ and Rust cancellation retests observed both channels before
sending the stop to the live compiler. C++ measured 65 ms for peer pixels
and 225 ms for COM1. Rust measured 64 and 806 ms. Both runs retain the
subsequent GUI response, signal status and exact prior output through reboot.

Both publication fault cases also passed, for ten boots in the complete gate.
The compiler exited zero before virtio reported write or flush status 1. The
launcher reported `published=false error=-21`, reaped the family and removed
the volatile output. COM1 responded in 141/151 ms. On both recovery boots the
retained ELF produced `C-ANSWER-42` and exit 7. The distinct replacement ran
with exit 19 after retry. The recovered images passed independent e2fsck.
The raw publication and recovery UART/QMP, peer and reboot scanouts, boundary
samples, source and artifact hashes are in the
[portable evidence](../../assets/validation/M17_WORKFLOW_LOCAL.json).

Earlier rejected runs remain available. PM timer observations attributed the
first compiler-load interaction timeout to repeated synchronous JBD2 writes.
One linker writev took 2,120 ms and several subsequent calls took 434–585 ms.
Volatile linker output and 64 KiB publication chunks reduce those commit counts.
Terminal row uploads reduce the scanout work for a single echoed character.
The earlier C observer also left its probe key in the shell, which caused a
real status-127 command. The corrected observer deletes the typed key before
running the artifact. QMP now sends the shutdown make and break together,
then requires the actual clean marker and a successful QEMU exit.
Two later observers exposed that the compositor's pointer covered the prompt
and that a shutdown panel sequence could reach the terminal if it still held
focus. The final gate positions the pointer outside the text, checks a fresh
echo and focuses the launcher before shutdown.

## Related regressions

The declared profile uses real virtio and JBD2 inside the guest. The successful
workflow, Files fault and M16 storage retries used ordinary image files in a
RAM-backed host filesystem. Earlier WSL disk-backed runs produced actual
2,000 ms virtio FLUSH timeouts and a 5 s Files save failure. The original
timeouts, writeback mode, guest durability checks and fresh QEMU boots were
retained. This profile measures recovery after specified device failures and
QEMU restarts while the host remains running.

`desktop-build-test` preserved the earlier 0x104 gate and verified 0x106
bad usercopy, result retention, owner/stale identity, detached cancellation,
staged-path replacement rejection and publication admission. Its real long
output reached 220,000 bytes, retained an 8 KiB tail and observed a peer
key-to-scanout upper bound of 2,956 ms and COM1 in 60 ms. Task/FD, global-open
and PTY exhaustion used the existing ceilings. The separate Files fault gate
passed all 16 cases and 43 boots with the original storage and latency
assertions.

## Limits

The monitor and earlier desktop profile cover actual client/compositor faults.
Compiler coverage uses fixed recipes and the existing 1 MiB tmpfs per-file
ceiling. PM hardware-counter observations still reached 2,420 ms inside one
Rust `munmap`. The measured GUI entries are discrete probes within each
workload. COM1 includes host observer scheduling and polling. M16 remote CI,
physical hardware, arbitrary power loss and M18 compiler reconstruction and
guest-only image generation have separate acceptance.
