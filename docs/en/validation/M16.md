## Backend/cache contract

VFS owns a capability-described filesystem instead of `Ext2`. Mount publishes
only the root and immutable ABI marker. Lookup is on demand and readdir uses
bounded backend cursors independent of inode/cache identities. Native v1 wire
layouts stay unchanged; Linux getdents returns the actual next directory cookie.
Persistent stat identities remain stable across regular-file cache eviction.

Node vectors grow fallibly from 32 slots to the existing 2,048-slot quota. Unopened,
unmapped regular-file nodes can be evicted without freeing their disk inode.
Directories/cwds, open descriptions, active mappings and the marker are pinned.
This does not promise unlimited directories. Slot reservation precedes persistent
mutation; inode exhaustion, descriptor/OOM rollback, shared offsets, unlink/open
lifetime and mapping coherence remain checked. A synthetic 10,001-file backend
isolates node pressure; independent ext2 tests cover uncached children, rmdir,
rename, persisted timestamps and retained opens. Directory traversal alone does
not fill the cache. The actual ext4 guest independently reads 10,001 files.

## Exact readonly ext4 profile

Test tools: e2fsprogs **1.47.0**, Rust **1.90.0**, QEMU **8.2.2**, locked Limine
9.5.0 and OVMF 2024.02-2ubuntu0.9. The guest gate uses q35/TCG, one CPU, 256 MiB
RAM, no NIC and the normal native boot image. Images are ordinary new files.

```sh
mke2fs -q -t ext4 -b 4096 -I 256 -g 1024 -N 16384 -m 0 \
  -O none,extent,filetype,sparse_super,large_file \
  -E lazy_itable_init=0 -d SOURCE NEW_IMAGE
cargo xtask foundation-test
```

The 64 MiB fixture has 16 groups. Accepted feature words are compat=0,
incompat=0x42 (filetype/extents), ro_compat subset=0x3 (sparse_super/large_file).
No journal, checksums, 64bit, flex/meta groups, indexed directories, xattrs,
symlinks, hard links or special files are accepted. Unsupported or recovery-flagged
images fail closed. Only regular files/directories and whole-second timestamp
fields are exposed. File size is at most 256 MiB; tree depth is at most three,
with at most 64 external tree blocks and 1,024 extents per loaded inode. At most
128 local groups are admitted. Unknown feature combinations never enable writes.

Checked geometry, sector capacity, inode/block allocation, metadata reservations,
extent ordering/ranges/overlap, cycles and per-inode block accounting bound each
read. This is not a complete in-kernel fsck or general ext4 compatibility claim.
Sparse and unwritten extents return zero; independently injected existing bytes
under an unwritten extent remain invisible. Five real-image host tests cover
20 MiB external/fragmented extents, 200 MiB sparse files, directory cursors,
read errors, unknown/dirty geometry, metadata aliases, cycles, overlaps and
unallocated references. The readonly device counts all attempted writes/flushes:
none occurred. Valid stopped fixtures pass `e2fsck -fn`.

The four-boot gate runs on a writable device and again on a readonly device,
checks exact patterns and actual `/persist/hello-c` execution/status, reboots,
then rejects recovery-flagged and unknown-feature copies while retaining the
serial shell. Every original/rejected disk is hashed before/after its session;
valid stopped disks pass e2fsck. Positive sessions have 120-second deadlines;
negative sessions retain the 60-second watchdog. This measures full sessions,
not foreground latency. No successful flush is faked for a writable filesystem:
the readonly backend simply has no dirty state or device-write/flush path.

Each run retains its ISO, initramfs, source fixtures, original and rejected disks
and result JSON under `build/foundation/readonly-TIMESTAMP/`; UART/QEMU logs are
`build/logs/foundation-*.{serial,qemu}.log`. The result hashes sorted first-party
source/configuration bytes (length-prefixed path and bytes), verifies source
stability, and records ISO/disk hashes, machine profile and timing. Documentation
is excluded from that implementation digest and updated after acceptance.
