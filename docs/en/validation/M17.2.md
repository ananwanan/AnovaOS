## Actual acceptance

`cargo xtask desktop-pty-test` passed two ordinary desktop-kernel QEMU 8.2.2 q35/TCG
boots with one BSP, 3 GiB RAM, 800×600 VGA, PS/2, an independent COM1 shell and a fresh
64 MiB Linux-personality ext4/JBD2 work disk. Rust is 1.90.0, musl 1.2.4, BusyBox
1.36.1 with a separately recorded job-control config, GCC 11.2.0 from the existing M11
source-build recipe, and e2fsprogs 1.47.0. No kernel/compiler/image self-hosting is claimed.

[Retained evidence](../../assets/validation/M17_PTY_LOCAL.json) contains exact implementation
hashes, input/tool identities, complete successful UART/TCP-QMP transcripts, command/result
records, stopped-disk bytes/hashes and compressed original QMP PPM images. These are real
scanouts, checked using independent literal font/color samples, not generated images or
an all-pixel golden reference. Decode each `gzip_base64` value with Base64 then gzip and
verify its decompressed SHA-256.

1. Before opening the terminal, `terminal check` fills all four actual PTYs and rejects a
   fifth; checks malformed/address/transfer bounds (version decoding is host-tested), foreign creator and stale ID,
   failed-read-copy retention, status-copy retention and a shell's actual status 17. Real
   task-slot exhaustion rejects START and rolls back its master. Native forked holders fill
   the actual per-process/global description pools; release restores PTY creation.
2. Physical launcher `t` replaces one GUI client with the native terminal. Actual keyboard
   input launches `/linux/pty-fixture`: distinct known stdout/stderr writes appear in green/red
   after the PTY merges them. The following command expands `$?` to 23 on scanout. No stream
   origin is inferred from the merged bytes. A real stopped-child WUNTRACED/WNOHANG/continue
   fixture renders `JOBS-OK`.
3. Physical Backspace changes a command from `EDIT-X` to `EDIT-Y`, then redirection saves
   `EDIT-Y\n` on disk. COM1 independently reopens it. A running Linux child renders
   `SPIN-READY`; COM1 responds while it is live. Physical Ctrl+C terminates that foreground
   child and the shell renders `INTERRUPT-130`.
4. A throttled 600-line child remains active during a physical bottom-right resize from
   50×26 to 46×24 cells. Actual output reports `WINCH-SEEN` and `SIZE ROWS=24 COLUMNS=46`.
   History reaches exactly 256 lines, evicts old lines and records dropped counts. Physical
   Shift-PgUp/PgDn browses/returns, and the surviving C GUI peer still receives physical input.
5. Physical Ctrl+D produces real EOF/shell exit. F5 starts a strictly newer session. Through
   graphical keyboard input, `/bin/gcc /etc/terminal-hello.c -o /persist/pty-app` compiles the
   actual source, reports `BUILD-0`, and `/persist/pty-app` renders `M17-COMPILED`/`RUN-7`.
   A separate fixture forks a descendant that calls setsid. Stopping its native creator from
   the launcher closes/reaps that family; relaunch works. F4 closes the replacement terminal.
6. Repeating `terminal check` establishes 25 free task slots versus the initial 24: the
   third original GUI client is now absent, with no leftover terminal, shell or escaped child.
   Each pressure check ends with four serialized START/CLOSE cycles whose sampled heap,
   free frames, open descriptions and pipes exactly match their own pre-START snapshots.
7. Clean session exit/shutdown, independent e2fsck, ordinary reboot, graphical reopen and
   graphical execution of the exact same saved program all pass. Work, program and ABI
   marker bytes match across both stopped-disk dumps; the mounted personality is not changed.

## Problems found and corrected

Whole-frame synchronous GUI upload could overflow the input-event queue and lose the start
of a quickly typed command. The terminal now uploads one acknowledged chunk at a time,
polling keyboard and PTY data between acknowledgements. Raster snapshots remain stable
until PRESENT; geometry invalidates an obsolete frame. The shell initially returned 255
because job-control wait used unsupported WUNTRACED; actual stopped-child notifications,
copy-before-consume and blocked-wait wakeup now implement that measured requirement.

The host driver also had two observation defects: the real mouse cursor could cover glyph
samples, and waiting from an advanced UART cursor could miss an already-recorded resize.
Captures now park the cursor outside the terminal and use a pre-action transcript position.
Peer coordinates come from that client's actual window record, not assumed launch order.
Restart resets an incomplete ANSI string so a previous producer cannot hide the new shell. The detached-family fixture now waits for a post-setsid pipe handshake and uses the accepted nanosleep path; its earlier unsupported pause loop and original UART observation are retained separately.

The host lacked the completed M11 stage. The unchanged recipe was built using its checksum-
locked inputs. The primary musl download returned 503; a Buildroot mirror supplied the exact
same locked SHA-256. An isolated verified Ubuntu m4 package and restoration of executable
modes from the verified bootstrap archive repaired host prerequisites. This is host source
construction of the existing guest seed, not guest compiler reconstruction.

## Regression and remaining scope

Validation results are retained with the evidence. Preserve `desktop-test`, `terminal-test`,
`verify`, `toolchain-test`, host tests, strict host/native/kernel Clippy, formatting,
bilingual links and file-purpose checks. The new main-only CI step runs the full PTY gate
after the existing M11 toolchain gate; no feature-branch/manual workflow was triggered.

The smaller `desktop-pty-test --without-toolchain` is a runtime-only option and cannot
establish compilation. Full-screen terminal editors, Unicode/IME, arbitrary ANSI/xterm,
WCONTINUED, wait-by-group, complete background/multithreaded job control, reliable graphical
source editing and all-GUI C/C++/Rust workflow remain independent. M17.3 files/reliable
editing is next. This tests clean shutdown/reboot, without adding new power-loss guarantees.
