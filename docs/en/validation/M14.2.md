## Actual controller, injected events and scanout

`cargo xtask input-test` boots a graphics-enabled, `input-test` kernel. QMP
`input-send-event` and `send-key` drive the actual emulated i8042/PS/2 path;
the host does not call a decoder directly to establish input delivery.

The controller explicitly selects keyboard scan-code set 1 with translation
disabled, and resets the mouse to standard ID 0, relative three-byte packets
with 1:1 scaling. Initialization checks interface tests, the controller self-test,
reply source, ACK/RESEND and mouse identity. Waits have a 100 ms ACPI PM timer
deadline plus an independent finite attempt budget; RESEND retries stop at three.
IRQ1/12 and all external device interrupts remain masked. The permanent kernel
root's scheduler loop polls at most 64 bytes and drains at most 64 queued events.
No device access, cursor drawing, allocation or logging occurs in an input IRQ.

The normal QEMU profile validates eleven ordered physical-key transitions:
A press/repeat/release, extended Right press/release, Shift+A press/release with
modifier bits set and cleared, and B press/release through QMP `send-key`.
Physical events are separate from text; keys do not enter the COM1 shell.
Movement and left/right/middle press/release transitions are checked separately.

Five real QMP P6 screenshots compare **every one of 480,000 pixels each**:
cursor at `(410,307)`, `(0,0)`, `(799,0)`, `(0,599)` and `(799,599)`.
This checks clipping and complete restoration of old cursor rectangles. The
7 by 9 arrow has an independently pinned literal raster in host tests. A fixed
63-pixel save area retains exact device bytes, including unused channels;
there is no retained full-screen allocation. Cursor presentation preserves
M14.1's reserved supervisor RW/NX WC mappings and uses MFENCE between WC stores
and later cursor operations. The cursor first appears on a pointer event,
so the original M14.1 boot pattern and heap-reclamation gate remain intact.

Two independent negative boots use `-vga none` and `-machine i8042=off`.
The former still verifies actual keys, movement and all three buttons with no
cursor renderer. The latter requires `[INPUT:FALLBACK]` and rejects READY.
Every boot executes `echo M14-INPUT-SERIAL-RECOVERY` in the real UART shell and
then shuts down through `[POWER:OFF] synced=true clean=true dma_reset=true`,
requiring QEMU exit 0. Each session has a 60-second watchdog; fatal markers,
unexpected healthy-path input resets, early/nonzero exits and bad scanouts fail.

## Recovery and negative evidence boundaries

The `input-test` feature executes checked in-guest adversarial cases before
the diagnostic consumer becomes available:

- Fill the real 64-event dispatcher beyond capacity. Overflow discards history
  and the triggering event, invalidates all held keys/buttons and publishes Reset.
- Reject a malformed mouse header without a fabricated pointer movement.
- Disconnect/reconnect the diagnostic consumer, dropping disconnected input and
  verifying the next make is a fresh press.
- Disable both actual i8042 ports, rerun controller/device initialization and
  require both devices to return before accepting QMP input.
- Expire incomplete keyboard and mouse sequences independently, before feeding
  a late continuation, including modular PM-counter wrap. Peer-device traffic
  cannot extend the stale sequence's lifetime. The deadline is 100 ms between
  source bytes, sampled at scheduler polls, independently of IF-masked LAPIC ticks.

These produce checked `[INPUT:SELFTEST]` and `[INPUT:TIMEOUT-TEST]` markers.
They are deliberately injected guest state/device-lifecycle tests, **not** QMP
wire-overflow, physical unplug, live compositor-crash or hotplug evidence.
The healthy QMP sessions independently prove continued physical input delivery
after recovery. PS/2 packet loss cannot always be detected from three bytes;
controller status errors and incomplete-sequence expiry reset both decoders.

The dependency-free `anova-input` crate has 22 host tests covering make/repeat/
break, both-sided modifiers, Caps Lock, Pause, PrintScreen/SysRq/fake shifts,
malformed sequences, signed nine-bit mouse extremes, button changes, motion
overflow, packet framing, source-independent reset, clipping, queue capacity/
wrap/overflow and consumer reconnect. The graphics tests pin the cursor raster;
host gate tests reject corrupt background/cursor pixels, invalid coordinates,
incomplete event-field matches, timeouts and guest failures.

## Limits and next stage

Only QEMU 8.2.2 q35 PS/2 keyboard and a standard three-button mouse are accepted;
the verified scanout remains standard VGA 800 by 600 by 32. Polling can lose
device bytes during long nonpreemptible kernel work and must sample the modular
PM counter within its wrap interval for reliable interbyte expiry. There is no
USB/wheel input, IRQ routing, physical hotplug or hardware acceptance claim.
Focus has one diagnostic subscriber only; application routing, graphical text,
window policy, user-space compositor and GUI ABI/SDK remain future stages.
CPU cursor copying has no vblank or atomic presentation guarantee. Remote CI is
configured with the real gate, but no remote run is claimed. M14.3 is next.
