## Actual guest observations

Test init is PID 1 and waits for the filesystem ELF and shell script before
exiting. The guest checks these cases through real native syscall boundaries:

- Read-only writes, missing paths, file/.., directory-write rejection,
  invalid fd and bad read/readdir/open/pipe pointers and wire sizes. Invalid
  read/readdir outputs leave their offsets unchanged; invalid pipe output
  never publishes endpoint resources.
- Independent opens versus dup/fork/spawn shared offsets; exec-retained fd 7;
  cwd inheritance and child chdir isolation; unlink while data remains open.
- A 4,096-byte writer exceeds the 1 KiB pipe buffer and blocks while its parent
  sleeps, then drains correctly. A reader blocks before delayed data, waits for
  final-writer EOF and resumes. Closed-reader writes report BROKEN_PIPE.
- All 32 descriptors are filled; failed pipe/create leave no new file, and
  closing descriptors restores capacity. 128 create/write/unlink cycles reuse
  node storage. A 64 KiB tmpfs file rejects an over-limit write.
- Separate tmpfs files fill the real fixed kernel heap until a write returns
  NO_MEMORY without moving its offset. Closing/unlinking them permits a fresh
  4 KiB write. This exercises actual heap exhaustion, not an artificial budget.
- The shell lists mounts/devices, creates/reads/appends relative tmpfs files,
  changes cwd, runs real Rust/C ELF applications, pipes 5,000 bytes through
  three stages, and contains an early-closing pipeline reader. Its visible
  status checks include 0, 7, 127, 1 and syntax error 2. An independent ELF
  reads and verifies the shell-produced file contents.

The accepted boot includes these markers (I/O counts depend on scheduling):

```text
[FS:CASE] paths-copy-offset-fork-exec-cwd passed=true
[FS:CASE] pipe-block-drain-eof-broken passed=true
[FS:CASE] limits-rollback-reuse passed=true
[FS:CASE] tmpfs-oom-rollback passed=true
[FS:TEST] passed=true
[SHELL:TEST] files=verified pipeline_bytes=5000 redirection=true cwd=true
[INIT:TEST] shell_status=0 children_reaped=true
[VFS:IO] blocks=21 wakes=21 open_descriptions=0 pipes=0
[VFS:READY] frames_restored=true heap_restored=true tmpfs=volatile
```

The kernel asserts exact free physical-frame and heap-used restoration after
the entire init session, and asserts zero live open descriptions/pipes. These
checks run in addition to all M3/M4/M5 protection, CPU/FPU, reclamation, process
capacity and lifecycle OOM checks. Boot exits QEMU 33; the twelve negative
images still reach their expected panic/OOM/fault/timeout injection and cannot
pass through an early banner. Their result files record actual classification.

## Real UART and fresh-boot tests

`terminal-test` starts the normal image and waits for the native prompt, then
writes input through QEMU's serial stdin with a 30-second watchdog per session:

1. Send `echo tty-editX`, DEL and CRLF. Require the actual `tty-edit` output,
   backspace echo and no syntax error from a spurious LF line.
2. Redirect `terminal-file` into `/tmp/terminal`, run cat and require its actual
   file contents. Send Ctrl+D; require init to restart the interactive shell.
3. Kill/reap that disposable ordinary guest after successful observations.
   Start a second guest from the same immutable ISO and fresh OVMF variables.
4. Cat `/tmp/terminal`; require NOT_FOUND, shell status 1 and another Ctrl+D
   restart. This verifies loss of writable tmpfs data, not disk persistence.

Logs/results are `build/logs/terminal*` and `terminal-reboot*`. The normal guest
has no debug-exit device and is killed only after the expected behavior is
observed. Other transcripts/results remain in `build/logs/` for CI upload.

## Limits and remote CI

The complete implemented bounds and exclusions are in
[M6_FILESYSTEM.md](../milestones/M6_FILESYSTEM.md). This is one BSP, bounded in-memory
mounts, a native single-argument-string exec contract and a small project-owned
shell. No writable persistence, Linux binaries, general mount/unmount, POSIX
terminal, signals, threads, SMP, USB input or in-guest compiler is claimed.

CI is updated to run the same VFS/parser checks, 13 regressions and the real
serial/two-boot test. M6 remote CI has not run; local success does not imply a
GitHub Actions result. Generated artifact hashes below identify this local
build, not reproducibility across debug paths or ISO timestamps.
