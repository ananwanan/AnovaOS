# M18.2: LLVM, rustc and Cargo component evidence

**English** | [简体中文](../../zh-CN/validation/M18.2.md)

The standalone LLVM 20.1.8 `LLVMDemangle` library passed local guest reconstruction,
repeat and reboot checks on 2026-11-21 (Asia/Shanghai). The run used
`feat/m18-bootstrap` from `a2a16a6` with the implementation identities in the retained
report. The [M15.4 feasibility record](M15.4.md) remains independent.

## Guest reconstruction and repeat

`cargo xtask m18-llvm-test` completed four q35/TCG boots on QEMU 8.2.2 with
OVMF, 3 GiB RAM, one BSP and no NIC. The host verified the 272,348,992-byte
Rust 1.90.0 release source archive against the [source lock](../../../ports/bootstrap/rust-inputs.json).
The source selection independently matched the SHA-256 of all 16 files from the
Rust release's pinned LLVM fork, including LLVM's unmodified license. This
selected source, input manifest and three first-party fixtures used 431,248 bytes
in 20 files. The host launcher initramfs contained 1,369 entries.

The guest ran six sequential C++17 compilations using inherited GCC/G++ 11.2.0,
musl 1.2.4 and binutils 2.37. It built for the static x86_64 Linux-musl personality
using `-O2 -pipe -fno-exceptions -fno-rtti` and `ar rcsD`, then statically linked
and stripped the test executable. `-pipe` streams the assembler input. The host
preflight measured a 1,066,492-byte Itanium assembly file, above the 1 MiB
tmpfs file limit. The guest uses a private temporary directory on each ext4 work
disk for remaining temporary files. The compiler's dependency records matched
all 14 selected non-system source and header files actually used by its six
compilations. The host independently compared the six archive members with the
guest object files and checked the fixture's static ET_EXEC format and execute mode.

Both clean work disks produced these byte-identical artifacts.

Each fixture returned the expected Itanium, Microsoft, Rust v0 and D names and
rejected invalid Itanium input. Each fresh reboot of the retained disk exercised
a real C++ syntax error and an omitted-library link error. Both returned status
1 with their original diagnostics and left no rejected output. Relinking with the
retained guest-built archive produced the prior executable's exact bytes. Both
executables ran again. The host compared all prior work files, including the
retained data file, and required read-only `e2fsck -f -n` success after each boot.
