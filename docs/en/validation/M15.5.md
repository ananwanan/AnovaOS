# M15.5 local guest kernel reconstruction

**English** | [简体中文](../../zh-CN/validation/M15.5.md)

This is a historical local validation record. Later acceptance is tracked in
[current status](../guides/STATUS.md); this documentation update does not rerun the gate.

Recorded 2026-10-24 (Asia/Shanghai), task branch `feat/m15-bootstrap`,
implementation base `104cdab`. The implementation is described in
[M15 kernel](../milestones/M15_KERNEL.md). The actual three-boot gate passed locally on QEMU 8.2.2 q35/TCG with one CPU,
3 GiB RAM and no NIC. This accepts guest kernel construction, exact retained-ELF
host-assisted packaging and actual boot/failure/recovery for the declared profile.

## Implemented acceptance contract

`cargo xtask bootstrap-kernel-test` prepares exact current kernel, local crate
and linker bytes, an isolated offline workspace and 20 authenticated registry
packages. It overlays matching official precompiled bare-metal core, alloc and
compiler_builtins libraries beside the inherited M12 Rust/Cargo/rust-lld 1.90.0
runtime. No host target artifact replaces any guest compilation. The initial boot
kernel/apps remain host-built and are separately identified. Source preparation and the host-compiled build/capacity
diagnostics are recorded separately from actual guest compiler outputs.

The declared target is `x86_64-unknown-none`, with the `bootstrap-metrics`
feature, opt-level z, one job/codegen unit, no debug information, stripped
symbols and aborting panics. Explicit Cargo target selection keeps kernel
code-model, relocation and red-zone flags away from Linux-musl build scripts.
All build outputs and temporary metadata go to the persistent work disk.

The three-session gate must prove actual guest compilation/publication,
byte-identical retained-ELF image packaging and boot identity, then a real
compiler rejection with old-kernel retention and another recovery boot. Each
session must reach successful ACPI shutdown, flush and acknowledged DMA reset;
each stopped disk must pass read-only e2fsck. The failure probe compiles a
small intentionally invalid Rust source to an unpublished candidate. It is
not a complete failed kernel Cargo rebuild.

## Capacity and regression behavior

Host preflight measured a stripped kernel under 1 MiB, but a smoltcp
intermediate rlib over 2 MiB. Persistent ext2 files therefore now allow 4 MiB
within the existing direct/single-indirect disk format. tmpfs and coherent
readonly shared-file caches retain their 1 MiB limits. Active shared caches
reject oversized growth with EBUSY; inactive caches are safely discarded before
growth. Larger private file snapshots remain separate from shared caches.
The disk stays 16 MiB/512 inodes, VFS 2,048 nodes, kernel heap 16 MiB and tasks
32 slots. Increasing QEMU RAM is not a substitute for these bounds.

Host tests cover real 4 MiB writes/readback/remount, shrink/zero growth, inode
and block reuse, limit/arithmetic rejection without writes, backend-specific
seek/ftruncate admission and active/idle shared-cache growth. The native
filesystem fixture now writes beyond 1 MiB and rejects at 4 MiB; the Linux
fixture separately verifies persistent 4 MiB and tmpfs 1 MiB boundaries while
preserving file bytes and descriptor offsets. The guest capacity probe checks
EFBIG, EMFILE and EAGAIN rejection followed by resource reuse.

## Initial execution failure and correction

An initial source-reconstruction attempt reached smoltcp metadata
emission, then failed with `No space left on device` while writing
`/tmp/rustcLC5UAe/lib.rmeta`. The Rust launcher had overwritten the build driver's
persistent TMPDIR with `/tmp`, whose writable files remain limited to 1 MiB.
The launcher now preserves an explicit TMPDIR, while retaining `/tmp` as its
default. A fresh independent work disk is used for the corrected build.
The failure transcript and invocation are retained as
`build/logs/bootstrap-kernel-tmpfs-failure.serial.log` and
`build/logs/bootstrap-kernel-tmpfs-failure.run.log`, with its manifest in
`build/bootstrap-kernel/tmpfs-failure.prepared.json`.

The locked smoltcp rustc invocation also needs 71 arguments, beyond the prior
70-argument wrapper limit. The wrapper now accepts up to 80 while explicitly
reserving array capacity for injected options and its terminator.

## Large-file I/O prerequisite

The corrected temporary-directory run exposed excessive indirect-table reads.
An independent counted BlockDevice test appended 2 MiB in 4,096 separate
512-byte writes and measured 16,211,368 sector reads. Each write scanned the
entire prefix twice and repeatedly fetched the same indirect table. That
exploratory QEMU run was deliberately stopped before acceptance; its logs are
`build/logs/bootstrap-kernel-slow-io.serial.log` and `.run.log`, with its prepared
manifest in `build/bootstrap-kernel/slow-io.prepared.json`.

Writes now keep one private indirect-table snapshot for that operation,
validate all referenced addresses and update the snapshot alongside ordered
on-disk pointer publication. The disk format, no-space preflight, data/pointer/
inode-length ordering and fail-closed partial-I/O behavior are preserved.
There is no cross-operation or global inode cache. The same counted test now
uses 175,376 sector reads, approximately 92 times fewer. The regression bounds
reads by write count and tests failed table reads, corrupted table/data pointers,
no-write rejection and successful recovery. Counts are retained in
`build/logs/m15-kernel-storage-io-preflight.txt`; they are fixture I/O counts,
not a claim of 92 times faster end-to-end compilation.

## Executed guest construction and recovery

The first session compiled all active kernel/local/registry packages from the
prepared sources using actual guest Cargo/rustc/rust-lld, then published a
349,464-byte high-half static kernel ELF. Its host-built initial seed kernel
has a different SHA-256. The host remounted the stopped work disk, checked the
ELF, retained its exact bytes and packaged it through the preserved-kernel
entry point. That path does not build a host kernel. Independent ISO extraction
matched every retained guest ELF byte before the next boot.

Both subsequent boots reported the expected embedded build identity and passed
memory ownership/page-permission checks, calibrated timer delivery, disk mount
and native C application execution with its expected exit status 7. The second
boot also ran the inherited rustc, capacity rejection/reuse probe and real syntax
rejection with compiler exit 1. Its capacity probe exhausted 29 additional
file descriptors and 29 child slots, then recovered; the recorded process/FD
peaks reached the existing 32-slot/descriptor limits. The prior kernel ELF
remained byte-identical. The final independent boot again used the same ISO and
identity, and all 181 retained workspace files matched the preceding stopped
state. Each session reached clean ACPI shutdown with flush and acknowledged DMA
reset; all three read-only e2fsck checks passed.

The inherited Cargo printed a nonfatal global-cache last-use advisory-lock
warning. It still completed with exit 0 and all explicit artifact/runtime checks
passed. General SQLite/POSIX locking and cache pruning are not accepted here.
Complete compiler output remains in the persistent build log and copied host
`bootstrap-kernel-build.cargo.log`; serial logs also retain real child statuses.

## Related runtime and storage regressions

All commands completed successfully on the final runtime sources:

- `cargo xtask verify`: all 13 boot/fault cases, including native/Linux runtime,
  memory, isolation, scheduler and filesystem checks in the normal test boot;
  controlled panic/timeout/exception/OOM cases were rejected as expected.
- `cargo xtask persistence-test`: six save/reboot/read-only/feature/write-error/
  flush-error scenarios, retained source/binary checks and e2fsck. The injected
  write-error scenario intentionally stops without claiming clean shutdown.
- `cargo xtask rust-cross-test`: the updated guest Linux runtime fixture verifies
  persistent and tmpfs file bounds, mapping/IPC ownership and timestamps, then
  runs the independently host-cross-compiled Rust std application. This regression
  does not claim a new guest Rust application build.

The orchestrating command returned exit 0. Retained invocation/output logs are
`build/logs/m15-kernel-verify.log`, `m15-kernel-persistence.log` and
`m15-kernel-rust-cross.log`, alongside the normal per-case serial/result files.
The separate full offline/online Cargo, GUI/GPU and native-hardware gates were
not rerun for this batch; their prior accepted scopes remain independent.

## Scope

Compiler reconstruction, guest-only complete image generation, GUI-enabled
kernel reconstruction, power-loss recovery and M15.6 independent clean-build
comparisons remain unverified. The syntax-failure probe does not establish
recovery from every possible complete kernel-build failure. Remote CI and
