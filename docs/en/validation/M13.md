## SDK and public developer workflow

`cargo xtask sdk-test` exports SDK 1.0.0 and checks its SHA256SUMS, builds the
independent C/C++/Rust native templates, executes host C/C++ layout/error
contract checks and invokes the exported Python driver directly for C and an independent Rust consumer.
Fresh candidate publication rejects stale extras/symlinks without removing the
previous release; host tests exercise this boundary and complete publication. Editing the
Rust path dependency actually changes the rebuilt ELF; a failing C compile
leaves the prior runnable ELF intact. Repeated runs refresh the fixture SDK
and source, avoiding validation of a stale copied runtime. Native v1 numbers,
error names/unknown values, layouts, field offsets and response versions are
checked separately. Final host validation passes 99 tests; purpose coverage
passes for all 247 repository files. Runtime argument tests cover 64 arguments of 1,023 bytes,
and reject 65 arguments or a 1,024-byte argument.

`cargo xtask app-test` exercises the public image path used by `app-image` and
`app-run`: an incorrect external package hash is rejected; a package built from
the public C template is embedded at `/repo/local.apkg`, installed in a real
guest, and its installed ELF runs with status 0. The actual missing-file error
is `not_found`; clean ACPI shutdown and `e2fsck -f -n` pass. Evidence:
`build/logs/app-workflow.serial.log` and `app-workflow.result.txt`.

## Versioned packages and policy

`cargo xtask package-v2-test` validates actual C/C++/Rust native packages and a
static ET_EXEC musl Linux package. All installed entries are followed by a shell
status assertion, so printing an early application marker cannot hide a failed
SDK error/RAII check. The C upgrade edits and recompiles its source and prints
`[M13:C:V2]`; failed staging retains the old running version, and the new code
runs both immediately after upgrade and after reboot. Downgrades fail. User data
survives upgrades, clean reboot and removal. Both disk profiles boot twice and
all four `e2fsck -f -n` runs pass.

The actual guest parser rejects 31 independently rehashed adversarial archives,
including architecture/ABI/SDK/dependency/permission/capability errors, invalid
paths, entry/mode/license faults, truncation/trailing bytes, malformed ELF and
TLS ranges. Rehashed tests get past the external archive lock and exercise the
inner validator. Valid controls install, while rejected inputs leave a real
host sandbox namespace byte-for-byte unchanged. Guest profile mismatches fail
before installation; a Linux disk also rejects legacy native ANOVAPK1.

The VFS pins the mount's ABI-marker node identity. Its host test rejects content
writes (including an already held descriptor and positioned write), truncate,
chmod/fchmod, executable-bit changes, unlink and source/destination rename.
Both real guest profiles attempt to overwrite `/persist/.anova-abi`, receive
read-only failure/status 1, and read the unchanged original marker/status 0.
Installation and execution policy therefore remain consistent while mounted.

Evidence: `build/logs/package-v2.result.txt` and `packages-v2-native`,
`packages-v2-native-reboot`, `packages-v2-linux`, `packages-v2-linux-reboot`
serial/QEMU logs. New packages retain original debug ELFs separately from the
stripped payload whose SHA-256 appears in the package descriptor.

## Captured faults and source symbols

`cargo xtask diagnostics-test` triggers real Ring 3 `#UD` instructions. Five
captured frame addresses resolve through host addr2line to
`m13_crash_leaf`, `m13_crash_middle`, `m13_crash_entry`, `main` and `_start`,
with actual source lines. A second fault with RBP=1 yields exactly one frame
and `reason=invalid-frame`. Both shell statuses are 134, a subsequent healthy
echo actually runs and the guest shuts down cleanly. The overall success result
is written only after function/source checks. A stripped ELF is rejected with
an explicit missing-symbol/debug-information error.

Evidence: `build/logs/diagnostics-guest.serial.log`,
`diagnostics.symbols.log`, `diagnostics.result.txt`. The fault ELF is
`build/diagnostics/m13-crash.elf`. The walk uses checked, recoverable usercopy,
at most 16 frames, 1 MiB above RSP and 64 KiB between links. Resource logs are
global frame/heap counters and task capacity, not per-process accounting.

## Regression harness corrections

The WSL pass exposed existing assumptions in two test tools. A UART read could
end at `[SHELL:STATUS] code=` before the succeeding zero, which the original
host gate immediately misclassified as failure. The transcript now waits for a
complete status line, with a fragmented-input regression test; nonzero complete
statuses still fail immediately. Guest compilation itself had returned zero in
the rejected initial toolchain/Rust logs.

The original host PTY fixture assumed one read consumed the complete canonical
echo and that Ctrl+C had already reached its handler when the write returned.
Private repeated traces reproduced the failure. The fixture now polls and
consumes exact echo/raw/reply streams, validates their bytes, and atomically
unmasks SIGINT in ppoll to wait for the real handler. All 30 private host traces
(ten each static/static PIE/dynamic) pass; the updated fixture also passes the
actual guest smoke gate. No assertion or compatibility behavior is skipped.

## Scope

Native v1 and ANOVAPK1 compatibility remain regression requirements. The v2
Linux package profile is bounded static ET_EXEC; broader M9 dynamic/PIE ELF
runtime acceptance is separate. Permissions are admission declarations, not a
process sandbox. No package dependency solver, signed publisher identity,
power-loss transaction guarantee, general Linux/glibc compatibility, native
Rust std, GDB stub, interactive user debugger or GUI implementation is claimed.
GUI ABI delivery remains independently versioned and deferred to M14.4.

Host validation additionally passes all 99 tests, strict host/user Clippy and
kernel qemu-test/double-fault/NX Clippy, root/user/template formatting,
247-file purpose coverage, doctor and diff checks. Kernel build passes; the
13-case verify gate includes reached expected faults/panic/timeout/OOM rather
than accepting a banner or a clean exit alone. Source-built GCC/musl/binutils/
make and the official checksum-locked Rust tools were prepared in this WSL
checkout; no compiler request was delegated to the host during guest tests.

The public Cargo gate is accepted with
`ANOVA_CARGO_TEST_PROXY=http://10.0.2.2:18099`, using a temporary anonymous,
loopback-only CONNECT transport restricted to GitHub/crates.io hosts. It does
not terminate TLS or supply a compiler. Guest Cargo verifies the pinned public
CA store, exact registry hash and Git revision, then rebuilds from retained
sources after an independent boot without a NIC. The generated transport helper
is `build/logs/m13-regressions/public_proxy.py`; it was stopped after the gate.
Direct public transport is **not established**: an initial trial hit a block
timeout before acquisition, and a later direct trial failed to start the DNS
resolver thread. The accepted proxy profile preserves the M12 boundary. One
transient Git TLS EOF was retried successfully by unmodified Cargo.

The existing nonfatal Cargo advisory-lock/cache-cleanup warnings remain, as
described in M12; no false lock implementation or TLS verification bypass was
added. Remote GitHub Actions has been configured with the new gates but was
not executed as part of this local acceptance.
