## Original failures and corrections

Original timestamped results are retained, not relabeled as passes. The first
constructor attempted a second GUI connection; removing the obsolete pre-connect
fixed startup. Fallible GUI creation now claims raster storage only after success
and releases it on drop, preserving bounded compositor replacement. GCC color
escapes made a raw sanitized log unreadable; the explicit color-never argument
fixes the controlled recipe without parsing status from output. A native-check
observer waited from a cursor past the record it sought; that run was explicitly
stopped and the observer fixed. A fixture expectation incorrectly used native CPU
fault status for a Linux process; actual UD2/SIGILL requires reason 3/code 4.
The eviction view was correct while its independent test alphabet lacked V;
the missing literal sample was added and the actual pixels then passed.

One earlier run, `1793810697336460340`, saved the exact repaired source but had a
real linker/storage failure (compiler status 1; staging cleanup IO_ERROR). Its
original disk and UART remain available. That run did not record the originating
block-failure category, so its root cause is **unclassified**, not claimed fixed.
Queue/completion/timeout diagnostics were subsequently added without changing the
existing two-second device deadline or fail-closed journal policy. A same-mount
storage failure can still require inspection and a fresh mount. The UI now reports
staging cleanup errors after unconditional task/descriptor cleanup; it does not
mask them with a successful status. The successful run above uses an independent
fresh disk. This accepts its declared profile, not arbitrary storage reliability.


A subsequent Files regression found an overwrite-save observer inspecting a partial
`[FILES:SAVED] pat` record. The actual save completed correctly; all relevant
observers now wait for newline-complete records with the original five-second
bounds and unchanged path/size/dirty assertions. A real TCP startup reset in the
storage-fault matrix occurred before any greeting/UART bytes. Only empty pre-greeting
EOF/reset can reconnect within the same five-second startup deadline; no VM is
relaunched, and partial greetings or any command failure remain fatal. Socket host
tests assert those boundaries. One full matrix also rejected an actual 16 KiB
save over its five-second budget. That result remains failed; the isolated bounds
case and final full 16-case/43-boot rerun passed with unchanged ceilings. No
interaction/device/build ceiling is increased.

A later graphical PTY regression exceeded its unchanged compiler deadline; its
original serial/scanout records remain failed. A separate reboot found a real
terminal stop/relaunch race: a disconnected peer's GUI slot remains occupied until
the compositor consumes its notification. Native connection now retries NO_SPACE
inside the existing 100-tick window and still returns NO_SPACE for four live
clients. The dedicated profile asserts both true exhaustion and recovery after a
physical peer close, then reclaims the helper and relaunches the C client.

The unthrottled detached-writer case exposed a kernel progress bug: with one byte
free, poll/wakeup declared the slave writable while write reserved two bytes for
CRLF. Repeated false-ready wakeups could prevent the nonpreemptible kernel from
enabling IRQs. Writes, poll and wakeups now share exact CRLF/echo/EOF predicates;
two host boundary tests exercise them. The real writer case now returns to the
UI, reports the leader's actual zero exit plus capture cut, retains independently
checked prior artifact bytes, and reclaims all descendants. Post-exit draining is
bounded at three delivered-status turns; incomplete capture cannot publish.

The observer in run `1793818208092670765` originally printed result=Ok despite a
35,157 ms compiler observation: it accepted an available result before checking
the declared 35,000 ms ceiling. This is an observer defect, not on-time evidence.
The raw record is preserved with this qualification. The check now enforces the
deadline before accepting completion; host assertions reject both 35,157 ms and a
one-nanosecond overrun. Its final strict rerun is recorded below.
