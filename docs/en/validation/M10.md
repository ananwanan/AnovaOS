# M10 local validation

**English** | [简体中文](../../zh-CN/validation/M10.md)

Recorded 2026-10-22 (Asia/Shanghai). Baseline: cbab786 on dev, the M9 merge.
Task branch: feat/m10-network-packages. This record covers the controlled
[M10 profile](../milestones/M10_NETWORK_PACKAGES.md); remote CI and pushing are separate.

## Inputs

- Rust 1.90.0, edition 2024, x86_64-unknown-none kernel and separate Linux/native user builds.
- QEMU 8.2.2, q35/TCG, one CPU, 256 MiB, pinned Limine/OVMF and the M9 musl 1.2.4-2 runtime.
- smoltcp 0.12.0 with checked-in Cargo.lock; no std or host networking dependency in the kernel.
- Mbed TLS 2.28.10, commit 2fc8413bfcb51354c8e679141b17b3f1a5942561, built with musl-gcc.
- Loopback TCP/UDP/DNS peers at 18080/18081/18082 and TLS 1.2 peers at 18083/18085.
  No public site, host bridge, TAP interface or firewall modification is needed.
- Generated short-lived test certificates. Private keys remain under ignored build/compat;
  only public certificates enter the image. Certificate bytes are intentionally generated inputs.

The existing linux-threads, linux-pie, libm9 and dynamic-musl fixture digests
match [M9](M9.md). A relocated-toolchain linker-path error was found during
validation: shared libc was absent, so a TLS DSO incorrectly pulled libc.a.
After restoring the shared input, M9 hashes match again. The build now explicitly
rejects DSOs without a real libc.so DT_NEEDED entry. Fresh-build host tracing
also exposed missing executable modes on copied BusyBox/runtime outputs; those
outputs now preserve source permissions explicitly. Their ELF bytes are unchanged.

## Accepted controlled paths

`cargo xtask network-test` passed with actual UART-launched Ring 3 syscalls:

- Modern PCI virtio-net RX/TX, two owned DMA pages, real ARP/IPv4/TCP and UDP traffic.
- TCP nonblocking connect, poll, SO_ERROR, dup/close, echo, finite receive timeout,
  shutdown/EOF and refused connection. Unsupported families/syscalls return errors.
- UDP reply/source bytes, EFAULT before dequeue, oversized datagram rejection.
- Actual randomized DNS A query/reply, ID/source/question checks, compressed-name
  cycle rejection and a real missing-response timeout.
- A blocked connected socket interrupted by SIGUSR1, fork/wait, eight-slot
  exhaustion and 32 repeated create/close cycles.
- Clean guest shutdown includes `[NET:RESET] acknowledged=true dma_released=true`.

`cargo xtask package-test` passed on the same persistent image across three boots:

1. No NIC: install demo v1, run its actual native ELF, save user data, stop an upgrade
   after a real staged file write, retain v1, reject corrupt/traversal/ABI archives,
   install v2 and shut down. e2fsck passes.
2. No NIC: recover v2 from disk, check versioned payload, execute its ELF, read the
   original user bytes, uninstall, verify the tombstone and retained user data.
   e2fsck passes.
3. With virtio-net: accept the trusted repo.anova HTTPS peer, reject wrong hostname,
   wrong CA and expired certificates, fetch the locked demo v2 package over TLS,
   validate/install it and read its payload. Network reset and e2fsck pass.

The TLS negatives require the actual Mbed TLS certificate-verification error
(-9984) and X.509 flags 4 (name), 8 (trust), and 1 (expiry). An unrelated timeout
cannot satisfy those negatives. All CA/name/date checks remain enabled.
The actual package parser also runs on the Linux host against valid, corrupt,
traversal and incompatible-ABI archives before guest packaging.

Logs: build/logs/network.serial.log, packages-offline.serial.log,
packages-reboot.serial.log, packages-online.serial.log and https-peer.log.
Existing source/binary persistence and terminal logs keep their earlier names.

## Regression results

- 76 host tests passed, including Gregorian/leap checks and shared socket
  description lifetime through dup/fork/exec/thread-table close.
- Host/kernel Clippy with warnings denied, native user Clippy, both workspace
  formatting checks and per-file purpose coverage passed.
- The M0–M9 13-case QEMU gate passed: boot exits 33; panic/OOM exit 35;
  real fault injections exit 37; the injected hang times out and is rejected.
  It retains full M9 pthread/futex/signals/PTY/static-PIE/dynamic-musl, isolation,
  heap/frame exhaustion and exact reclamation assertions.
- Ordinary UART terminal tests passed, including dynamic musl startup, Ctrl+C,
  line editing/EOF and fresh-boot tmpfs loss.
- Persistence tests passed: editor/source/ELF bytes and hash across reboot,
  actual native execution, clean shutdown/e2fsck, read-only/unknown-feature rejection,
  and real block write/flush errors.
- Linux-host compatibility traces passed for the existing pinned probes and CLI/runtime profiles.

## Limits

The accepted network is polled IPv4 client networking on QEMU. TCP servers,
IPv6, DHCP, general musl getaddrinfo and arbitrary Linux network programs remain
outside this profile. HTTPS package acquisition uses the controlled host peer
and generated test CA; arbitrary public repositories and production TLS policy
are unverified. Native SDK v1 is the only accepted package dependency. No package
solver, multi-user permissions, concurrent installer or power-loss transaction
is claimed. ext2 remains non-journaled; a failed physical I/O still needs recovery.
SMP, general Linux/glibc and guest GCC/G++/rustc/Cargo remain future work.
