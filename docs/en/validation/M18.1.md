## C89 probe exposed the Linux pipe bound

In the subsequent RAM-backed run, the unmodified configure compiled, linked and
executed its `conftest`, reported `checking whether we are cross compiling... no`,
found GNU C and confirmed `-g`. It stopped during the original ISO C89 probe.
Ash's 1–4 KiB inline heredoc path writes the pipe before starting the reader command.
Our 1 KiB Linux queue could not complete that write, leaving the writer and
configure idle. The host stopped the stalled VM. Exact UART and the source
`configure.stdout`/`config.log` from the stopped disk are retained under
`build/m18-validation/initial-failures/1795237879037987970/`.

The Linux adapter now reserves a 4 KiB stream buffer before publishing pipe
endpoints. This supplies matching empty-pipe capacity, with the existing short
writes when partially full. Host VFS tests cover one complete 4 KiB write,
full/partial readiness, exact wrapped contents, EOF and broken-reader handling,
and descriptor/pipe pool exhaustion/reuse. Native stream and packet capacities
and slot limits are unchanged.

The first pipe-aware guest run recorded `[M18:POSIX:SHELL] heredoc=2049`
after comparing the actual heredoc output byte-for-byte. It completed the
other applet and arithmetic checks and responded over COM1 during live configure.
