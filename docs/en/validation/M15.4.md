## Executed guest assessment

`cargo xtask bootstrap-rust-test` completed two QEMU 8.2.2 q35/TCG boots with
one CPU, 3 GiB RAM and no NIC. Both used an independent Linux-personality
16 MiB/512-inode work disk and reached clean ACPI shutdown with storage flush
and acknowledged DMA reset. Both read-only `e2fsck -f -n` checks passed.
The accepted result is `build/logs/bootstrap-rust.result.json`, with the
source audit and preparation manifest embedded. Serial/QEMU/result files use
the `bootstrap-rust-probe` and `bootstrap-rust-reboot` prefixes.

The first boot recorded the inherited Rust/Cargo versions, then guest rustc
compiled and linked a first-party std application using vectors, a worker
thread and persistent file reads/writes. It reported value 42. Guest G++
separately compiled a first-party C++17 fold-expression/`std::optional` fixture;
that executable also reported 42. These are seed application tests, not
compiler component builds. The host independently parsed both guest-built
ELFs and checked their executable modes after shutdown.

A guest copy preserved the working Rust executable before rustc compiled the
deliberately invalid `bad.rs` to the same output path. The compiler returned 1
with the actual expected-expression diagnostic. Host inspection proved the
saved copy and retained executable were byte-identical. Both successful
applications ran again after the negative probes and resource exhaustion.

The host-built first-party diagnostic attempted actual `execvp` calls for
`python3`, `cmake`, `ninja`, `git`, `perl` and `pkg-config`; each child supplied
`ENOENT` through a checked pipe and returned 127. It also attempted
`python3 rust-x.py --help` against the unchanged retained upstream entry file.
The interpreter could not execute, so no upstream Python or later bootstrap
code ran. Missing optional tools are configuration-specific evidence, not
proof that every possible source route requires all six programs.

The diagnostic ran Cargo against a separate minimal manifest selecting
`curl = "=0.4.48"`, matching the audited upstream Cargo manifest and lockfile.
Its inherited `/rs/vendor` profile lacks that dependency. Cargo returned 101
with the actual missing-`curl` and vendor-path diagnostics. The bounded
captured file was checked after shutdown and is also retained as
`build/logs/bootstrap-rust-cargo-dependency.log`. This tests the selected
offline dependency availability; the complete upstream Cargo workspace or
release vendor tree was not built or configured in the guest.

The existing capacity diagnostic rejected an over-1-MiB persistent resize
while preserving prior bytes, exhausted and recovered descriptors with
`EMFILE`, and exhausted/reaped children with `EAGAIN` before a new successful
fork/wait. The second independent boot executed both retained applications.
All 31 workspace files, including imported upstream sources/notices, fixtures,
captured Cargo output, successful executables and the saved Rust copy, matched
byte-for-byte across the boots.

functional build tools, stage0/native dependencies and measured output budget.

## Source checks and regressions

The new Python suite has ten test groups covering checksum mismatch, path
traversal, duplicate/ambiguous paths, link/special-file handling, missing or
oversized selected files, exact component accounting and changed/symlinked
publication/cache paths. Existing bzip2 and GCC rejection suites also passed.
`rust_probe.py --verify` checked the existing source publication without
writing it. Host evidence tests reject incomplete guest markers and failed
diagnostics. Formatting, strict xtask Clippy, the `bootstrap-metrics` kernel
check and all 193 host unit/doc tests passed. The final strict host check also
covered every host package selected by CI. Purpose coverage passed for 340
files. Exact commands, exit codes and host durations are retained in
`build/logs/m15-rust-source-checks.json`, with complete output in
`build/logs/m15-rust-source-checks.log`.

A dangling final-result symlink was separately rejected before preparation;
its target was not created and the accepted report was restored byte-for-byte.
Its host output is retained in `build/logs/m15-rust-result-symlink.host.log`.
Every final implementation-file hash was compared against the accepted
report. Local file links in the changed Markdown documents and diff whitespace
checks passed.

The first broader Rust/Cargo regression completed its 609-step guest boot and
clean shutdown, then correctly failed the host compile-count assertion:
`m12-macro` compiled three times instead of two. The extra rebuild occurred
after an unchanged macro dependency's prior successful rebuild. Its original
host and serial logs are retained as `m15-rust-initial-rust-test.host.log` and
`m15-rust-initial-rust-build.serial.log`; the failed command record is
`m15-rust-regressions-initial.json`. This result was not treated as acceptance.

Inspection found a preexisting timestamp-precision mismatch. Ordinary ext2
mutations cached nanoseconds while explicit timestamp updates and the ext2
inode stored whole seconds. Cargo backdates dependency metadata to compiler
start; a fractional source mtime in that same second could then appear newer
and trigger an unnecessary subsequent rebuild. The VFS now normalizes ext2
cache timestamps to its persisted precision while retaining tmpfs nanoseconds.
Focused host and guest checks cover this behavior. The existing exact Cargo
compile-count assertions remain unchanged. The corrected full `rust-test`
passed both build and reboot phases: `m12-macro` and its support dependency
each compiled twice, `m12-app` five times, and `itoa`/the dependency-free
application once each. The original no-op, source/dependency-change,
invalid-macro, real syntax failure and retained-output checks all passed.

All eight final command gates passed on the corrected sources. Complete host
output uses `build/logs/m15-rust-regression-COMMAND.host.log`; exact exit codes
and durations are retained in `build/logs/m15-rust-regressions.json`.

CI includes the source rejection suite and the new guest assessment after
preparing inherited Rust tools, and retains audit/preparation manifests and
logs. Remote CI was not run in this local batch. The runtime change is the
ext2 cached timestamp normalization above; no syscall, disk format, capacity

were not rerun and retain their separate earlier records. M15.5 can proceed independently with the verified inherited guest
rustc; this assessment does not make compiler source bootstrap its prerequisite.
