## Actual guest build and application gate

`cargo xtask gui-sdk-test` passed the build boot and a clean reboot on the
same native ext2 volume. COM1 line-editor input saved seven exact sources:
C/C++/Rust language clients, an ABI boundary probe, a caller-fault probe,
Rust note and the interactive Rust graphical terminal. The guest's real
GCC/G++ compile separate freestanding C/C++ objects. Guest rustc compiles
the dependency-free runtime rlib and Rust client objects, then links every
client with native CRT/intrinsics/panic code. Host tools only package source
and the already accepted compiler binaries; no host-built GUI client replaces
a guest output. The mounted immutable ABI marker is `anova.native.v1`.

Each language client opens its own window, renders text/primitives/widgets,
accepts physical `a` into its text field and a real button click, then closes
on `q`. The C++ client additionally verifies move construction, move assignment,
RAII destruction and moved-from/stale use. The Rust note copies edited text
into its explicitly process-local clipboard and checks the copied bytes.

The Rust graphical terminal starts a helper before GUI initialization. It
executes real native `/bin/echo` and supports `echo TEXT` and `pwd` commands.
QMP types `echo hi` one physical key at a time, waits for field acknowledgements,
presses Enter and verifies actual `hi` output pixels. Native command processes,
pipe output and their wait statuses are real; the helper is reaped on close.
This bounded terminal does not provide a PTY, job control or ANSI emulation.

The gate checks **28 actual screenshots** with independently specified literal
palette, border, textfield and original glyph samples. It never calls the
production renderer to construct expected pixels. Initial/text/clicked complete
screenshot SHA-256 values also match between all three independent language
clients, and every phase matches its own image after reboot. Sampling is not
full-screen per-pixel comparison; the older M14.3 gate remains independently
responsible for its complete composition comparisons.

All seven client/compositor pairs per boot have unique process IDs and actual
wait statuses. A deliberately invalid GUI output pointer writes unmapped
`0x1000`, producing exactly the declared client's hardware page fault (vector 14)
and reason 1/code 14 wait outcome. Other faults are rejected. The following
ordinary C client still works, proving recovery after the fault. No fixture
fault is mistaken for a normal exit. F11 stops each compositor; every expected
child is reaped, serial recovery succeeds, both guests exit 0 via clean ACPI
shutdown and both `e2fsck -f -n` runs pass.

After all builds the editor appends a real `#error` to the C source. Compilation
must fail 1 with the real compiler diagnostic, while the preceding executable
remains byte-for-byte unchanged. The editor removes that line. Exact seven
source files, seven parsed native executables and the retained pre-failure
C executable have matching hashes before/after reboot. The second boot runs
the retained applications without recompiling them.

## ABI, ownership and host checks

The generated C header asserts sizes/alignments/offsets; guest C/C++/Rust
clients exercise actual version negotiation and by-value rectangle calls.
Negative cases include wrong version/description size, invalid UTF-8, text
limits, unsupported color bits, small buffers, layout exhaustion, single-window
quota, stale/reused generations and double destroy. The runtime has no heap
allocator: its fixed-storage `LIMIT` cases are capacity failures, not a claim
of actual heap-OOM injection. The preserved M14.3 gate still performs real
kernel heap exhaustion and rollback.

Sixteen runtime host tests cover raster guards/clipping, glyph pixels,
UTF-8/backspace/capacity atomicity, lifecycle, copied chunk completeness,
ordered events, overflow RESET, geometry preservation during combined
resize/overflow, interrupted presentation/redraw, key modifiers/repeat/release,
malformed event shapes, disconnection and remote stale/session invalidation.
The complete host suite reports 182 passing tests. Three additional host gate tests check identity/wait records, fatal markers,
timeout and the exact single declared fault. These are pure tests, separate
from actual guest scheduling, physical input and memory isolation evidence.

The exported SDK was checksummed, its generated header checked, and a copy
outside the main workspace independently ran all 16 crate tests using its
own Cargo manifest. Formatting (root/user/standalone sources), purpose coverage
for 302 files, local Markdown links and `git diff --check` passed. Source and
unsafe ownership explanations were reviewed separately from those mechanical
checks. After the complete build/reboot gate, `cargo xtask gui-sdk-replay` passed
another retained-output boot using the final host driver. It required the
original ISO/source/ELF hashes, awaited the terminal's explicit `RENDERED`
acknowledgement before a single output screenshot, rechecked all seven
scenarios and preserved every source/executable hash. Its separate
`build/gui-sdk/replay.result.txt` records `result=Ok`.
