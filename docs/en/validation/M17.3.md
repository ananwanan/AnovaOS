## Reproduction and retained evidence

Run in the existing Ubuntu 24.04/WSL repository:

```sh
cd /home/ananwanan/projects/AnovaOS
cargo test -p anova-editor --target x86_64-unknown-linux-gnu
cargo test -p anova-abi -p anova-vfs --target x86_64-unknown-linux-gnu
cargo xtask desktop-files-test
cargo xtask desktop-test
cargo xtask desktop-pty-test
cargo fmt --all -- --check
python3 scripts/check_docs.py
cargo xtask check-files
```

`desktop-files-test` builds the ordinary desktop kernel, creates its own fresh
64 MiB Linux-personality ext4/JBD2 disk under `build/disks/`, and drives two
ordinary QEMU q35/TCG boots with one BSP, 3 GiB RAM, 800×600 VGA and PS/2.
A 180-second watchdog applies independently to each boot. This gate does not
require downloading or reconstructing compilers. Sources are entered physically;
UART only observes data and constructs explicit external-change/collision fixtures.

The gate retains `build/desktop-files-test/result.txt`, actual per-boot UART/TCP-QMP
transcripts and QEMU commands, genuine PPM scanouts, exact stopped-disk source
copies and their SHA-256 values. Failure is recorded as `result=Err`, with the
failed operation; a missing/failed result is not acceptance. Inputs are recorded
in `build/desktop/inputs.txt`; the result also records the exact ISO hash and disk.

[Retained minimal local evidence](../../assets/validation/M17_FILES_LOCAL.json)
contains exact implementation snapshots/hashes, the original per-boot records,
genuine editor/PTY PPM scanouts, source dumps, host-check outputs and preserved
regression observations. Decode each `gzip_base64` as Base64 then gzip, and verify
the decompressed `sha256`. This file preserves observations and pending scopes;
it does not promote the minimum loop to complete M17.3 storage-fault acceptance.

## Checks implemented by the gate

- Create a directory and physically type/save C, C++ and Rust sources.
- Modify C, cancel a dirty close, reject launcher stop and ignore session
  restart/exit while Files is active, then save without discarding the buffer.
- Occupy the exact temporary sibling from an independent process; reject save,
  retain dirty state, retain the old target and collision bytes, then retry.
- Change the same target externally, cancel the overwrite prompt, check the
  external bytes, explicitly confirm replacement and save the editor bytes.
- Rename C, create/delete a scratch source, navigate to the parent and reopen.
- Check actual editor source glyphs against independent literal font/colors.
- Read all three exact paths through the real graphical Linux-musl PTY. Check
  known source tokens on actual scanout using independent font/color samples.
- Cleanly stop the desktop, sync and ACPI-shutdown; run independent e2fsck and
  compare debugfs dumps to exact source bytes and the unchanged Linux ABI marker.
- Boot the same disk, reopen all sources graphically, repeat graphical PTY reads
  and stopped-disk exact-byte comparisons after a second clean shutdown.

The editor host fault matrix injects `IO_ERROR` and `NO_SPACE` at every required
save phase, including partial/completing write, temporary/backup file flush,
parent flush and replace. It checks that no failure marks saved and that exact
prior bytes survive at the old target or retained backup. A backup-cleanup error
is a successful save with an explicit retained-copy outcome. Separate native ABI
and VFS tests cover version/record/path validation, no-clobber rename, replacement
and shared persistent data access.

## Regression results and observer controls

Full `cargo xtask test-host` passed, including the existing journal-cut matrix
and the eight editor tests. Strict host/native/kernel Clippy, native file ABI
smoke, the original five-boot `desktop-test`, full compiler-enabled two-boot
`desktop-pty-test` and independent two-boot `terminal-test` passed locally.

The PTY gate exposed two host-observation defects. COM1 could read a newly created
file before the physical shell completed its write; the gate now waits for an
actual graphical `REDIRECT-0` completion marker. Repeated 1.4 MB compiler scanouts
at 30 ms also caused the 35-second compiler observation to fail on this WSL host.
An independent detached `8a1f4f7` checkout reproduced that timeout with unchanged
product code, the original 30 ms sampling and only the redirection handshake fix.
Its compiler build/stage/package inventories, BusyBox/fixture ELFs, source and
wrapper inputs were byte-identical to the current branch.

Only compiler-completion observation now samples every 500 ms. The 35,000 ms
watchdog is unchanged and checked before accepting a successful frame; all
5,000 ms input/interaction checks and other scanout cadence are unchanged. The
full gate passed with compiler completion at 16,113 ms; Ctrl+C, peer input and
independent UART took 2,497/2,774/61 ms. The new guest-built program's SHA-256 is
`f74307b578ca8971a48245124c82d23fa9d985ad34a14ee53fc78e5a8e2a5868`
after both shutdowns. This is a new run identity; historical M17.2 evidence is
retained unchanged.

The evidence retains all three failed observations, the independent baseline
commit/patch/results, a separate fresh-compiler diagnostic and its observer note,
as well as the successful full gate. The diagnostic's unsupported literal `G`
caused its matcher to report false despite actual successful output; it is not
used as the official pass. No compiler timeout or failed observation is hidden.

## Acceptance limits

Full M17.3 acceptance remains pending actual GUI-level file-size, inode, disk-full,
virtio write and flush failure cases, including the promised prior copy on those
real devices. Host model failures are not actual device failures. Earlier M16
storage gates remain applicable; they do not replace end-to-end editor evidence.
The gate proves clean shutdown/reboot only; abrupt power loss is unverified.
Full C/C++/Rust GUI compilation, concurrent compiler latency, fault recovery,
remote CI and physical hardware remain separately scoped. Actions stays main-push-only.
