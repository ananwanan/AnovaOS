`cargo xtask desktop-files-fault-test` passed the complete 16-case, 43-boot
local profile on implementation base `76e409e` with the retained source snapshot.
The successful run is `build/desktop-files-fault-test/1793195881857107135/`;
its exact ISO SHA-256 is `b1afcf226d02987f8f72387be997f9a03b949b84ae786cf2cb78e87a72f50f64`. This completes the remaining bounded
M17.3 storage-fault exit. It does not establish arbitrary power-loss durability.

The gate uses ordinary q35/TCG, one BSP, 3 GiB RAM, the unchanged desktop resource
quotas and genuine 800×600 scanout. Each boot keeps its 180-second watchdog;
open/save/close, error and pixel observations have 5,000 ms bounds. The independent
PTY compiler observer remains at 500 ms with its unchanged 35,000 ms deadline
and 5,000 ms interaction budgets. Existing main-push-only Actions policy remains.
The host QMP transport sends a complete JSON/CRLF record together and enables
`TCP_NODELAY`; UART file observations wait for complete records. These observer
changes do not alter keyboard cadence or any declared deadline. Clean reboot
checks mean normal ACPI shutdown followed by a fresh QEMU boot of the same disk;
this adds no in-guest reboot command. Device-error recovery on a separate copy
is described separately below. The maximum
measured flush fault-control interval was 1,641 ms. `implementation.json` binds
17 GUI/editor, host-gate, QMP, VFS/ext4/virtio and CI source identities; the gate
rejects changes during the run. `host-tools.json` records the actual local QEMU
8.2.2 and e2fsprogs binary identities/versions.

The `bounds` case opens exactly 16,384 bytes, rejects a 16,385-byte file while
clean, rejects insertions into full clean and dirty buffers, and rejects an
oversized open after an explicit discard choice while retaining the usable dirty
buffer. Path, cursor, length and whole-buffer fingerprint are checked. Separate
stopped snapshots compare disk bytes before any subsequent save; later saves,
normal shutdown, independent e2fsck, graphical reopen and a second normal shutdown
compare the exact expected 16,384-byte result and unchanged oversized file.

Four independent disks use real ext4 allocations to leave zero or one free inode
or 4 KiB data block. No bitmap/free-counter spoofing or host editor Fs mock is
used. Actual GUI saves encounter `NO_SPACE` while creating the temporary/backup
or writing their data. The gate observes error text and dirty pixels, exact short
buffer hex, target/sibling bytes and hashes. Independent COM1 removes only the
recorded pressure and inspected artifacts; the same GUI buffer then retries
successfully. The saved file bytes then survive clean shutdown/reboot.

Eleven other disks receive a fresh QMP blkdebug filter after mount. Selected
first-write and flush faults travel through the real virtio device request,
VFS and ext4/JBD2 save path. Actual `BLK:ERROR` completed status 1 and native
`FILES:IO_END` operation errors are required; per-case configuration and complete
QMP/UART records bind the chosen event to its real save phase. These are
representative stage cuts, not an exhaustive cut at every sector or journal
transaction. M16's separate matrix remains retained.

Stock QEMU can observe `flush_to_os` yet skip its flush-to-disk callback when no
new writes advanced the generation. For an explicit no-new-write file/parent
fsync, the gate uses real blkdebug flush breakpoints, observes them asynchronously,
installs the next breakpoint before resuming and rewrites the existing final
512-byte sector through the same backend to advance QEMU's write generation.
Tail bytes/SHA-256 are checked before and after the rewrite and again after the
completed FLUSH error. They must remain identical. The original real virtio FLUSH
must return completed status 1 in the intended syscall. The helper changes no disk bytes and does not substitute a guest
syscall result. The stock QEMU version and binary identity (canonical path/size/SHA-256), plus
the helper source, are retained.
For the exact stopped and remounted bytes below, **O** is the 17-byte
`// M17-FAULT-OLD\n`, **N** is the 18-byte `z// M17-FAULT-OLD\n`, **empty** means
an existing zero-byte file, and **absent** means an independently confirmed missing
path. Every error keeps all pending N bytes in the GUI; successful cleanup-error
cases remain clean.

The unchanged ABI marker and recovered prior copies are compared after normal
shutdown and reboot. An independent read-only audit confirmed all ten expected
shutdown/reboot `recovered.c` dumps exist and equal O; all ten failed/remounted
tail sectors equal the recorded original 512 bytes; all 17 implementation hashes
match. It counted exactly 43 boot commands and 32 clean `POWER:OFF` records. The
eleven initial fault sessions ended only after completed errors. No failed phase
is assumed to have created both siblings; see `independent-audit.json`.

After external device fault removal, same-mount retries still fail closed and
preserve the observed buffer and prior dirty/clean state. The gate records that
result, terminates QEMU only after completed errors, keeps the original failed
image and boots a separate copy through ordinary mount/recovery. It checks exact
namespace bytes again, copies a complete backup to `/persist/recovered.c` when
available, explicitly re-enters pending bytes where needed and retries through
the graphical editor. It then normally shuts down, runs independent e2fsck and
reboots/reopens/checks bytes. These selected failures do not establish replay of
an in-flight committed transaction in every boot. Termination after a reported
error is not a power cut during a save; unsaved-buffer crash recovery is unclaimed.

The new actual cleanup cuts exposed a product UX defect. Required save operations
had completed and the model correctly marked clean, but a redundant directory
refresh on the failed mount replaced the explicit saved/cleanup-error notice
with a generic storage error. The client now preserves the successful outcome,
skips that refresh after cleanup failure and logs `backup_cleanup_failed=true`.
The notice requests inspection because late cleanup errors can follow actual
backup removal. Both actual cleanup cases verify saved pixels, clean state and
phase-appropriate exact sibling bytes.

## Checks implemented by the gate

- Create a directory and physically type/save C, C++ and Rust sources.
- Modify C, cancel a dirty close, reject launcher stop and ignore session
  restart/exit while Files is active, then save without discarding the buffer.
- Occupy the exact temporary sibling from an independent process; reject save,
  retain dirty state, retain the old target and collision bytes, then retry.
- Change the same target externally, cancel the overwrite prompt, check the
  external bytes, explicitly confirm replacement and save the editor bytes.
- Rename C, create/delete a scratch source, navigate to the parent and reopen.
- Check actual editor source glyphs against independent literal font/colors.
- Read all three exact paths through the real graphical Linux-musl PTY. Check
  known source tokens on actual scanout using independent font/color samples.
- Cleanly stop the desktop, sync and ACPI-shutdown; run independent e2fsck and
  compare debugfs dumps to exact source bytes and the unchanged Linux ABI marker.
- Boot the same disk, reopen all sources graphically, repeat graphical PTY reads
  and stopped-disk exact-byte comparisons after a second clean shutdown.

The editor host fault matrix injects `IO_ERROR` and `NO_SPACE` at every required
save phase, including partial/completing write, temporary/backup file flush,
parent flush and replace. It checks that no failure marks saved and that exact
prior bytes survive at the old target or retained backup. A backup-cleanup error
is a successful save with an explicit cleanup-failure outcome; actual device cleanup
can fail after the sibling has already been removed. Separate native ABI
and VFS tests cover version/record/path validation, no-clobber rename, replacement
and shared persistent data access.

## Acceptance limits

The executed 16-case/43-boot GUI profile completes bounded M17.3 local storage-fault
acceptance. It covers the declared size limit, real inode/block exhaustion,
representative virtio write/flush phases, exact artifacts, recovery/retry and
normal shutdown/reboot. It does not cover every sector cut, arbitrary concurrent
writers, in-save power cuts, unsaved-buffer crash recovery or arbitrary atomic
durability. QEMU termination occurred only after completed errors; not every
ordinary recovery boot replays an in-flight committed journal transaction.

Full all-GUI C/C++/Rust compilation, compiler-load latency and M17.4/M17.5 remain
separate. Main-push-only CI is configured; actual new remote execution and physical
hardware remain unverified. Existing M16 and independent ext2/COM1 gates remain.
