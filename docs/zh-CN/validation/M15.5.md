# M15.5 本地 guest 内核重建

[English](../../en/validation/M15.5.md) | **简体中文**

记录于 2026-10-24（Asia/Shanghai），任务分支 `feat/m15-bootstrap`，实现基线 `104cdab`。实现见 [M15 内核](../milestones/M15_KERNEL.md)。三次真实启动门禁在 QEMU 8.2.2 q35/TCG、单 CPU、3 GiB RAM、无 NIC 下通过，接受声明范围内的 guest 内核构建、保留 ELF 的准确宿主辅助打包及实际启动/失败/恢复。此处保存历史证据，后续进度见[状态](../guides/STATUS.md)。

## 已实现的验收契约

`cargo xtask bootstrap-kernel-test` 准备当前内核、本地 crate 和 linker 的准确字节、隔离离线工作区及 20 个经认证 registry 包。在继承的 M12 Rust/Cargo/rust-lld 1.90.0 旁叠加匹配的官方预编译 bare-metal core/alloc/compiler_builtins 库。没有宿主目标产物替换 guest 编译。初始启动内核和应用仍由宿主构建并独立标识；源码准备、宿主编译的构建/容量诊断与实际 guest 编译产物分开记录。

目标为 `x86_64-unknown-none`，启用 `bootstrap-metrics`，opt-level z、单任务/代码生成单元、无调试信息、剥离符号和 panic abort。显式 Cargo target 将内核 code-model、relocation、red-zone 参数与 Linux-musl build scripts 隔离，全部输出和临时元数据写入持久盘。

三次会话必须证明 guest 实际编译/发布、保留 ELF 的字节准确打包和启动身份，再验证真实编译拒绝保留旧内核及后续恢复启动。每次须正常 ACPI 关机、刷盘、确认 DMA reset，停盘通过只读 e2fsck。失败探针只向未发布 candidate 编译小型刻意非法 Rust 源码，并非完整失败的内核 Cargo 重建。

## 容量与回归行为

宿主预检发现 stripped 内核不足 1 MiB，而 smoltcp 中间 rlib 超过 2 MiB，因此 persistent ext2 文件上限改为 4 MiB，仍使用原 direct/single-indirect 格式。tmpfs 和 coherent readonly shared-file cache 保持 1 MiB；活动缓存拒绝过大增长并返回 EBUSY，空闲缓存先安全丢弃，大型私有文件快照独立处理。工作盘仍为 16 MiB/512 inodes，VFS 2,048 nodes、内核堆 16 MiB、任务 32 槽；增加 QEMU RAM 不能代替这些边界。

宿主测试覆盖真实 4 MiB 写入/读回/重挂载、缩小/补零增长、inode/块复用、上限/算术拒绝且无写入、按后端区分的 seek/ftruncate 和活动/空闲共享缓存增长。原生文件系统样例写过 1 MiB 并在 4 MiB 拒绝；Linux 样例分别检查持久 4 MiB 和 tmpfs 1 MiB，同时保留文件字节与 fd offset。guest 容量探针验证 EFBIG、EMFILE、EAGAIN 后的资源复用。

## 初次执行失败及修正

首轮源码重建到 smoltcp 元数据输出时，在 `/tmp/rustcLC5UAe/lib.rmeta` 出现 `No space left on device`。Rust launcher 覆盖了构建驱动指定的持久 TMPDIR，使用 `/tmp`，其文件仍受 1 MiB 限制。现保留显式 TMPDIR，仅未指定时默认 `/tmp`。修正后使用全新独立工作盘；失败日志为 `build/logs/bootstrap-kernel-tmpfs-failure.serial.log` 和 `.run.log`，清单为 `build/bootstrap-kernel/tmpfs-failure.prepared.json`。

锁定 smoltcp rustc 调用还需要 71 个参数，超过原 wrapper 的 70 上限；现最多 80，明确为注入选项和终止元素保留数组容量。

## 大文件 I/O 前置条件

修正临时目录后暴露重复间接表读取。独立 counted BlockDevice 测试以 4,096 次 512-byte append 写入 2 MiB，观测 16,211,368 次扇区读取。每次写两遍扫描前缀并重复读取同一 indirect table。该探索 QEMU 在验收前刻意终止，日志为 `build/logs/bootstrap-kernel-slow-io.serial.log` 和 `.run.log`，准备清单为 `build/bootstrap-kernel/slow-io.prepared.json`。

现在每个写操作保留一份私有间接表快照、验证所有引用地址，并在有序盘上 pointer 发布时同步更新快照。磁盘格式、空间预检、data/pointer/inode-length 顺序和部分 I/O fail-closed 行为不变，没有跨操作或全局 inode cache。同样测试现在为 175,376 次读取，约减少 92 倍。回归按写次数限制读取量，并测试表读取失败、损坏表/数据指针、拒绝时无写及成功恢复。计数存于 `build/logs/m15-kernel-storage-io-preflight.txt`，这是测试 I/O 次数，不是编译端到端提速 92 倍。

## 实际 guest 构建与恢复

首次会话以真实 guest Cargo/rustc/rust-lld 从准备源码编译活动内核、本地及 registry 包，发布 349,464 字节 high-half static 内核 ELF。初始宿主种子内核 SHA-256 不同。宿主重挂停盘、核 ELF 并保留准确字节，经 preserved-kernel 入口打包，该路径不调用宿主内核构建；下一次启动前独立提取 ISO 内核并逐字节比较。

后两次启动报告预期嵌入身份，通过内存所有权/页权限、校准计时器、挂盘和原生 C 应用执行（预期退出 7）。第二次还运行继承 rustc、容量拒绝/复用及真实语法拒绝（编译器退出 1）。容量探针耗尽 29 个额外 fd 和 29 个 child 槽后恢复，记录的进程/描述符峰值到达既有 32 上限，原内核 ELF 完全不变。最终独立启动同 ISO/身份，181 个保留工作区文件与先前恢复状态一致。三次均正常 ACPI/刷盘/确认 DMA reset，三次只读 e2fsck 通过。

继承 Cargo 输出非致命 global-cache last-use advisory-lock 警告，仍以 0 完成并通过全部显式产物/运行检查。本验收不接受通用 SQLite/POSIX locking 或 cache pruning。完整编译输出保留于持久构建日志和宿主 `bootstrap-kernel-build.cargo.log`，串口还保留真实 child statuses。

## 相关运行时和存储回归
