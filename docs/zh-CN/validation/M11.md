- Rust 1.90.0、edition 2024，bare-metal kernel/native/Linux-musl 各有独立 target/linker flags；development Rust 保留调试信息并用 opt-level1。
- QEMU 8.2.2、q35/TCG、单 CPU、锁定 Limine/OVMF；开发 ISO 用 1 GiB，旧 base-image 回归仍用 256 MiB。
- 源码构建 GCC/G++11.2.0、binutils 2.37、make 4.4.1、musl 1.2.4、GMP 6.2.1、MPFR 4.1.0、MPC 1.2.1，全部 URL/SHA-256 在[inputs.json](../../../ports/gcc/inputs.json)。校验锁定的 musl.cc GCC 11.2.1 archive 是宿主 bootstrap，不是目标 sysroot。

- 真正执行 installed-file mismatch 和 source-recipe change 两拒绝路径，均非零；恢复后 inventory 验证通过。重复 toolchain-build 可复用已验缓存，最终配方先准备完整新安装再替换旧生成树。

recipe/config 在 `ports/gcc/build.py`，日志、archive、installed inventory 和 package/archive hashes 留 `build/toolchain`。宿主小型 launcher/runtime probe 只配置或检查 guest，不替代 guest 生成的验收应用；再分发前参阅[第三方边界](../third-party/m11.md)。哈希仅标识本地构建，compiler configuration 保留绝对宿主路径，完整逐文件清单随 image。

## guest 开发与独立磁盘检查

`cargo xtask toolchain-test` 在普通启动上用真实 UART 完成：

1. runtime probe 使用真实 vfork child 共享父进程字节，父进程挂起，exec 后其 SIGUSR1 handler 观察 child 最终值。失败 exec 后 child exit 也以正确 wait status 唤醒父进程。另验 tmpfs 私有快照、offset 不变、umask、fchmod/stat、不支持 special mode bits 和真实 32 描述符上限。
2. guest editor 创建 C、C++、Makefile、语法错误和链接错误源，宿主随后要求逐字节相符（含 tab）。
3. guest GCC 编译/链接两个 C 源码，应用检查 stdio、malloc/free、argv 和文件输出 guest-C:42。
4. guest G++ 以 `-pthread` 编译 C++17，应用检查 string/vector、异常传播、unwind 时 RAII 析构、真实 std::thread、原子通信和 join。
5. make 构建独立对象，未修改的第二次调用报告无事可做；editor 改 helper 返回 43 后只重编 helper.c。UART 要求 main.o 编译一次、helper.o 两次，新应用写 guest-C:43。
6. 真实 parser 和 undefined-symbol linker 错误分别退出 1，旧程序仍运行、拒绝输出不存在，probe 还检查编译临时文件清理。
7. 正常 ACPI 后独立检查 ext2 源码字节、ELF、可执行权限、SHA-256 和干净 e2fsck。第二次启动运行保存的 C/C++ 应用再正常关机，全部独立哈希在两次间相同。

## 继承回归

- verify 全部 13 场景满足预期：boot33、panic/OOM35、真实 fault37、注入 hang 超时。OOM 须在扩大后的 16 MiB heap 真实申请 32 MiB 并到 alloc 默认 panic，不只检查诊断文本。
- 普通启动保留全部 M9 static/PIE/dynamic-musl、pthread/TLS/futex、signals/PTY、native isolation、页/堆耗尽和精确回收；tmpfs 压力现在真实耗尽扩大 heap。
- terminal-test 通过串口编辑、CRLF/EOF、shell 重启、dynamic-musl/Ctrl+C、全新启动 tmpfs 丢失。
- persistence-test 通过 editor/source/ELF保留、native 执行、shutdown/e2fsck、readonly/unknown-feature拒绝、真实 virtio write/flush错误。
- network-test通过受控TCP/UDP/DNS、poll/timeout/signal、fd复用/回收和DMA teardown。
- package-test通过离线install/upgrade/rollback/remove、reboot/userdata、HTTPS和精确CA/name/expiry拒绝。
- 77 项 host tests 通过，含扩展 startup-vector、私有快照、offset 保留、mode/timestamp、严格 OOM。
- host all-target/native-user/kernel(qemu-test/double-fault/no-execute) Clippy 均拒 warnings，两个 workspace 格式和全部 189 first-party 用途条目通过；Python recipe/source locks 及 shell 入口解析通过。
- trace-compat 对锁定 Linux probes、BusyBox和static/PIE/dynamic-musl通过；host trace 仅是对照，不能代替 guest 执行。

独立 CI compiler job 先构建锁定工具再运行 toolchain-test，只上传证据/哈希清单而非工具链二进制；本记录不声明远端 Actions 通过。

## 接受限制

仅接受声明 musl 范围内离线、静态、小型 C/C++ 应用开发。异常和一个标准库线程已启用并实测，不代表任意 stdlib/build-system。dynamic app、LTO、OpenMP、sanitizers、compiler self-bootstrap 和 guest Rust/Cargo 不属 M11。GCC 可选 sysinfo/getrusage/madvise probe 可真实 ENOSYS，显式 GC 参数支持已验路径，不伪造 syscall 成功。

仍为单 BSP、32 任务槽、eager allocation 和固定资源边界。历史 ext2 文件 1 MiB，仅正常关机持久化，无日志、原子编辑保存或断电恢复保证；不声明通用 Linux/glibc、SMP 或公开完整源码配套的工具链二进制分发。准确限制/所有权见 M11_TOOLCHAIN。
