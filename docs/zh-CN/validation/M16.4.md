# M16.4：受控 ext4 可写

[English](../../en/validation/M16.4.md) | **简体中文**

2026-10-27 在 `feat/m16-ext4-write` 实现，基于 M16 基础提交 `e6c67af`
（其基线为 `dev` 的 `616ff47`），扩展了[只读阶段](M16.md)。
本地验证记录见下文；远端 CI、M16.1 预算、JBD2/M16.5 与工作盘迁移/M16.6 分别验收。

## 准入与显式启用

普通内核和 `Filesystem::mount` 仍将 ext4 挂为只读。只有 `ext4-write` 内核 feature、
`Ext4::mount_writable` 或明确的 `mount_with_ext4_writes` 请求才会在完整有界审计后启用
**ext4-write-v1**。即使使用可写内核，设备保护的只读盘也保持只读。

配置使用 e2fsprogs **1.47.0**、4 KiB 块、256 字节 inode、组内元数据与线性目录；
COMPAT=0、INCOMPAT=`0x42`（extent/filetype），RO_COMPAT 仅限 sparse_super/large_file。
拒绝带日志、需要恢复、脏盘、checksum、64-bit、flex/indexed、xattr 和未知特性布局。
挂载审计位图尾部、保留块/inode、组及全局空闲计数、所有受支持 inode 间的唯一块归属、
目录类型/链接数、点/点点和以根为终点的父目录链。拒绝泄漏/重复分配、不支持类型、
有硬链接的普通文件、非 root 所有权和特殊权限位。

```sh
cargo xtask ext4-image --linux build/disks/work.ext4
cargo xtask run --ext4-write --toolchain --disk build/disks/work.ext4
cargo xtask foundation-write-test
```

原生 ABI 工作盘省略 `--linux` 和 `--toolchain`。创建命令仅以 `create_new` 新建 `build/`
下的普通文件，不覆盖旧镜像或设备；默认 ext2 创建/启动路线保留。确切选项：

```sh
mke2fs -q -t ext4 -b 4096 -I 256 -g 256 -N 128 -m 0 \
  -O none,extent,filetype,sparse_super,large_file \
  -E lazy_itable_init=0 -d SOURCE work.ext4
```

命令创建 8 MiB 镜像，包含不可变 `.anova-abi`、临时目录、自有源码/Makefile 与独立读错误
样本；不转换现有磁盘，也不切换默认工作盘。

## 语义与资源边界

| 操作 | 已实现契约 |
| --- | --- |
| 文件数据 | 创建/独占创建、覆盖/追加、读取、截断及增减长度至 256 MiB；检查偏移；空洞/未初始化 extent 读零，导入文件 EOF 尾部及复用块不会暴露旧数据。 |
| 分配 | 多块组/inode 组、空闲计数和目录计数同步；合并 extent 和有界外部叶节点；最终删除回收数据/树块及 inode。 |
| 目录 | 线性记录复用/扩展、mkdir/rmdir、文件/目录跨父目录重命名、替换空目录或文件、正确更新点点/父目录链接，拒绝环、类型冲突和非空目录。 |
| 生命周期 | 重命名/删除保留原描述符身份、dup/fork 共享偏移和只读共享映射；新名字不会占用尚保留的孤儿 inode。最终关闭/解除映射回收；分配失败保留可重试的固定身份；延后清理的 OOM 不会把已经发布的删除/重命名报告为失败。替换仍作为 cwd 使用的目录返回忙。 |
| 权限/时间 | root 所有的 `000..777` 权限、执行准入、秒级 atime/mtime/ctime；chmod 更新 ctime，数据修改更新 mtime/ctime，显式时间保留未指定字段。读取采用 noatime；不承诺多用户/ACL/set-ID。 |
| 未支持 | 创建硬链接/符号链接、任意 Linux ext4 特性、可写共享映射及缩小正在映射的文件仍不支持；native syscall v1 不变。 |

可写审计最多接收 16,384 个 inode、128 组、每目录 256 个块（1 MiB）。extent 遍历保留
只读的深度、1,024 extent、64 树块限制；写入重建使用内联根或最多四个外部叶节点。
每次操作最多暂存 **1,024 个发生变化的 4 KiB 块**，包括数据和元数据。实际分配耗尽或达到
暂存上限返回 `NO_MEMORY`；磁盘/inode/extent/目录容量耗尽返回 `NO_SPACE`。
通过较小的连续写入可构造更大文件。内核 16 MiB 堆、2,048 节点、128 共享打开描述、
32 task/descriptor 和 1 MiB 只读映射缓存上限不变。格式上限不等于容量性能验收。

## 顺序与失败边界

所有可失败的分配、读取、位图/命名空间更新、计数及树构造都在未发布的内存暂存层完成。
预检阶段 ENOSPC、OOM、参数错误或读失败会丢弃暂存，原有磁盘字节、名字、长度和共享
偏移保持不变。VFS 在创建持久对象前预留缓存/打开容量。

提交先写入并 flush 脏超级块，再写数据、flush、发布暂存的元数据/计数、再次 flush；
发布过程不分配内存。写/flush 失败使挂载停止服务：后续操作/sync/shutdown 返回错误，
不报告正常清理。写入或 flush 清洁标记失败时尽力恢复脏状态；设备不可用时无法保证修复
写入到达介质。

**这不是日志，也不是崩溃原子事务。** 发布开始后的 I/O 失败可能留下部分修改，需要离线
恢复；测试保留原始失败镜像。旧输出保留只对预检失败及声明的编译错误用例验证，不承诺
任意中断的元数据提交。`sync`/`fsync` 会 flush 但保持脏标记；成功关机要求完成孤儿回收
并 flush 清洁标记。仅停止后的正常清洁镜像要求通过 `e2fsck -fn`；正常重启不代表断电恢复。

## 本地验证

可复现宿主测试使用真实 `mke2fs` 镜像、持久字节比较与独立 `e2fsck -fn`，不是模拟 inode。
线程局部的 System 分配器在创建、写入、调整长度、重命名、删除和最终回收的每个连续预检
分配点返回真实失败。独立 VFS 测试注入最终关闭/解除映射回收 OOM，验证身份固定和重试。
设备测试区分可恢复的预检读取与停止服务的写/flush 提交故障。

`foundation-write-test` 构建显式可写内核与继承的 guest GCC/make 镜像，验证真实 Linux/musl
文件操作、目录/cwd 移动、fork/dup、映射一致性、原生堆耗尽、实际 ENOSPC、`make`/GCC
与 BusyBox 读取、源码编译失败保留旧可执行文件、正常关机/重启、准确元数据和独立 ELF
哈希。独立保留磁盘注入已完成 virtio 请求的读、写和延迟 flush 错误；设备只读启动比较
完整镜像不变。QEMU 为 q35/TCG、单 BSP、1 GiB 内存；主启动限时 240 秒，后续故障/重启
启动限时 120 秒。
