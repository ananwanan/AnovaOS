## 后端/缓存契约

VFS 持有能力明确的文件系统后端，替代具体 `Ext2`。挂载仅发布根和不可变 ABI 标记，
按需查询；readdir 使用独立于 inode/缓存身份的有界后端游标。native v1 线格式不变，
Linux getdents 返回真实下一目录 cookie。持久 stat 身份在普通文件缓存回收后保持稳定。

节点向量从 32 槽可失败扩展到原有 2,048 槽限额。不打开、不映射的普通文件节点可回收，
不释放其磁盘 inode；目录/cwd、打开描述、活跃映射和标记保持固定身份。这不代表无限
目录。持久化修改前先预留槽位；继续检查 inode 耗尽、descriptor/OOM 回滚、共享偏移、
unlink/open 生命周期和映射一致性。10,001 文件的确定性后端隔离缓存压力；独立 ext2
测试覆盖未缓存子节点、rmdir、rename、时间戳和已打开文件保留。单纯目录遍历不填满
缓存，实际 ext4 guest 另行遍历 10,001 个文件。

## 准确的 ext4 只读配置

测试工具为 e2fsprogs **1.47.0**、Rust **1.90.0**、QEMU **8.2.2** 及锁定的 Limine 9.5.0、
OVMF 2024.02-2ubuntu0.9。guest 门禁使用 q35/TCG、单 CPU、256 MiB RAM、无 NIC 和普通
原生启动镜像。所有镜像均为新建普通文件。

```sh
mke2fs -q -t ext4 -b 4096 -I 256 -g 1024 -N 16384 -m 0 \
  -O none,extent,filetype,sparse_super,large_file \
  -E lazy_itable_init=0 -d SOURCE NEW_IMAGE
cargo xtask foundation-test
```

64 MiB 镜像含 16 个块组。允许 compat=0、incompat=0x42（filetype/extents）、ro_compat
为 0x3（sparse_super/large_file）的子集。不支持 journal、checksum、64bit、flex/meta
块组、indexed 目录、xattrs、符号链接、硬链接或特殊文件。未知特性或设置恢复标志的
镜像明确拒绝，仅公开普通文件/目录和整秒时间字段。文件上限 256 MiB，extent 树深度
最多 3，每个已加载 inode 最多 64 个外部树块、1,024 extents，最多 128 个局部块组。
未知特性组合不会启用写入。

读取前检查几何、扇区容量、inode/block 分配、元数据保留、extent 顺序/范围/重叠、循环
和每 inode block 计数。这不是内核内完整 fsck，也不宣称通用 ext4 兼容。稀疏和未初始化
extent 返回零，向未初始化块预置的已有设备字节不会暴露。五项真实镜像宿主测试覆盖
20 MiB 外部/碎片 extent、200 MiB 稀疏文件、目录游标、读取错误、未知/脏几何、元数据
别名、循环、重叠和未分配引用。只读设备统计所有写入/flush 尝试，结果均为零。正常
停止镜像均通过 `e2fsck -fn`。

四次启动门禁分别在可写设备和只读设备上验证准确字节及 `/persist/hello-c` 的真实
执行/退出状态、重启，再拒绝恢复标志和未知特性的镜像副本，保留串口 shell。每份原始/
拒绝镜像均比较会话前后哈希；有效停止盘通过 e2fsck。正向启动限时 120 秒，负向启动
沿用 60 秒 watchdog。计时为完整会话，不是前台延迟。没有为可写文件系统伪造 flush
成功：只读后端没有脏状态，也不调用设备写入或 flush。

每次运行将准确 ISO、initramfs、源测试数据、原始/拒绝镜像与 result JSON 保留于
`build/foundation/readonly-TIMESTAMP/`，UART/QEMU 日志位于
`build/logs/foundation-*.{serial,qemu}.log`。结果对按路径排序的第一方源码/配置字节
计算摘要（路径与内容均带长度），验证执行期间源码稳定，并记录 ISO/磁盘哈希、机器
配置及时间；文档不纳入此实现摘要，在验收后更新。
