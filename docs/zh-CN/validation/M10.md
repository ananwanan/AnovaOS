# M10 本地网络与应用包验证

[English](../../en/validation/M10.md) | **简体中文**

记录于 2026-10-22（Asia/Shanghai），dev 合并 M9 的基线 `cbab786`，任务分支 `feat/m10-network-packages`。只覆盖受控 [M10 配置](../milestones/M10_NETWORK_PACKAGES.md)，远端 CI/推送独立报告。后续进度见[当前状态](../guides/STATUS.md)。

## 输入

- Rust 1.90.0、edition 2024，x86_64-unknown-none 内核和 Linux/native 用户构建分离。
- QEMU 8.2.2、q35/TCG、单 CPU、256 MiB、锁定 Limine/OVMF 和 M9 musl 1.2.4-2 runtime。
- smoltcp 0.12.0，提交 Cargo.lock；内核无 std 或宿主网络依赖。
- Mbed TLS 2.28.10，提交 `2fc8413bfcb51354c8e679141b17b3f1a5942561`，由 musl-gcc 构建。
- loopback TCP/UDP/DNS peers 为 18080/18081/18082，TLS1.2 peers 为 18083/18085。不需要公网、host bridge、TAP 或防火墙修改。
- 生成短期测试证书，私钥只留在忽略的 build/compat，镜像仅含公有证书；证书字节明确属于生成输入。

原 linux-threads、linux-pie、libm9、dynamic-musl 摘要与 [M9](M9.md) 相同。验收发现迁移工具链的 linker 路径错误：缺 shared libc 时 TLS DSO 错拉 libc.a。恢复 shared input 后 M9 hashes 再次相同；构建现明确拒绝缺少真实 libc.so DT_NEEDED 的 DSO。fresh-build 宿主跟踪还发现复制 BusyBox/runtime 时丢 executable mode，现显式保留源权限，ELF 字节不变。

## 接受的受控路径

`cargo xtask network-test` 经真实 UART 启动的 Ring 3/syscall 通过：

- modern PCI virtio-net RX/TX、两个自有 DMA 页及真实 ARP/IPv4/TCP/UDP 流量。
- TCP 非阻塞 connect、poll、SO_ERROR、dup/close、echo、有界 receive timeout、shutdown/EOF 和 refused connection；不支持的 family/syscall 返回错误。
- UDP 回复和源字节，EFAULT 在 dequeue 前返回，拒绝超大 datagram。
- 真实随机 DNS A query/reply，检查 ID/source/question，拒绝压缩名环，并验证真实缺回复超时。
- 阻塞的已连接 socket 被 SIGUSR1 打断、fork/wait、八槽耗尽、32 次 create/close。
- 正常关机须 `[NET:RESET] acknowledged=true dma_released=true`。

`cargo xtask package-test` 在同一持久镜像的三次启动中通过：

1. 无 NIC：安装 demo v1 并运行真实 native ELF，保存用户数据；真实 staged-file 写后中止 upgrade 仍保留 v1；拒 corrupt/traversal/ABI archives，再安装 v2、关机，通过 e2fsck。
2. 无 NIC：从盘恢复 v2、核版本 payload、运行 ELF、读取原用户数据；卸载后检查 tombstone 和数据保留，通过 e2fsck。
3. 带 virtio-net：接受可信 repo.anova HTTPS，拒 wrong hostname/CA/expired cert，通过 TLS 获取锁定 demo v2、验证安装并读 payload，network reset/e2fsck 通过。

TLS 负例必须得到真实 Mbed TLS certificate-verification -9984 及 X.509 flags4(name)、8(trust)、1(expiry)，其他超时不能满足；CA/name/date 检查始终开启。真实 package parser 在 Linux 宿主先检查 valid/corrupt/traversal/incompatible ABI，再打包进 guest。

日志为 build/logs/network.serial.log、packages-offline.serial.log、packages-reboot.serial.log、packages-online.serial.log、https-peer.log；原源码/二进制持久化和终端日志名不变。

## 回归结果

- 76 项宿主测试通过，含公历/闰年及共享 socket open-description 在 dup/fork/exec/thread-table close 中的生命周期。
- host/kernel/native user Clippy 拒绝全部 warnings，两个 workspace 格式与逐文件用途检查通过。
- M0–M9 的 13 个 QEMU 场景通过：boot33、panic/OOM35、真实 fault37、注入 hang 超时并拒绝；保留完整 M9 pthread/futex/signals/PTY/static-PIE/dynamic-musl、隔离、heap/frame 耗尽和精确回收。
- 普通 UART 通过 dynamic-musl、Ctrl+C、行编辑/EOF、全新启动 tmpfs 丢失。
- 持久化通过 editor/source/ELF 重启字节/哈希、真实 native 执行、正常关机/e2fsck、只读/未知特性拒绝、真实 block write/flush 错误。
- 既有锁定 probes、CLI/runtime 的 Linux 宿主兼容 trace 通过。

## 限制

网络验收仅限 QEMU 上轮询 IPv4 client。TCP server、IPv6、DHCP、通用 musl getaddrinfo 和任意 Linux 网络程序不在范围内。HTTPS 获取使用受控宿主 peer/生成测试 CA，任意公网仓库和生产 TLS policy 未验证。包仅接受 native SDK v1 依赖，不声明 dependency solver、多用户权限、并发 installer 或断电事务；ext2 仍无日志，物理 I/O 失败仍需恢复。在该历史阶段，SMP、通用 Linux/glibc 和 guest GCC/G++/rustc/Cargo 仍属后续。
