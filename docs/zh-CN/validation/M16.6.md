## 迁移与显式使用

```sh
cargo xtask ext4-journal-image --linux build/disks/new-work.ext4
cargo xtask run --ext4-write --toolchain --disk build/disks/new-work.ext4
# 或将已有、停止且干净的 ext2 镜像复制到新目标：
cargo xtask ext4-migrate build/disks/retained.ext2 build/disks/migrated.ext4
cargo xtask foundation-migrate-test
```

创建使用 e2fsprogs **1.47.0**、64 MiB 普通文件、4 KiB blocks、256-byte inodes、每组 8,192
blocks、4,096 inodes 和 8 MiB 内置日志：

```sh
mke2fs -q -t ext4 -b 4096 -I 256 -g 8192 -N 4096 -m 0   -O none,extent,filetype,sparse_super,large_file,has_journal   -J size=8 -E lazy_itable_init=0 -d SOURCE NEW_IMAGE
```

工具使用 create-new，绝不覆盖已有镜像。CLI 提供的路径限于 `build/` 下的普通镜像，不操作
物理块设备、不原地转换；普通/默认存储仍为 ext2。原生 ABI 配置省略 `--linux` 和 `--toolchain`。

迁移首先要求源盘已停止并通过 `e2fsck -fn`，通过实际只读的文件/设备包装器打开，核对不可变
ABI 标记。分块复制名称与字节到新建目标，恢复权限与秒级 atime/mtime/ctime，关机后只读重挂载，
比较完整路径/类型/权限/时间/哈希清单。复制子节点后恢复父目录时间，前后核对源盘哈希并保留
启动/恢复用途；`NEW_IMAGE.migration.json` 记录准确清单和身份。复制失败保留完好的源盘与
供检查的部分目标，不会隐式提升默认盘或覆盖重试。

## 实际验收流程

1. 创建包含受检构建闭包的干净 ext2 源盘，迁移到新 JBD2 盘，比较全部 31 个路径/字节/权限/
   时间；用同一内核实际只读启动保留的 ext2 源盘，核对 ABI 标记。
2. 新盘 guest 启动真实 make/GCC 与独立写进程，后者反复覆盖/fsync 128 KiB 文件。等实际 GCC
   命令进入日志后，在构建仍活跃时通过 UART 请求 fork/exec BusyBox echo、fsync/rename 保存
   前台文件、读取真实编译日志，强制响应满足预算；等待编译/链接成功，回收写进程后正常关机。
3. 再启动并强制重编译，在存储压力下重复前台操作，对构建进程组发送 SIGINT，等待非成功返回，
   保留上次可用可执行文件，回收写进程后关机。
4. 再启动，运行重建的 bzip2 压缩/解压官方样本，故意编译拒绝样本（必须出现准确编译器诊断、
   make 状态 2），再次运行工具并正常关机。
5. 每次停止盘独立通过 `e2fsck -fn`；核对中断/编译拒绝前后可执行文件哈希、解压与源字节完全
   一致、压缩与官方 block-size-1 样本完全一致、重启后的前台保存、迁移源码字节和原 ext2 均未变。

专用前台监督程序属于验收工具；通用桌面/PTY 编辑和 M17 流程仍需独立实现/验收。
`build/foundation/migration-TIMESTAMP/` 保留源盘/工作盘、ISO、guest 生成 ELF、预算、迁移/
最终清单、源码/产物哈希、资源观察值与 UART 日志。CI 已加入新门禁并上传证据，实际远端运行
结果另计。
