## 宿主跟踪

`cargo xtask trace-compat` 对 musl 和 BusyBox echo/ls/cat/sh 通过。真实 QEMU-user `-strace` 日志与输出保存在 `build/logs/compat-host-*`。此环境禁止 native ptrace，因此这些是 Linux 上的 QEMU-user 观察，不是完整 native strace；同架构 exec 可能离开 QEMU-user，故各 applet trace 补充父 shell trace。

观察到 musl 使用 arch_prctl、set_tid_address、ioctl、writev、mmap、brk、PROT_NONE brk guard、munmap、open、write、lseek、read、fstat、close、unlink 和 exit_group。BusyBox ls 另用 CLOEXEC open/fcntl、getdents64、lstat；ash 增加 identity/cwd/stat、signal 查询/修改/mask、pipe、fork、dup2、execve、wait4/WNOHANG。适配依据这些实测实现；不支持的 ioctl 和自定义 signal action 在 AnovaOS 仍返回真实错误。

## 实际 guest 检查

`cargo xtask test-compat` 仅在完整旧启动回归、真实 Linux 标记和 QEMU isa-debug-exit 33 均满足时通过。负载是独立 Ring 3 ELF 程序，而非内核函数或预写日志。

| 场景 | 要求证据 |
| --- | --- |
| freestanding Linux | argc/argv/envp/auxv；unknown->ENOSYS；EBADF/EFAULT/ENOENT；匿名页清零；FS base/非法base；私有 fork/Linux wait 状态 |
| 事务式 exec | 缺可执行文件时调用者存活；exec 成功接收环境；CLOEXEC 槽消失，继承共享 open-description 仍可用 |
| SIGPIPE/random/time | 真实断管以 signal13 终止默认 child，忽略 SIGPIPE 则 EPIPE；检查 RDRAND、拒 bad random pointer、relative nanosleep 返回 |
| musl 1.2.4 | 真实 libc/PT_TLS 初始化、volatile compiler TLS、errno、200,000-byte malloc/free、create/write/seek/read/fstat/close/unlink |
| BusyBox echo/ls/cat | echo 准确、/etc 列目录成功、motd 字节准确，各进程退出 0 |
| BusyBox ash | 真实 fork/exec/wait管道/重定向；/tmp/bb逐字节核验；shell 退出后 VFS 独立验 5,000-byte 管道；false 状态展开为 1 |
| 内存负例 | 部分 anonymous-map OOM 回滚；overlap 不发布前缀映射；销毁后 frame/heap 精确回基线 |
| 回收 | 各 Linux 负载退出后无 process/open-description/pipe，frame/heap计数恢复 |


门禁要求以下真实观察：

```text
[LINUX:MEMORY] partial_oom=rolled_back overlap=retained frames_restored=true heap_restored=true
[LINUX:PROBE] errno=true mmap=true TLS=true fork=true wait=true exec=true env=true CLOEXEC=true SIGPIPE=true random=true sleep=true
[LINUX:MUSL] TLS=true malloc=true errno=true file=true
[LINUX:BUSYBOX] applet=echo passed=true
[LINUX:BUSYBOX] applet=ls passed=true
[LINUX:BUSYBOX] applet=cat passed=true
[LINUX:SHELL] bytes=12 redirection=true verified=true
[LINUX:SHELL] bytes=5000 redirection=true verified=true
M8-status-1
```

ash 注册自定义 handler 时返回 `[LINUX:ENOSYS] nr=13`，这是已声明限制，不能据此证明 signal handler 工作。未选 applet、ash trap/job control、Ctrl+C、线程、动态 musl、glibc 和编译器仍未验证或未实现。

## 回归结果

- 检查格式和文件用途，宿主/内核/应用 Clippy 拒绝全部 warnings；61 项宿主测试（含 shell parser）通过。
- `cargo xtask verify` 的 13 场景全部满足分类：启动 33，panic/heap OOM 正确分类为 panic，timeout 到达注入点，UD/GP/PF/DF/stack guard/RO/NX/direct-map NX/unmapped 均到真实异常，不忽略失败。
- `cargo xtask terminal-test` 两次普通启动通过。首次经真实 UART 启动 linux-musl 和 `/linux/sh`，执行重定向管道，创建/读取文件，看到 M8-UART 和 native status 0，再检查 EOF 后 shell 重启；第二次确认原 tmpfs 文件重启后不存在。
- `cargo xtask persistence-test` 六个 M7 场景全部通过：编辑保存、重启字节/SHA 比较、重启后 native ELF、干净 e2fsck、只读盘、未知特性及真实 write/flush EIO。要求真实 ACPI 关机，不能仅有 banner。
- CI 已加入 musl/make/QEMU-user 和宿主 trace 收集，本记录不声明远端 Actions 结果。

日志保存在 `build/logs/`。M7 CPU/设备/存储限制不变，本阶段只增加受选静态 CLI 兼容，不是 guest 工具链。
