## 复现与保留证据

在已有 Ubuntu 24.04/WSL 仓库中运行：

```sh
cd /home/ananwanan/projects/AnovaOS
cargo test -p anova-editor --target x86_64-unknown-linux-gnu
cargo test -p anova-abi -p anova-vfs --target x86_64-unknown-linux-gnu
cargo xtask desktop-files-test
cargo xtask desktop-test
cargo xtask desktop-pty-test
cargo fmt --all -- --check
python3 scripts/check_docs.py
cargo xtask check-files
```

`desktop-files-test` 构建普通桌面内核，在 `build/disks/` 创建独立的全新 64 MiB
Linux personality ext4/JBD2 盘，使用单 BSP、3 GiB RAM、800×600 VGA、PS/2，
执行两次普通 QEMU q35/TCG 启动。每次启动独立受 180 秒 watchdog 限制。
本门禁不要求下载或重建编译器。源码由物理输入键入；UART 只用于观察数据和
构造明确的外部修改/事务文件占用故障。

门禁保留 `build/desktop-files-test/result.txt`、各次启动的实际 UART/TCP-QMP
记录与 QEMU 命令、真实 PPM 画面、停机后精确源码副本及其 SHA-256。
失败记录为 `result=Err` 并说明失败操作；缺失或失败的结果不是验收。
输入身份位于 `build/desktop/inputs.txt`，结果同时记录精确 ISO 哈希及磁盘路径。

[保留的最小本地证据](../../assets/validation/M17_FILES_LOCAL.json)包含精确实现
快照/哈希、原始启动记录、真实编辑器/PTY PPM 画面、源码导出、宿主检查输出和
保留的回归观测。每个 `gzip_base64` 先 Base64 解码再 gzip 解压，并验证解压后
`sha256`。该文件保留观测及待验范围，不把最小闭环升级为完整 M17.3 存储故障验收。

## 门禁实现的检查

- 创建目录，通过物理键盘键入并保存 C、C++、Rust 源码。
- 修改 C，取消脏缓冲区关闭；Files 活动期间拒绝启动器停止并忽略会话重启/退出，
  再保存且不丢弃内容。
- 由独立进程占用精确临时兄弟路径；拒绝保存并保留脏状态、旧目标和占用文件
  字节，清理后重试。
- 外部修改同一目标，取消覆盖提示并检查外部字节，再明确确认覆盖和保存。
- 重命名 C、创建/删除临时源码、返回父目录并重新打开。
- 用独立字形/颜色常量检查编辑器实际画面中的源码字形。
- 通过真实图形 Linux-musl PTY 读取三个相同路径，以独立字形/颜色样本检查
  实际画面上的已知源码标记。
- 正常停止桌面、sync、ACPI 关机；独立 e2fsck，并用 debugfs 导出精确源码
  和不可变 Linux ABI 标记逐字节比较。
- 使用同一盘重启，图形重新打开全部源码，再做图形 PTY 读取及第二次正常关机
  后的停机字节比较。

编辑器宿主故障矩阵在每个必要保存阶段注入 `IO_ERROR` 和 `NO_SPACE`，覆盖
部分/完成写入、临时/备份文件 flush、父目录 flush 与 replace。检查失败绝不
假装已保存，旧精确字节仍位于原目标或保留备份。备份清理失败属于成功保存并
明确报告保留副本。原生 ABI 和 VFS 测试分别检查版本/记录/路径、拒绝覆盖的
rename、显式替换和共享持久数据。

## 回归结果与观察器对照

完整 `cargo xtask test-host` 通过，包含既有日志切点矩阵及八个编辑器测试。
严格宿主/原生/内核 Clippy、原生文件 ABI 冒烟、原五启动 `desktop-test`、
启用真实编译器的两启动 `desktop-pty-test`、独立两启动 `terminal-test` 均本地通过。

PTY 门禁暴露两个宿主观察缺陷：COM1 可能在物理 shell 写完前读到刚创建的空文件，
现在先等待实际图形 `REDIRECT-0` 完成标记。每 30 ms 重复抓取 1.4 MB 编译画面
也导致该 WSL 宿主的 35 秒编译观测失败。独立 detached `8a1f4f7` 检出使用未改动
产品代码、原 30 ms 采样，仅加入重定向完成观察修正，同样复现超时。其编译器
构建/安装/打包清单、BusyBox/测试 ELF、源码和包装器输入与当前分支逐字节相同。

现在仅编译完成观察改为每 500 ms 采样；35,000 ms watchdog 不变，并在接受成功
画面前严格检查。全部 5,000 ms 输入/交互检查与其他画面采样频率均不变。
完整门禁中编译完成为 16,113 ms，Ctrl+C、其他客户端输入及独立 UART 分别为
2,497/2,774/61 ms。此次客体构建程序在两次关机后 SHA-256 均为
`f74307b578ca8971a48245124c82d23fa9d985ad34a14ee53fc78e5a8e2a5868`。
这是新运行身份，历史 M17.2 证据保持原样。

证据保留全部三次失败观察、独立基线提交/补丁/结果、全新编译器诊断及其观察器
说明，以及成功的完整门禁。诊断字形匹配器缺少 `G`，曾在实际成功画面下报告
false，该诊断不作为正式通过结果。编译超时与失败观察均未隐藏。

## 验收边界

完整 M17.3 仍需实际 GUI 层文件大小、inode、磁盘满、virtio 写入和 flush
故障验证，以及这些真实设备失败时声明的旧副本保持。宿主模型故障并非实际
设备故障。既有 M16 存储门禁继续适用，但不能替代编辑器端到端证据。
本门禁仅证明正常关机/重启，突然断电未验证。全 GUI C/C++/Rust 编译、编译
并发交互延迟、故障恢复、远端 CI 和实机仍独立处理；Actions 继续仅 main 推送。
