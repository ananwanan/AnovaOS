## 真实 GUI 存储故障验收（2026-10-28）

`cargo xtask desktop-files-fault-test` 已在实现基线 `76e409e` 及保留源码快照上
通过完整 16 用例、43 启动的本地配置。成功运行目录为
`build/desktop-files-fault-test/1793195881857107135/`，准确 ISO SHA-256 为
`b1afcf226d02987f8f72387be997f9a03b949b84ae786cf2cb78e87a72f50f64`。这补齐 M17.3 剩余有界存储故障退出条件，不代表任意断电持久性。

门禁使用普通 q35/TCG、单 BSP、3 GiB RAM、既有桌面资源配额及真实 800×600 画面。
每次启动保持 180 秒 watchdog；打开/保存/关闭、错误及像素观察均受 5,000 ms
预算约束。独立 PTY 编译观察器仍为 500 ms 采样、35,000 ms 截止，交互预算仍为
5,000 ms；Actions 继续仅 main 推送。宿主 QMP 一次发送完整 JSON/CRLF 记录并
启用 `TCP_NODELAY`，UART 文件观察等待完整记录；这些观察器修改不改变按键
采样节奏或任何声明的截止时间。正常重启检查指 ACPI 正常关机后，创建新的
QEMU 进程启动同一磁盘，没有新增客体内 reboot 命令；独立副本的设备错误恢复
另见下文。flush 故障控制最大实测 1,641 ms。
`implementation.json` 绑定 17 个 GUI/编辑器、宿主门禁、QMP、VFS/ext4/virtio
及 CI 源码身份，运行中改变即拒绝；`host-tools.json` 记录本地实际 QEMU 8.2.2
及 e2fsprogs 的版本和二进制身份。

`bounds` 打开恰好 16,384 字节的文件，在干净状态拒绝 16,385 字节文件，分别
拒绝向已满的干净/脏缓冲区继续插入，并在明确选择放弃后仍因超长而打开失败时
保留可用脏缓冲区。检查路径、光标、长度与全缓冲区指纹。后续保存之前即在独立
停机快照核对磁盘精确字节，之后保存、正常关机、独立 e2fsck、图形重开及第二次
正常关机，再核对预期 16,384 字节结果和保持不变的超长文件。

四个独立磁盘通过真实 ext4 分配，分别留下零或一个空闲 inode、4 KiB 数据块。
没有伪造位图/空闲计数，也没有用宿主编辑器 Fs mock 替代。实际 GUI 保存分别在
创建临时/旧副本或写入其数据时遇到 `NO_SPACE`；检查错误文字、脏状态像素、短
缓冲区全部十六进制字节、目标/同级文件精确内容及哈希。独立 COM1 只解除已记录
的压力、删除已检查的事务文件；同一 GUI 缓冲区重试成功，保存后的文件字节通过
正常关机/重启检查。

另外十一个磁盘在挂载后接入全新 QMP blkdebug 过滤器。选定首个写入和 flush
故障经过真实 virtio 设备请求、VFS 及 ext4/JBD2 保存路径，必须出现实际
`BLK:ERROR` 完成状态 1 和原生 `FILES:IO_END` 操作错误；各用例配置及完整
QMP/UART 记录把选定事件绑定到真实保存阶段。这些是代表性的阶段切点，不穷举
每个扇区或每次日志事务；既有 M16 矩阵继续独立保留。

标准 QEMU 可能触发 `flush_to_os`，却因无新写入推进代数而跳过 flush-to-disk
回调。显式且无新写入的文件/父目录 fsync 因此使用真实 blkdebug flush 断点，
异步观察，先安装下个断点再恢复，并通过同一后端重写已有最后 512 字节扇区，
推进 QEMU 写入代数。扇区字节/SHA-256 在重写前、重写后和 FLUSH 错误完成后
分别核对，必须始终相同。原始真实 virtio FLUSH 必须在预期 syscall 返回完成状态 1。辅助操作不改变磁盘
字节，也不替换客体 syscall 返回值；保留标准 QEMU 版本、二进制身份（准确路径/
大小/SHA-256）及辅助源码。
下表同时核对停机与重新挂载后的精确字节：**O** 为 17 字节
`// M17-FAULT-OLD\n`，**N** 为 18 字节 `z// M17-FAULT-OLD\n`；**空文件**
表示存在且为零字节，**不存在** 表示独立确认路径缺失。每个保存错误都在 GUI
保留全部 N 字节；所需保存已成功而清理失败的用例保持干净状态。

| --- | --- | --- | --- | --- |
| `inode-temp`、`temp-create-write` | O | 不存在 | 不存在 | 错误；脏 |
| `blocks-temp`、`temp-data-write` | O | 空文件 | 不存在 | 错误；脏 |
| `inode-backup`、`temp-fsync`、`backup-create-write` | O | N | 不存在 | 错误；脏 |
| `blocks-backup`、`backup-data-write` | O | N | 空文件 | 错误；脏 |

O 的 SHA-256 为 `020ba2984add886f376b3f51deff8875882d606ff1a53900add8c8a4f2fe472e`；N 为 `cfb13e1b4933c384c8c42c760583f757f8e61e9f9f8b5dcf58b0bd5fdb8d88c9`。正常关机和重启后
同时核对不可变 ABI 标记及实际恢复的旧副本。独立只读审计确认预期的十个
关机/重启 `recovered.c` 转储全部存在且精确等于 O，十个失败/重挂载镜像尾扇区
等于记录的原始 512 字节，17 个实现哈希均匹配；计数恰好 43 次启动命令和
32 条干净 `POWER:OFF`。十一次初始故障会话仅在错误完成后结束。不假定每个
失败阶段都创建两个同级文件，详见 `independent-audit.json`。

解除外部设备故障后，同一次挂载仍处于故障封闭状态，重试继续报错，并保持
已观察到的缓冲区及此前脏/干净状态。门禁记录该结果，仅在错误已经完成后终止 QEMU，保留原始失败
镜像，再在独立副本上普通启动/挂载恢复。重新核对命名空间字节，若存在完整备份
则复制到 `/persist/recovered.c`，必要时明确重新输入待保存字节，再通过图形编辑器
重试。随后正常关机、独立 e2fsck、重启、重开并核对字节。这些选定故障不证明
每次启动都重放了正在提交的事务。报告错误之后终止并非保存期间断电，也不声称
未保存编辑器缓冲区具备崩溃恢复能力。

真实清理切点发现了一项产品交互缺陷：所需保存操作已成功，模型正确标为干净，
但失败挂载上的多余目录刷新把明确的保存/清理错误提示覆盖为通用存储错误。
客户端现保留成功结果，清理失败后跳过该刷新，并记录 `backup_cleanup_failed=true`。
提示要求检查存储，因为清理的晚期错误可能发生于备份已删除之后。两个真实清理
用例同时验证已保存像素、干净状态和对应阶段的同级文件精确字节。


分配计数/审计、故障配置/QMP 规则、UART/QMP 和 QEMU 命令、真实 PPM 与像素检查、
原始失败/快照镜像、普通恢复策略、精确源码/事务转储及 SHA-256。非零工具退出、意外读取诊断
或缺失预期转储均被拒绝；失败观察保持 `result=Err`，不能计为通过。新的
[保留故障证据](../../assets/validation/M17_FILES_FAULT_LOCAL.json) 包含验证过的
gzip/Base64 记录、源码快照及普通镜像哈希；镜像本身仍保留在 `build/` 的普通文件中。

以下早期观察解释修正原因，全部尝试继续保留：单独边界运行 `1793193272043999794` 通过；
`1793193407864450080` 已完成精确 inode 重试，但独立观察器缺少 `SAVED` 的 V，
修复只涉及观察器。`1793193593955143449` 通过边界及两个 inode 用例，随后在
宿主 QMP 问候阶段遇到 EAGAIN，QMP 为空且 UART 只有固件字节。
校准运行 `1793193904570343583` 为必要发布后同步配置 flush 40，但标准 QEMU
跳过无新写入的回调，使实际错误延迟到清理，因而暴露上述产品提示缺陷。flush 34
偏移探针也因命中替换而未通过严格阶段检查。追踪探针 `1793194311489307819` 因
UART 打开记录尚未完整而停止，观察器现等待完整行；`1793195179046512756`
暴露同步 HMP wait-break 死锁，现异步观察实际 QEMU 挂起。首次完整尝试
`1793195466515108038` 通过边界和四个压力用例后，QMP 拒绝空 `set-state`
配置；没有状态转换时，辅助代码现省略此可选属性。已证明的独立临时文件
fsync 运行 `1793195368622412021` 完成三次启动，实际 fsync/virtio 错误及尾扇区
一致性控制耗时 806 ms，未扩大保存/控制预算。最终故障阶段以实际操作和事务文件
检查绑定，不能仅从事件序号推断。所有失败、后续独立检查及完整成功矩阵一起
保留，没有把超时或失败结果改写为通过。

## 门禁实现的检查

- 创建目录，通过物理键盘键入并保存 C、C++、Rust 源码。
- 修改 C，取消脏缓冲区关闭；Files 活动期间拒绝启动器停止并忽略会话重启/退出，
  再保存且不丢弃内容。
- 由独立进程占用精确临时兄弟路径；拒绝保存并保留脏状态、旧目标和占用文件
  字节，清理后重试。
- 外部修改同一目标，取消覆盖提示并检查外部字节，再明确确认覆盖和保存。
- 重命名 C、创建/删除临时源码、返回父目录并重新打开。
- 用独立字形/颜色常量检查编辑器实际画面中的源码字形。
- 通过真实图形 Linux-musl PTY 读取三个相同路径，以独立字形/颜色样本检查
  实际画面上的已知源码标记。
- 正常停止桌面、sync、ACPI 关机；独立 e2fsck，并用 debugfs 导出精确源码
  和不可变 Linux ABI 标记逐字节比较。
- 使用同一盘重启，图形重新打开全部源码，再做图形 PTY 读取及第二次正常关机
  后的停机字节比较。

编辑器宿主故障矩阵在每个必要保存阶段注入 `IO_ERROR` 和 `NO_SPACE`，覆盖
部分/完成写入、临时/备份文件 flush、父目录 flush 与 replace。检查失败绝不
假装已保存，旧精确字节仍位于原目标或保留备份。备份清理失败属于成功保存并
明确报告清理错误；真实设备也可能在副本已经删除后才返回错误。原生 ABI 和
VFS 测试分别检查版本/记录/路径、拒绝覆盖的
rename、显式替换和共享持久数据。

## 回归结果与观察器对照

完整 `cargo xtask test-host` 通过，包含既有日志切点矩阵及八个编辑器测试。
严格宿主/原生/内核 Clippy、原生文件 ABI 冒烟、原五启动 `desktop-test`、
