# M18.4：分组件的重复与恢复证据

[English](../../en/validation/M18.4.md) | **简体中文**

## 基础光盘镜像路线

两块独立新建 JBD2 ext4 工作盘生成逐字节相同的 25,620,480 字节 ISO，SHA-256 为
`9ee587c3725309a63ad21b7c96057d1eaa3db8fce49afdbc4ae1a0bc3cd08a7b`。两轮使用同一个受检
guest 内核，及经过检查的引导、应用和 initramfs 输入。独立宿主提取验证 19 个普通文件路径
及内容；两个最终镜像均实际启动并匹配保留内核身份。对比覆盖相同输入下的镜像产物，独立内核
构建证据见 [M15.6](M15.6.md) 及 [M16 容量](M16_CAPACITY.md)。

报告分开记录构建、重启、发布拒绝、取消及压力。压力运行达到 16,384 分配块，并以 `ENOSPC`
拒绝写入；下一次启动使用旧 ISO，保留精确用户内容，释放预留空间，并验证新写入能复用所释放
的容量。21 ms COM1 观测对应实际取消。全部六次会话、原始日志、预算、证据相对路径和输入来源
见 [M18.3](M18.3.md)。

## 编译器路线

独立 LLVM 配置在两块干净工作盘编译、归档并链接同样的六个上游翻译单元，归档和测试可执行
文件精确匹配，SHA-256 分别为 `115729861d9765babf31151e3266946e04d8d743c4fc79814c88dd7ed32371d2`
和 `d7de9798b1b32a14e06ee731f93857fd9587a056e33680ddc4e03dcf4d1e86b5`。两次重启均在真实语法
及缺库链接失败后保留原归档、可执行文件和工作区字节，并使用保留归档重新链接得到逐字节相同的
可执行文件。[LLVM 运行](M18.2.md)保留依赖、测量及原始诊断。LLVM 的取消、资源耗尽与发布
失败仍需各自的组件测试。

[GCC 前置配置](M18.1.md)有独立证据。完整 GCC、rustc、Cargo、LLVM 后端、带 GUI 内核及
多阶段编译器的重复/恢复仍待完成。
