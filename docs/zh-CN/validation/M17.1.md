## 实现范围

- Rust `/bin/desktop` 管理一个合成器与三个已有、独立实现的 C/C++/Rust GUI 参考客户端。
  第四个连接/窗口归启动器使用。既有 GUI C ABI 和 native v1 记录保持不变。
- `init` 独立启动 COM1 shell，并等待任一子进程。shell 退出只重启 shell；
  桌面退出后串口恢复入口继续可用。默认启动方式不变。
- 启动器按钮或 `1`、`2`、`3` 启动/停止对应准入客户端；焦点和拖动沿用合成器。
  `r` 替换会话，`q` 退出；使用快捷键前先聚焦启动器。
  Stop 是立即以信号 15 终止，并非未保存提示或应用配合的正常关闭。
- 普通会话替换/退出会停止并回收自己管理的客户端和合成器，客户端退出报告真实原因/代码。
  合成器丢失会请求新会话；自动与手动重启共享进程生命周期内最多三次替换的限制。
  创建、绘制/呈现或轮询期间断连均进入同一重启路径。
  不修改持久文件；客户端缓冲区和 surface 重新创建，不自动恢复。
- 桌面布局根据可见矩形选择位置，忽略隐藏的 ABI 契约测试窗口。
  仍为四客户端/窗口，最大私有 surface 为 320×240。

## 进程边界

`crates/abi/src/process.rs` 定义独立实验系统调用 `0x101`。
RDI 为 `(version << 32) | operation`，RSI 为精确非零 PID；
POLL 的 RDX 为 16 字节 native `WaitStatus` 输出地址，STOP 则要求为零，版本为 1。
只允许操作调用者的直接子进程，PID 不复用；路径不会授予显示/输入权限。
Linux 调用者继续进入原有 Linux 分派器。

POLL 在原生子进程仍存活时返回 WOULD_BLOCK，不阻塞父进程；
退出后先复制状态再回收，非法输出地址保留 zombie。
STOP 对仍存在的 zombie 幂等，否则以信号 15 终止直接原生子进程。
存活的 Linux 子进程返回 UNSUPPORTED；已退出子进程沿用原生父进程既有 wait 状态语义。
同级、父级、间接后代和陈旧 PID 返回 NO_CHILD。
该接口不是全局任务观察器，也不会终止整棵进程树。

## 构建与启动

```sh
cargo xtask desktop-build
cargo xtask fetch
cargo xtask desktop-image
cargo xtask desktop-test
cargo xtask run --desktop
# 显式复用 native personality 工作盘：
cargo xtask run --desktop --disk build/disks/work.ext4
```

`desktop-build` 构建原生用户态、未修改的三语言 GUI 客户端和经检查的归档，
不下载 GCC/Rust Linux 种子配置。归档额外显式准入 Linux personality 的
`/linux/desktop-park`，通过真实 nanosleep/exit 验证存活子进程拒绝边界，
它不是 shell 或编译器。GUI 客户端由**宿主构建**，不构成新的 guest 编译证据。
产物和哈希位于 `build/desktop/`，镜像为 `build/images/anova-desktop.iso`。
`run --desktop` 只接受可选磁盘，使用 q35/TCG、单 BSP、3 GiB RAM、
800×600 标准 VGA/PS2 和 COM1；默认仍使用临时 ext2 盘。
显式桌面内核也准入已有的受控 ext4/JBD2 可写配置。

已验收的稳定会话包含七个进程：init、shell、监督器、合成器及三个客户端。
上限仍为 16 MiB 堆、32 任务槽、每进程 32 FD、128 打开对象、2,048 VFS 节点和四个私有窗口。
下述实测覆盖会话操作与主动施压，不构成编译器并行运行验收。

## 本地 QEMU 验收

`cargo xtask desktop-test` 已通过五次 q35/TCG 正常关机启动，使用 QEMU 8.2.2、
Rust 1.90.0 与 e2fsprogs 1.47.0。验收实现接续 `43121e9`；
[保留证据](../../assets/validation/M17_DESKTOP_LOCAL.json) 保存精确源码哈希、客户端/ISO 身份、
完整 UART/QMP 记录及压缩的原始 PPM。三个客户端的实际画面保存在其中的 `screenshots.three-clients.ppm`，
与另外五个压缩截图一起保留，均来自真实 QMP 屏幕捕获。远端 CI 与实机尚未验证。

1. 新建 64 MiB ext4/JBD2 工作盘：独立 C/C++/Rust 契约、三个同时可见窗口、物理键鼠输入、
   焦点、拖动、客户端自然关闭及启动器重开均通过。启动器和三个客户端占满四连接配额时，
   第五个连接被拒绝。既有三语言契约与原始客户端探针验证单 surface 配额、陈旧句柄和外来所有权。
2. 独立 COM1 shell 执行 `desktop check`：存活非阻塞等待、实际信号 15 停止、错误复制保留状态、
   回收、陈旧/非子进程拒绝、存活 Linux 进程拒绝及真实任务/FD 耗尽恢复均通过。
   七个桌面任务运行时，检查进程还能占满 24 个槽；会话退出后，新检查进程能占满 29 个槽。
   两次检查均额外打开并释放 29 个 FD。
3. 一个受监督原始客户端实际执行 UD2，以原因 1/向量 6 回收，另一客户端继续接收物理输入。
   专用测试会话的 F12 让实际合成器执行 UD2。监督器回收全部自有子进程，以新的 session 身份
   启动合成器并连接新客户端；新的 C 客户端实际接收输入并绘制预期文字。
   一次自动加两次手动替换用尽共同限额，下一次请求返回 BUSY，COM1 继续可用。
4. 普通桌面 ISO 重启同一 ext4 工作盘，重新打开精确保存内容并正常退出；独立普通 ISO/ext2 启动
   验证旧配置及保存内容。无显示和禁用 i8042 的普通启动保留 COM1 与文件。
   每次启动均独立重启串口 shell，实际完成 QEMU/ACPI 正常关机；所有停止后的磁盘通过 `e2fsck -fn`。

## 发现并修复的故障

首次完整图形场景发现真实竞态：启动器绘制期间合成器死亡被转换为 IO_ERROR，导致桌面直接停止。
现已把创建、绘制/呈现及轮询中的 Disconnected 保留为重启请求，遵循同一有界清理/替换策略。
原始故障串口及后续成功的五启动记录均保存在 JSON 证据中。

宿主最初缺少运行工具。本轮将已校验的 Rust 与 Ubuntu snapshot 包解压到隔离构建工具目录，
未使用此前不完整的 QEMU 包。补齐 QEMU 模块/ROM 路径及迁移后的 musl 共享 libc，没有放宽哈希。
环境拒绝 Unix socket 连接，因此新门禁使用临时、**仅绑定 127.0.0.1 的 TCP QMP 端点**，
沿用相同的有界事务/错误检查；既有 Unix QMP 调用方继续受支持。

已执行：原生 `desktop-build` 及 ELF/归档准入，ABI/调度器/GUI/运行时宿主测试，
xtask 测试，严格宿主/原生/桌面内核 Clippy 及格式检查。

环境缺少 QEMU/xorriso，配置的 Ubuntu 软件包源返回 HTTP 503，官方 archive 连接超时；
锁定固件主源返回 503，官方备用源成功，既有 Limine/OVMF 哈希全部验证通过。没有放宽输入身份和校验要求。

实际执行 `cargo xtask desktop-image` 已完成原生输入、固件检查和桌面内核链接/校验，随后因缺少 `xorriso` 而失败（`No such file or directory`，退出码 1），不接受任何 ISO 或启动结果。官方保留包重试仅得到不完整的 QEMU 下载，未执行，也未视为校验通过。
