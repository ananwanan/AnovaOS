# M12：Rust 与 Cargo 本地验证

[English](../../en/validation/M12.md) | **简体中文**


截至 **2026-10-23（Asia/Shanghai）**，R1–R6 已在有界离线和联网范围内通过本地验收。公网获取使用记录的宿主代理和公开 PEM 根证书，未证明直接公网 DNS/传输。远端 CI、AnovaOS 原生 std 和编译器自举仍是独立成果。

本页按时间保留早期范围、失败和未完成检查点，不能将中间“未验收”当成最终状态，也不能用最终成功擦除失败证据。当前结论以末尾的联网完成记录为准，当前开发进度见 [STATUS](../guides/STATUS.md)。

## 初始离线验收：2026-10-22

基线为 dev 的 `7ce53fe`，分支 `feat/m12-rust-cargo`。环境为 Rust1.90.0、QEMU8.2.2、锁定 Limine/OVMF、q35/TCG 和单 BSP；Rust 镜像使用 3 GiB RAM，普通镜像保留独立配置。

锁定的 M11 GCC/G++11.2.0、binutils2.37、make4.4.1、musl1.2.4 重新从源码构建并验证完整库存。musl 主地址返回 HTTP403 后，Buildroot 镜像提供相同锁定摘要的源码。宿主工具来自验证后的 Ubuntu 软件包，使用 CARGO_INCREMENTAL=0 和全新输出验证。

rustc、Cargo、匹配 musl std、LLVM/rust-lld 来自官方 2025-09-18 二进制分发，验证归档、安装文件和最终归档库存；这证明执行与应用编译，不代表 Rust/LLVM 源码构建。实际版本为 `rustc 1.90.0 (1159e78c4 2025-09-14)`、`cargo 1.90.0 (840b83a10 2025-07-30)`。保留 LICENSE/COPYRIGHT、Cargo 第三方归属，以及无 `/tc` 时也需要的 GCC 展开库 COPYING3/COPYING.RUNTIME，来源见 [配置](../../../ports/rust/inputs.json) 和 [第三方记录](../third-party/m12.md)。

前置交叉编译样例只用于独立门禁。正式应用均由客户系统编译器生成：R1 经 UART 编辑 Rust，验证 Vec/String、文件、真实线程和工作线程等待子进程；R2 无依赖离线 Cargo 返回 42；R3 使用真实 itoa1.0.15 和归档/文件校验、锁文件、源替换，初次 42，改源码后 43；R4 构建脚本生成 OUT_DIR 与环境，执行客户系统 GCC/ar 并链接返回 84 的真实 C；R5 构建过程宏共享库，由匹配 rustc 装载展开为 42。真实语法错误返回 1 且旧应用仍能运行，干净重启后源码与五个 ELF 字节不变，四个保存应用继续执行。

初始会话没有 NIC，使用 --offline --frozen。当时 R6 尚未接受，原生 std 和编译器自举未实现；独立过程宏不代表任意 Cargo 宏依赖图。实际 Compiling 记录为 m12-plain 一次、itoa 一次、m12-app 两次；中间无改动构建不重编，源码修改只把运行值 42 改成 43，构建脚本输入仍为 42、C 结果仍为 84。

## 运行时与最初证据

rust-cross-test 验证备用信号栈和 SA_ONSTACK、处理期间改栈拒绝、过小和错误指针；分离线程解除自身栈后退出，非法可执行返回即使 SIGSEGV 被屏蔽或忽略也终止子进程。还验证 200 字节 ext2 名称，拒绝 256 字节分量及 513 字节路径，并保持原生目录记录和游标不变。

文件与 IPC 检查包含 O_NOFOLLOW、dirfd 相对删除、空目录删除和已打开目录身份、忙 cwd 与 inode 复用；双向 SEQPACKET、截断、原子反压、坏指针不出队、零长消息、EOF；替换后已打开文件、pread/pwrite 偏移、截断与清零增长、模式位和 OFD flock。原内存所有权、W^X、CPU/FPU、OOM、终端、存储、网络包 TLS 和 C/C++ 门禁保持通过。

没有新增目录事务日志、断电恢复、SMP 或通用 Linux/glibc。POSIX fcntl 记录锁不支持，Cargo 缓存最后使用时间警告非致命，与冻结 vendor 构建独立；可选时间戳或加速复制探测返回真实错误，复制仍通过实际文件 I/O 完成，flock 另行实现。

初次完整验证通过 81 项宿主测试和 211 文件用途覆盖，以及格式、严格 Clippy、原 OS/工具链门禁。磁盘为 `build/disks/rust-1792661571469480982.ext2`，两次 e2fsck 返回 0，102/128 文件、1168/4096 块，两次均干净关机和 DMA 重置确认。最初 18 个持久文件摘要、归档及逐文件表保留下方；重启后均不变。日志在 build/logs，工具库存位于 build/rust，没有远端 CI 结果声明。

后续 `feat/m12-validation` 增加 std::fs::copy 的字节数和内容断言，交叉门禁完成四次交互并干净关机；81 项宿主测试、格式、用途和严格检查通过。原 18 摘要属于更早完整运行，不冒称覆盖此新增断言；当时“下一步 M13”仅是历史说明。

## Cargo 宏依赖图与完整回归：2026-10-22

基线 `6d623b3`，分支 `feat/m12-validation`。新环境没有先前未提交工作区，因此直接重建记录中的宏场景并验证源码。锁定工具重新准备，仍为单 BSP、无网络。

m12-macro 的普通和构建依赖共用 m12-macro-support，构建脚本生成宏使用的源码和环境；宿主依赖 rlib 使用 PIC，应用仍静态。最初 128 inode 磁盘在生成 itoa 临时归档时真实 ENOSPC，Cargo 返回 101。Linux 开发盘改为 512 inode，成功运行使用 146 个，证明 128 不足；16 MiB 大小、128 字节 inode、原生几何和当时 1 MiB 文件上限不改。

工具在独立暂存位置 strip 后复制到候选系统根目录。准备重试暴露同目录的临时 ELF 文件；先验证正常安装摘要，再清理生成文件并重建库存。完整库存与 ELF 验证随后通过，未排除隐藏文件或弱化完整性检查。

首次启动完成 155 步交互，宏结果 42→修改支持库后 84，支持库、宏和应用必须重新编译。非法宏输入产生真实 `error: m12-macro expects no tokens` 和 Cargo101，旧应用仍输出 84，修复后成功。独立 rustc 语法错误仍返回 1 并保留旧程序。编译计数为 itoa1、plain1、support2、macro2、app5。

第二次启动六步交互运行四个保存应用，23 个源码与 ELF 摘要不变。两次 e2fsck 均为 0，146/512 文件、1544/4096 块，磁盘 `build/disks/rust-1792678601469597775.ext2`。库存和归档完整摘要见标识；回归日志在 `build/logs/m12-regressions/`。联网、原生 std 和自举在这一时间点仍独立。

## 联网检查点与保留失败

最初检查点保留受控、公网运行器、CA 输入和运行时修改，**当时没有成功联网会话**。83 项宿主测试、用途、格式、Python/JSON、差异检查、改动目标严格检查通过，交叉门禁已验证 select/EINTR、共享文件所有权/OOM 和时间戳，但不代替该源码检查点完整回归。

此前虽下载 registry 归档，解压因缺时间戳调用返回 Cargo101；接口补齐后尚未完成重试，当时没有完整 online/public 结果。获取、编译、传输负例、无网缓存重建和保存摘要仍待验收。

2026-10-23 后续补充 UART 编辑器遇错停止、实际超时诊断、冷缓存离线获取负例、重启后全新目标目录，并将 ext2 深目录导入改为节点上限内迭代，取代八层限制。83 项宿主测试、228 文件用途覆盖和严格检查通过，但该提交环境缺 QEMU、musl-gcc、xorriso，没有新增客户系统或完整回归结果，因此仍未验收。

随后装备齐全的环境中，受控门禁完成首次 515 次、重启五次交互；第二次无对端或 NIC，仅用保存缓存重新编译。49 文件摘要和两次文件系统检查成功，旧盘为 `build/disks/rust-online-1792684976558957700.ext2`，真实 CA、名称、过期、校验、截断下载和应用超时均观察到。运行器之后拆分首次与完整结果、启动前作废旧成功，因此该修改仍需完整重试。

公网门禁一度完成获取和客户系统执行，但宿主断言预期了上游没有的模块声明而失败；修正为检查实际 `pub struct Buffer {` 并分别验证两个格式化值 42，完整重启仍待重试。中间矩阵通过 83 宿主测试、格式、228 用途、严格检查、13 场景、终端、存储、网络包、追踪、交叉和独立运行时；离线 Cargo/C++ 及新增只读写入故障断言尚待，因此该时点 R6 没有完整验收。

## 联网最终完成：2026-10-23

基线 `e60e4e9`、分支 `feat/m12-validation`。最终完整重试接受 [M12 网络](../milestones/M12_NETWORK.md) 中的 R6，早期失败日志仍保留。工具仍是未修改官方 Cargo/rustc1.90.0。Mozilla CA 集锁定 2026-10-20 及 SHA-256，MPL-2.0 notice 独立锁定，无秘密或生成服务端私钥进入镜像。

受控对端提供 m12-net-dep0.1.0 和完整 Git 提交，初始缓存无源；对端只传数据，客户系统执行下载、解压、解析和编译，全程验证 TLS。公网使用真实 crates.io itoa1.0.15 及 GitHub dtolnay/itoa 固定提交，无 vendor 替换。该宿主需要 HTTP 代理，仅向测试镜像配置可达地址和公开根；代理不终止 TLS、不编译应用，因此证明经代理获取公网 HTTPS，未证明直接 DNS/传输。

最终受控盘为 `build/disks/rust-online-1792686417501023999.ext2`，公网盘为 `build/disks/rust-public-1792686676390887769.ext2`。完整结果与首次启动结果分文件；每次先写 result=Running，两个启动、源码检查和文件系统检查都完成后才发布 result=Ok。完整门禁、失败原因、修复、重建、库存及摘要表保留下方。

`build/logs/m12-online-regressions/results.json` 的 26 命令全部退出 0，覆盖格式、228 文件用途、83 宿主测试、严格检查、构建/doctor、13 QEMU 场景、终端、真实磁盘错误、网络包、追踪、交叉、独立 Rust、完整离线 Cargo 和 C/C++。后两项分别 598.27 秒、69.21 秒，并包含独立重启。

最终重试矩阵 `build/logs/m12-final-gates/results.json` 另通过最新只读映射故障、两个完整联网门禁及严格检查，恢复标准 Rust/C 镜像并验证两种工具库存。受控门禁加入 CI，但本地记录不声称远端执行。
