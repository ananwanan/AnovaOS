# M18.3：guest 启动镜像构建证据

[English](../../en/validation/M18.3.md) | **简体中文**

有界 UEFI 光盘 profile 于 2026-11-21 13:03:14 至 13:09:50（Asia/Shanghai）通过六次 QEMU
启动。两块独立干净 JBD2 工作盘生成的最终镜像逐字节相同，两份镜像均启动先前实际在 guest
内构建的内核并运行原生 COM1 工作流。[镜像契约](../milestones/M18_BOOTSTRAP.md#在-guest-内构建启动镜像)
描述格式，以及 GUI 内核和编译器源码重建各自的验收边界。

## 输入、命令与预算

使用 `cargo xtask m18-image-test REPORT GUEST_ELF`，输入已验收的容量记录及其保留内核。
需要生成新输入时运行 `cargo xtask foundation-capacity-test`。本次使用历史
[M17 容量重放](M17.5.md#相关回归)，核对重放凭据、原始内核构建与恢复的 UART 日志，以及停止的
ext4 工作盘中的内核精确字节。431,488 字节 ELF 的 target 是 `x86_64-unknown-none`，feature
为 `ext4-write,bootstrap-metrics`。其原始 guest 构建继承 Rust/Cargo/rust-lld 1.90.0 及匹配的
目标库。

宿主构建静态 musl 镜像构建器、原生应用及基础 `anova.initramfs.v1`，并准备独立的初始种子镜像。
Guest 构建器读取 19 个普通输入文件，共 25,544,624 字节。最大文件为 12,261,097 字节的 initramfs。
Limine 9.5.0 UEFI 可执行文件、EFI CD 映像和许可证遵循[引导锁](../../../boot/dependencies.toml)。
Guest 写入含 Rock Ridge 文件名和 UEFI El Torito 条目的 ECMA-119 光盘镜像。宿主 xorriso
以只读方式独立提取，并逐字节比较全部输入，包括 `/boot/kernel.elf`。
[ECMA-119](https://ecma-international.org/publications-and-standards/standards/ecma-119/)、
[UEFI 2.10 光盘引导](https://uefi.org/specs/UEFI/2.10/13_Protocols_Media_Access.html#iso-9660-and-el-torito)、
[El Torito 1.0](https://www.scs.stanford.edu/nyu/04fa/lab/boot-cdrom.pdf)。

预先声明 q35/TCG、OVMF、256 MiB RAM、单 BSP 和无网络。两块干净工作盘均为 64 MiB JBD2 ext4，
采用 4 KiB 块及 4,096 个 inode。构建器限制每个输入 16 MiB、每份镜像 32 MiB，流式缓冲为 4 KiB。
除现有 16 MiB 内核堆、2,048 个 VFS 槽、32 个占用任务槽及每进程 32 个 FD 外，还约束新增物理帧
为 32,768 个 4 KiB 帧、每次构建或压力启动 600 秒、每次最终镜像启动 90 秒，COM1 取消响应
观测上限为 5,000 ms。

## 独立宿主检查

`python3 ports/bootstrap/test_image_build.py` 在 WSL 通过 6 项测试。宿主构建的静态 musl
构建器使用合成输入生成两份相同镜像。
`xorriso` 独立提取精确文件并报告 UEFI El Torito 条目。测试检查引导目录校验和及引导映像
精确字节，并实际触发输入缺失/符号链接/特殊文件/超限、候选冲突及清理、目录阻止发布、
输出上限失败和输出与输入别名。合成 ELF 属于此宿主夹具。单独的预检还拒绝了与容量报告
不匹配的真实 guest ELF。

## Guest 会话与恢复

第一轮实际触发输入缺失的 `ENOENT`、完整流式写入后的重命名 `EISDIR`，以及对正在写入的任务
发送 Ctrl+C 后的信号 2/状态 130。随后显式清理遗留候选，COM1 在 21 ms 后返回提示符。
两次独立的最终镜像启动均报告精确嵌入身份，读取持久化用户字节，运行原生 C 应用得到退出码 7，
并完成干净关机。两份 ISO 提取树均与全部输入逐字节相同。

压力用例复制停止后的第一块工作盘，宿主放入 31,752,192 字节占位文件，留下 64 个可用块。
随后 guest 镜像流写入在已分配 16,384 块时触发真实 `ENOSPC` 并清除失败候选。停止后独立
确认旧镜像和用户数据字节保留。再次启动旧镜像后读取相同用户字节，删除占位文件并成功分配新文件，
恢复后的已分配块数为 8,569。六次会话停止后均通过独立 `e2fsck -f -n`。
