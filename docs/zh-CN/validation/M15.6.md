# M15.6 本地重复重建验收

[English](../../en/validation/M15.6.md) | **简体中文**

记录于 2026-10-24（Asia/Shanghai），任务分支 `feat/m15-bootstrap`，实现基线 `55e3751` 加清单所记本地变更。`cargo xtask bootstrap-repeat-test` 退出 0，`result=Ok`。[重复重建契约](../milestones/M15_REPEAT.md) 在以下范围通过本地验收：两次独立干净的 bzip2 构建、两次独立干净的内核构建、声明的十一项 bzip2 输出和最终内核 ELF 比较，以及各组件的功能、编译失败和重启恢复。内核中间文件并非全部字节相同。本记录保存历史证据，最新进度见[当前状态](../guides/STATUS.md)。

## 实际执行与保留证据

两轮中各顺序执行完整 `bootstrap-test` 和 `bootstrap-kernel-test`。十二次 QEMU 8.2.2 q35/TCG 会话全部成功，单 CPU、无 NIC；bzip2 使用 1 GiB RAM，内核使用 3 GiB。每次均正常 ACPI 关机、成功刷盘并确认 DMA 重置，停机磁盘均通过只读 `e2fsck -f -n`。

汇总结果为 `build/logs/bootstrap-repeat.result.json`，调用日志为 `build/logs/m15-repeat-invocation.log`，独立证据目录为 `build/bootstrap-repeat/1792852979158547458/`。各 `round-{1,2}/bzip2/` 和 `round-{1,2}/kernel/` 分别保存组件结果、准备/输入清单、initramfs、调用和完整串口/编译日志、停机工作盘、ISO 副本、提取的声明输出和 SHA-256 清单。内核另存 `kernel.readelf.txt` 的头、节、段和 note 列表；整个运行保存准确源码快照、`source-files.json`、`environment.json` 和 `comparison.json`。

四个组件报告均为 `clean_build=true`。每个 bzip2 初盘恰有 26 份源码/配方/测试文件，没有对象或可执行文件；每个内核初盘没有持久内核工作区或 Cargo 目标。检查了不同工作盘路径，没有复用前轮目录。汇总宿主墙钟为 2,315,907 ms，包括准备、编译、启动、关机和归档。

## 功能与失败恢复

两次 bzip2 均由 guest GCC 编译八个 C 单元、链接工具，并执行压缩、解压和流完整性检查。block-size-1 输出等于官方 golden 测试样例，宿主 Python 独立解码也等于参考。非法输入返回 2。重启后真实 C 编译器到达刻意的 `#error`，make 返回 2，旧压缩器仍可运行。每轮 37 个持久源码/输出文件在失败和重启前后哈希不变，两轮完整 bzip2 文件映射亦相同。

两次内核构建均在 guest 中使用实际 Cargo/rustc/rust-lld 处理锁定源码。宿主保留 ELF 并通过不重新构建宿主内核的路径打包；独立提取每个 ISO 的内核，启动前必须准确匹配该轮 ELF。新内核和恢复启动报告预期身份并执行原生应用。真实 Rust 语法错误返回编译器状态 1，不留下未发布 candidate，旧可启动内核保持不变。每轮的 181 文件恢复工作区在最后一次独立重启前后不变。

容量探针还验证真实 `EFBIG`、`EMFILE`、`EAGAIN` 拒绝后的文件、描述符和子任务槽复用。刻意耗尽的最大值与普通构建观察分开报告。

## 元数据及中间产物差异

比较保留所有差异。新磁盘路径、ISO 哈希、宿主墙钟、调度采样和编译时间在两轮间变化。bzip2 准备差异为 ISO 哈希及磁盘路径，内核为种子 ISO 哈希及磁盘路径；内核构建身份和 initramfs 字节不变。guest ISO 分别为 `ec047c57664f7b47f2b74b9250a52f80cfde6b914a62fb399303b22cbd7c8b0d` 和 `703afb890cfc693e554dcd933257e799e2c1c91b5f043e968296d9cc80de9d0e`，提取的内核完全相同。本验收不声明 ISO/磁盘可重现；只读主卷检查确认 ISO 创建和修改时间不同，描述符留在诊断报告中，这些差异不改变声明的 ELF 输出。

两个内核恢复清单有十个文件不同：`build.log`、`target/.rustc_info.json`、anova-abi/kernel/memory/platform/vfs 的五个 Cargo 依赖指纹、smoltcp 生成的 `out/config.rs` 及其 `.rlib`/`.rmeta`。原始哈希保留在 `comparison.json` 和停机工作盘；只读 debugfs 分析存于 `build/logs/m15-repeat-workspace-analysis.json`，含哈希、字节偏移和相关生成内容。

Rust 编译器 info 解析后的 JSON 相等但键顺序不同；smoltcp 配置的常量行相同但顺序不同，锁定上游构建 script 使用 HashMap 并直接迭代生成常量。中间库/metadata 也不同，但尚无完整二进制因果诊断；五个依赖指纹的差异原因同样未由本验收确立。两份完整构建日志都保留非致命 Cargo global-cache advisory-lock 警告和不同耗时（7m23s、7m32s），仍退出 0 并通过显式产物/运行检查，不接受通用缓存锁和清理功能。

因此验收覆盖十一项 bzip2 输出、最终内核 ELF、功能及恢复，不声明每个内核中间文件、工作区字节、日志、文件系统镜像或 ISO 相同。

## 宿主检查与剩余范围

`cargo xtask test-host` 通过 200 项，日志为 `build/logs/m15-repeat-final-host.log`。bzip2/GCC/Rust/kernel 源码拒绝测试分别 3/6/10/9 项通过；严格 xtask 和 bootstrap-metrics 内核 Clippy、格式、用途清单、本地链接和 diff 检查通过。这些检查不替代上述十二次真实 guest 会话。最终独立检查还将全部 106 个保留的组件文件哈希与各 `inventory.json` 核对。CI 配置运行汇总并上传证据，guest-toolchain 超时为 120 分钟，此配置尚未通过远端运行验证。

宿主仍准备锁定源码和继承种子、编译初始内核/应用/诊断、创建工作盘、打包镜像、提取 guest 输出并驱动独立验证；guest 只构建声明的 bzip2 和最终内核。本门禁不解除或重评 M15.3/M15.4 的编译器源码阻塞，也没有重建 GCC/LLVM/rustc/Cargo。guest 内完整镜像生成、GUI-enabled 内核、原生硬件和通用可重现性仍未验证。Rust 失败样例为小型非法源码，不是完整失败内核 Cargo 构建；正常关机恢复不证明无日志 ext2 断电恢复。两个最终产物匹配仅证明记录的输入/环境比较，不代表独立于继承种子或从纯源码自举。远端 CI 和发布未由本地验收验证。
