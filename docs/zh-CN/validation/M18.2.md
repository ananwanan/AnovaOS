# M18.2：LLVM、rustc 和 Cargo 组件证据

[English](../../en/validation/M18.2.md) | **简体中文**

独立的 LLVM 20.1.8 `LLVMDemangle` 库于 2026-11-21（Asia/Shanghai）通过本地
guest 重建、重复构建和重启验证。运行基于 `a2a16a6` 的 `feat/m18-bootstrap`，
实际实现身份见保留报告。[M15.4 可行性记录](M15.4.md) 继续独立保留。

## Guest 重建与重复构建

`cargo xtask m18-llvm-test` 在 QEMU 8.2.2 q35/TCG 上完成四次启动，使用
OVMF、3 GiB 内存、单 BSP，关闭网卡。宿主根据[源码锁](../../../ports/bootstrap/rust-inputs.json)
校验 272,348,992 字节的 Rust 1.90.0 发行版源码归档。源码准备独立比较了 Rust
发行版固定 LLVM fork 的全部 16 个选定文件的 SHA-256，包含未改动的 LLVM 许可证。
选定源码、输入清单和三个第一方夹具共 20 个文件、431,248 字节。宿主生成的运行
initramfs 包含 1,369 个条目。

Guest 使用继承的 GCC/G++ 11.2.0、musl 1.2.4 和 binutils 2.37 顺序执行六次
C++17 编译，目标为 x86_64 Linux-musl 静态 personality，使用
`-O2 -pipe -fno-exceptions -fno-rtti` 和 `ar rcsD`，再静态链接测试程序并剥离
符号。选项 `-pipe` 以流方式传输汇编输入。宿主预检测得 Itanium 汇编文件为
1,066,492 字节，超过 tmpfs 的 1 MiB 单文件限制。Guest 在各 ext4 工作盘的
私有临时目录保存其余临时文件。编译器依赖记录与六次编译实际使用的 14 个非系统
源码和头文件完全一致。宿主独立比较六个归档成员与 guest 对象文件，并检查夹具的
静态 ET_EXEC 格式和执行权限。

两块独立干净工作盘得到字节完全一致的产物。

| Guest 产物 | 字节 | SHA-256 |
| --- | ---: | --- |
| `libLLVMDemangle.a` | 660,656 | `115729861d9765babf31151e3266946e04d8d743c4fc79814c88dd7ed32371d2` |
| `demangle` | 411,592 | `d7de9798b1b32a14e06ee731f93857fd9587a056e33680ddc4e03dcf4d1e86b5` |

两次夹具运行均得到预期的 Itanium、Microsoft、Rust v0、D 名称反修饰结果，并拒绝
无效 Itanium 输入。两次从保留磁盘重新启动后，都触发真实 C++ 语法错误和缺库链接错误。
两项均返回状态 1，保留原始诊断，未留下失败产物。用保留的 guest 构建归档重新链接，
所得可执行文件与先前产物字节完全一致，两个可执行文件均再次运行。宿主比较全部先前
工作区文件和保留的数据文件，每次启动后的只读 `e2fsck -f -n` 均通过。

## 预声明预算与实测用量

两块干净的 64 MiB Linux personality ext4 工作盘均使用 4 KiB 块、4,096 个 inode
和 8 MiB 内部日志。门禁声明每会话限时 900 秒，编译期间 COM1 响应上限 5,000 ms，
采样物理页增量上限 196,608 个 4 KiB 帧，内核堆 16 MiB、VFS 槽 2,048 个、
总任务槽 32 个、每进程描述符 32 个。两次构建均在活跃的 G++ 进程写出首个对象之前
响应 COM1 请求。每次构建保留 1,685,548 字节的工作区文件。全部会话干净关机并

## 宿主 LLVMDemangle 源码闭包验证

WSL 宿主使用与 M11 对应的 GCC/G++ 11.2.0 和 binutils 2.37，从 Rust 固定 fork 提交
`e8a2ffcf322f45b8dce82c65ab27a3e2430a6b51` 编译 LLVM 20.1.8 的 `CMakeLists.txt`
列出的六个未修改 demangle 翻译单元。源码审计校验 16 个 Git blob（424,749 字节），包含
实现、八个头文件/定义文件、`CMakeLists.txt` 和 LLVM 许可证。选定组件构建无需生成的 LLVM
头文件或调用 CMake、Ninja。静态 Linux-musl 夹具链接归档，对 Itanium、Microsoft、Rust v0
及 D 名称解码，并拒绝无效的 Itanium 名称。宿主耗时 5.49 秒，宿主子进程实测 RSS 最高
183,724 KiB，这些数字仅覆盖宿主运行。

## Rust 与 Cargo 边界

锁定 Rust 1.90.0 的 `src/stage0` 要求 2025-08-07 的 Rust 1.89.0。M12 的 1.90.0
rustc、Cargo、target std 和 rust-lld 仍单独识别为继承组件。获取指定 stage0、在 guest 中
实测调用，以及为 rustc 和 Cargo 准备有界离线输入闭包仍待完成。完整组件和多阶段各需独立实测。

独立宿主扫描校验发行版 `src/stage0` 的 SHA-256 为
`05f9bc20d622ffeedf9c56b73fd4fb0b0a27d67b8d0c09460d01209cc2d41604`，其中
`dist/2025-08-07` 的 `x86_64-unknown-linux-musl` 条目指定以下输入。

| 指定包 | 固定 xz 输入的 SHA-256 |
| --- | --- |
| rustc 1.89.0 | `7cb45d30d4cdb8462d9b2f0f30d7a365752c80e63a54d92466d988c565ca9650` |
| rust-std 1.89.0 | `b098c201e26a4810536efd13f1c265ae340463cd477ad8a073b89be98d3f1f9f` |
| Cargo 1.89.0 | `04c8c7c73dfe492690c1497e22ef9388628b1248286bbd32725eaddab0042783` |

独立 Cargo.lock 的 512 个 registry 包校验和全部在官方发行版 vendor 元数据中找到。
对应完整包目录共 30,274 个文件、638,095,056 字节，包含所有平台和可选/开发输入，范围
大于仍待测定的 Linux-musl 构建闭包。根锁文件的 517 个 registry 校验和也全部匹配。
原始宿主评估保留在 `build/m18-llvm/host-checks/rust-route-assessment.json`。
下一项工作是独立引入并实测三个指定 stage0 包。为 Cargo 源码构建制定预算前，需要解析
锁定的 Linux-musl 依赖图，并选定 SQLite、libgit2、curl/HTTP2 和 TLS 原生依赖。
本批尚未验收 rustc、Cargo、std、链接器或多阶段 bootstrap。
