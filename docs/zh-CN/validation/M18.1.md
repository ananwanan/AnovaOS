## 保留的首次失败

首次 QEMU 运行通过 `sed`、`awk`、`grep`、`expr`、`tr`、`sort`、`cmp`、`mv` 和有界 `ln`
断言，实际 C 算术程序输出 `gmp=42 mpfr=42 mpc=42+1i`。原始 configure 越过初始工具
检查，检测到复制回退，随后超过 300 秒 guest 会话时限。此次未取得 configure 退出或正常关机
结果。启动 shell 自检后，保留的 configure 输出反复出现 `as_echo: eval: line 0: syntax error:
unexpected end of file (expecting ")")`。

Autoconf 启动时的长 printf 操作数超过此 Linux personality 的单字符串 1,023 字节 exec
上限。显式 BusyBox 配置现加入 ash `printf`、`echo` 内建和真实 `install` applet。更新
夹具核验 13,312 字节的内建 printf 操作数，并检查 `install` 保留所请求的执行权限及精确内容。
原 M15 工具集保持不变。上游 `configure` 和 `Makefile.in` 保留原样。

停止的工作盘和串口记录位于 WSL Linux 文件系统运行的
`build/m18-gcc-1795236569866563897/round-1/`。原始宿主命令输出为
`build/m18-gcc-attempt-1.log`。

## C89 探测暴露 Linux 管道容量

后续 RAM-backed 运行中，原样 configure 实际编译、链接并运行 `conftest`，报告
`checking whether we are cross compiling... no`，识别 GNU C 并确认 `-g`。随后停在原有 ISO
C89 探测。ash 的 1–4 KiB 内联 heredoc 路径会先写满数据，再启动读者命令。原 1 KiB Linux
队列无法完成该写入，写者和 configure 均停等。宿主终止停滞的 VM。停盘取出的精确 UART、
原始 `configure.stdout`/`config.log` 保留于
`build/m18-validation/initial-failures/1795237879037987970/`。

Linux 适配器现在先分配 4 KiB 字节流缓冲，再发布管道两端。空管道可接收相应完整写入，部分
占用时仍可短写。宿主 VFS 测试覆盖完整 4 KiB 写入、满管道及部分占用就绪、回绕精确内容、
EOF、断开读者及描述符/管道池耗尽后复用。原生字节流及 packet 容量和槽位限额保持不变。

使用新管道容量的首轮 guest 启动对实际 heredoc 输出逐字节比较，再记录
`[M18:POSIX:SHELL] heredoc=2049`。此次通过其他 applet 与算术检查，并在 configure
存活期间通过 COM1 应答。

## 干净入口复跑和递归 exec 诊断

全新 64 MiB 工作盘上的 TCG 第 `1795246921220643036` 轮通过原始顶层 configure，退出 0。
Make 启动原始 4,012 字节 `configure-gcc` 命令，进入 `./gcc`，报告
`cannot find sources (tree.c) in /m18-source/gcc` 并退出 2。构建启动至正常关机耗时
528,938 毫秒，COM1 响应 40 毫秒。采样物理帧增量峰值 11,452 页，堆峰值 2,542,944 字节，
VFS 峰值 1,450 节点。成功的 ext4 更新峰值为 3,059 块和 67 个 inode，关机时为 2,534 块、
66 个 inode。只读 `e2fsck` 和同盘全新启动验证了种子算术程序、原生 `hello-c` 和保留的工作区字节。
第二个独立轮次得到相同退出状态并通过恢复检查，构建启动耗时 868,626 毫秒，COM1 响应 60 毫秒。

另取停机磁盘副本，通过 `-o configure-gcc` 单独运行同一份 guest 生成 Makefile 的递归配方。
Guest 实际输出 `make: /bootstrap/sh: Argument list too long` 和
`Makefile:3997: all-gcc Error 127`，make 退出 2。日志与工作盘在
`build/m18-validation/gcc-stage1/exec4095/` 和 `recursive-exec4095/`。
后者的 UART SHA-256 为 `d146cb8e2da863d5cd9a902461f665397d2db28ab5fad57591f52215d445f708`。

Linux 修复允许每串 12,287 数据字节，argv/env 每向量 16 KiB。受检启动块仍为 32 KiB，
每向量最多 256 项，原生 ABI 使用独立限制。TCG 第 `1795247681285534961` 轮在全新 Stage1 盘上
于 configure 前通过真实 fork/exec 的 13 项测试。覆盖 argv、env 的单串长度、向量总字节和项数
恰好达到上限及超限一单位，启动块恰好 32 KiB 及超限一字节，以及 8,355 字节 `ash -c` 操作数
返回 43。每项拒绝均返回 `E2BIG`。24 项 ABI/ELF 宿主测试、严格 ABI/ELF 和 ext4/metrics 内核
Clippy 以及裸机调试构建均通过。

后续全新盘 `m18-gcc-test --entry` 通过未修改的配方实际进入递归 make。在故意不配置的 GCC
子目录中报告 `No rule to make target 'all'`，make 退出 2。正常关机和种子重启均通过，证据在
`build/m18-validation/gcc-stage1/entry-expanded/`。

另一次 guest 复跑从锁定源码宿主预检中取出实际 `ar rcT libbackend.a` 配方，仅归一化 ar
可执行文件路径。其 466 项、6,709 字符串数据字节触发 `Argument list too long`，shell 退出

`build/m18-validation/m18-gcc-ar-vector-zup045e3/` 和 `m18-gcc-ar-vector-jt0dc5r5/`。
后续 KVM guest 复跑在 `all-gcc` 中执行原版 `ar rcT libbackend.a`，接受共 6,701 字节的
466 个操作数，创建 1,397,276 字节的薄归档，随后进入下一目标。实际构建记录在

## Ext4 上的大型 Linux 可执行文件

独立 TCG 诊断从 initramfs 和可执行的 ext4 副本运行同一份 26,486,984 字节的继承版 `cc1`。
Initramfs 进程退出 0。Ext4 副本分配内核堆时出现 `[MM:OOM] size=26486984 ... capacity=16777216`，
进程退出 126。在同一停机盘的新副本上按位置加载 ELF 后，两个进程均退出 0。该轮启动的堆峰值为
1,675,968 字节，物理帧增量 8,241 页。两次诊断均正常关机并通过只读 `e2fsck`。保留盘、命令和
原始日志在 `build/m18-validation/gcc-stage1/persistent-elf-before/` 和 `persistent-elf-after/`。

Linux `execve` 校验持久文件中的主 ELF，并按最多 16 KiB 分块填充私有用户页，再提交映像。
原生执行 ABI 和解释器准入使用既有路径。本诊断执行的是继承版编译器后端。

## 第一轮 Stage1 源码盘到达 `configure-intl`

首次 512 MiB TCG 第 `1795247681285534961` 轮通过种子和 exec 夹具。原始顶层 configure
退出 0。原始 `all-gcc` 进入 `configure-intl`，通过 guest C 编译器和预处理器探测，随后
因找不到可用的 grep 退出 2。上游对非 GNU grep 的探测以 `diff` 比较长行结果，而该轮
BusyBox 配置没有此 applet。更新后的配置准入 `diff`，验证实际长行输出相等和不同输入的状态，
并准入原始 fixincludes 规则用到的 `find` 条件。

构建耗时 880,098 毫秒，COM1 活跃交换 61 毫秒。峰值为 27,229 ext4 块、2,424 个 inode、
1,498 个 VFS 节点、12,385 个采样物理帧和 2,568,480 字节内核堆。ACPI 正常关机、只读
`e2fsck` 以及重启后运行种子和比较观测工作区精确字节均通过。工作盘、源码清单、退出状态、
顶层日志和 `intl/config.log` 保存在 `build/m18-validation/gcc-stage1/round-intl-missing-diff/`。

独立宿主预检用选中的 C/C++ 和生成器输入验证原始 `configure-gcc`、`all-gcc` 目标图。
选集含 2,272 份精确上游文件、90,009,327 字节载荷，计入目录和清单共占 2,366 个源码 inode。
宿主产物和夹具结果在 `build/m18-host-quality/stage1-source-discovery/`。Guest Stage1 的验收
依赖实际在 guest 内完成构建和运行检查。

独立 TCG 诊断复跑在新工作盘上放入停机轮次中由 guest 生成的精确顶层配置，以及最终锁定源码选集。
复跑使用 BusyBox grep 和 diff 通过 `configure-intl`，完成原始 GCC 子配置并生成 `gcc/Makefile`、
`auto-host.h` 及 binutils 包装脚本，随后构建 `libiberty.a` 和构建端的 `libiberty`、
`fixincludes`，并完成构建端 `libcpp` 的配置。

原始 `all-build-libcpp` 配方在 `localedir.hs` 停下，ash 报告找不到可执行的 2,636 字节发行脚本
`move-if-change`。停机盘上的脚本字节精确匹配，权限为 `0755`。固定版本的 ash 尝试执行文本文件
返回 `ENOEXEC` 后，通过配置的 BusyBox 路径重试。Guest 中缺少旧路径 `/proc/self/exe`。
独立 M18 配置现使用 `/bootstrap/busybox`。前置夹具直接执行未修改的发行脚本，检查退出状态和目标字节。

该复跑中 make 退出 2，ACPI 正常关机后通过只读 `e2fsck`，共耗时 4,031,509 毫秒。停机盘有
27,956 块和 2,630 个 inode，VFS 峰值 1,852 节点，采样物理帧增量 19,270 页，堆峰值
2,250,560 字节。源码清单、原始退出状态、构建产物和资源记录在
`build/m18-validation/m18-gcc-1795247681285534961-configure-replay-1795249014969709880/`。

第二轮全新盘独立重现相同的 `localedir.hs` 失败，顶层 configure 退出 0、make 退出 2。
构建耗时 4,650,838 毫秒，峰值为 28,059 块、2,676 个 inode、1,916 个 VFS 节点、
19,266 个采样物理帧和 2,774,720 字节内核堆。正常关机、独立 `e2fsck` 和重启运行种子通过。
证据在 `build/m18-validation/gcc-stage1/round-script-exec/`。

配置修复后的 ash 在新工作盘上通过了直接运行原版脚本的夹具。首个停机复跑盘的新副本也越过
相同的 `localedir.hs` 配方，产生预期时间戳、编译原始 `all-build-libcpp` C++ 源码并进入
`configure-zlib`。Zlib 的时间戳探测因固定 BusyBox `ls` 拒绝 `-Lt` 和 `-t` 选项而失败。
停机盘记录了 2021 年发行源码时间和 2026 年 guest 构建时间。独立 M18 配置现为该上游探测启用
按时间排序、跟随链接和 sleep。原始 zlib 配置输出及工作盘保存在
`build/m18-validation/m18-gcc-1795253321699336247-ash-resume-1795253408652227944/`。

第三轮全新工作盘复现 `configure-zlib` 故障并实际输出 `ls: unrecognized option: t`，
顶层 configure 退出 0，make 退出 2。`move-if-change` 前置探测、正常关机和种子重启通过。
构建耗时 4,815,512 毫秒，峰值为 28,306 块、2,702 个 inode、1,951 个 VFS 节点、
19,266 个采样物理帧和 2,774,720 字节内核堆。精确输入、停机盘和记录在
`build/m18-validation/gcc-stage1/round-zlib-ls/`。

修复后的 `ls` 复跑对发行源码和新建 guest 文件通过了 `-Lt` 和 `-t`，并通过原始 zlib 时间探测，
构建了 zlib、libbacktrace 和编译器 host 侧 libcpp。下一处停在 `all-libcody`，原始 `buffer.o`
规则执行 `mkdir -p $(dir $@)`，传入 `./` 后 Linux 适配层返回 `EINVAL`。该轮在 872,875 毫秒后
make 退出 2，达到 28,872 块、2,798 个 inode、1,989 个 VFS 节点、19,285 个采样物理帧和
2,251,040 字节堆峰值。QEMU 正常关机。详见
`build/m18-validation/m18-gcc-1795253731575501307-ls-resume-1795253809780135975/`。

Linux `mkdir` 改为处理末尾斜线和已有目录语义，包括将已解析的 `.`、`..` 及根目录返回 `EEXIST`。
TCG 工作盘副本在 libcody 工作目录通过精确 `mkdir -p ./` 命令，原始规则生成 17,904 字节的
`buffer.o`。独立 `test-compat` 复跑在 45,902 毫秒内通过新增 mkdir 用例。命令和串口文件
`test-compat-mkdir*` 保存在 `build/m18-validation/gcc-stage1/regressions/`。
