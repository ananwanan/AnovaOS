## 原始失败与修正

保留原始带时间戳结果，不改写为成功。初版构造流程重复连接 GUI，删除旧前置
连接后修复。GUI 创建仅在可失败步骤成功后认领栅格，析构释放认领，保留有界
合成器替换。GCC 颜色转义导致原始清理显示难读，固定 color-never 参数修复配方，
没有解析输出猜状态。原生断言观察者从已越过目标的游标等待，明确停止该轮后
修正观察逻辑。fixture 曾误用原生 CPU fault 状态，Linux UD2/SIGILL 实际应为
reason 3/code 4。淘汰界面本身正确，但独立字形样本缺少 V；补齐样本后真实像素通过。

早期 `1793810697336460340` 已精确保存修复源码，却遇到真实链接/存储失败，编译
状态 1，临时产物清理 IO_ERROR。保留原盘与 UART；该轮没有记录最初块设备失败
分类，因此根因仍为**未分类**，不宣称已经修复。随后增加队列、完成和超时元数据
诊断，没有修改原有两秒设备期限或日志文件系统失败关闭策略。同挂载存储错误仍
可能需要检查和重新挂载。UI 现在在无条件任务/描述符回收后显示清理错误，不用
成功状态掩盖。本次成功配置使用独立新盘，只验收声明范围，不证明任意存储可靠性。


后续 Files 回归发现覆盖保存观察者读取了不完整的 `[FILES:SAVED] pat`。真实保存
正确完成；有关观察者统一等待完整换行记录，保留原五秒界限和路径、大小、dirty
断言。存储故障矩阵还遇到握手/UART 尚无任何字节时的 TCP 启动重置；仅空握手的
EOF/reset 可在同一五秒启动期限内重连，不重新启动 VM，部分握手或任何命令失败
仍立即失败。宿主 socket 测试断言这些边界。另一次全矩阵拒绝了超过原五秒预算
的真实 16 KiB 保存；保留该失败，独立边界用例和最终完整 16 用例/43 启动重跑均
按不变上限通过。没有提高交互、设备或构建上限。

后续图形 PTY 回归曾超过原编译期限，保留失败的原始串口和画面。另一次重启发现
终端停止/重启的真实竞态：合成器读取断开通知前，旧 GUI 槽位仍占用。原生连接
现在在已有 100 tick 窗口内重试 NO_SPACE；四个真实客户端持续占满仍返回 NO_SPACE。
专项断言真实耗尽及物理关闭其他客户端后恢复，随后回收辅助进程并重新启动 C 客户端。

无节流的脱离会话写入者暴露内核进展错误：只剩一个输出字节空间时，poll/唤醒
判断 slave 可写，而写入为 CRLF 预留两个字节。反复虚假唤醒可能使不可抢占内核
无法启用 IRQ。写入、poll 与唤醒现共用准确 CRLF/回显/EOF 条件，并以两个宿主
边界测试验证。真实持续写入者现可返回 UI，显示首进程真实零退出及采集中断，
独立核对原产物字节仍保留，所有后代均回收。取得状态后最多继续排空三轮，
不完整采集不能发布产物。

`1793818208092670765` 的观察者最初在 35,157 ms 编译结果下仍输出 result=Ok：
它先接受已到达结果，再检查声明的 35,000 ms 上限。这是观察者缺陷，不能作为
按期通过证据。原始记录保留并附此说明；现先检查期限，再接受完成，宿主断言
拒绝 35,157 ms 和超过一纳秒的结果。最终严格重跑结果见下文。
