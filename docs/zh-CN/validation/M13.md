# M13：SDK、包策略与诊断验证

[English](../../en/validation/M13.md) | **简体中文**


本地验收日期为 **2026-10-23（Asia/Shanghai）**，基线 dev 的 `b3880a0`，在 `codex/m13-sdk-packages` 和 WSL 克隆 `/home/ananwanan/code/AnovaOS` 实现；聊天原 Windows 挂载目录当时没有项目源码。环境为 Ubuntu24.04/WSL2、Rust/Cargo1.90.0、GCC/G++13.3.0、binutils2.42、QEMU8.2.2 q35/TCG、e2fsprogs1.47.0 和锁定 OVMF/Limine，不声称实机或远端 CI 执行。

## SDK 与公开开发流程

sdk-test 导出 SDK1.0.0 并检查 SHA256SUMS，构建独立 C/C++/Rust 模板，执行 C/C++ 布局和错误契约，直接调用导出的 Python 驱动构建 C 和独立 Rust 使用方。候选发布拒绝过时额外文件或符号链接，保留旧版本；宿主覆盖失败和完整发布。修改 Rust 路径依赖确实改变 ELF，C 编译失败保留可运行旧 ELF。重复门禁刷新 SDK 和源码，避免验证旧运行时副本。

原生编号、错误名称、未知负值、结构大小、字段偏移和响应版本独立检查。最终 99 项宿主测试和 247 文件用途覆盖通过；运行时参数迭代器覆盖 64 个 1023 字节参数、拒绝 65 个或 1024 字节参数。这是迭代器边界，不表示全部最长参数可同时装入启动块。

app-test 使用 app-image/app-run 的公开镜像路径。错误外部摘要拒绝，C 模板包放入 `/repo/local.apkg`，在真实客户系统安装并运行，状态为 0；缺文件实际错误为 not_found。干净 ACPI 关机和 e2fsck 通过，日志为 `build/logs/app-workflow.serial.log`、app-workflow.result.txt。

## 版本化包与磁盘策略

package-v2-test 验证真实 C/C++/Rust 原生包和静态 ET_EXEC musl Linux 包。每个已安装程序后都有 shell 状态断言，提前标记不能掩盖 SDK 错误或 RAII 检查失败。C 升级真实修改并重编源码，打印 `[M13:C:V2]`；暂存失败保旧版，升级后与重启后均运行新代码，拒绝降级。用户数据跨升级、重启和卸载保留。两个磁盘范围各启动两次，四次 e2fsck 全部通过。

实际客户系统解析器拒绝 31 个独立重算外部摘要的对抗归档，覆盖架构、ABI、SDK、依赖、权限、能力、路径、入口、模式、许可、截断、尾字节、ELF 和 TLS。重新摘要使测试通过外层锁，真正进入内层验证。有效控制包可安装，被拒输入令宿主沙箱命名空间字节完全不变；磁盘人格不匹配在安装前失败，Linux 盘也拒绝旧原生 ANOVAPK1。

VFS 固定挂载 ABI 标记的 inode。宿主验证已有描述符写、定位写、截断、chmod/fchmod、执行位、删除和两向重命名全部拒绝。两个真实客户系统尝试覆盖 `/persist/.anova-abi` 得只读失败和状态1，再读原标记得状态0，保证挂载期间安装和执行策略一致。

证据包括 package-v2.result.txt、native/Linux 的首次与重启串口/QEMU 日志，位于 build/logs。原调试 ELF 与包内 strip 载荷独立保存，描述符摘要对应载荷，不混淆两种身份。

## 故障与源码符号

diagnostics-test 触发真实 Ring3 #UD，五个帧地址由宿主 addr2line 解析到 m13_crash_leaf、m13_crash_middle、m13_crash_entry、main、_start 及实际源码行。另一次 RBP=1 的故障只得到一帧和 reason=invalid-frame。两次 shell 状态134，之后正常 echo 真正执行，客户系统干净关机。仅函数和源码检查完成后写总成功；已 strip ELF 明确以缺符号或调试信息错误拒绝。

日志为 diagnostics-guest.serial.log、diagnostics.symbols.log、diagnostics.result.txt；故障 ELF 为 `build/diagnostics/m13-crash.elf`。回溯使用可恢复的受检用户复制，最多16帧、RSP以上1 MiB、相邻64 KiB；资源记录是全局页、堆和任务容量，不是每进程统计。

## 回归运行器修正

WSL 串口读取可能结束在 `[SHELL:STATUS] code=`，后续的零尚未到，旧运行器立即误判失败。现在等待完整状态行，并增加分片输入回归；完整非零仍立即失败，最初被拒的工具链/Rust 日志中编译本身实际为零。

原 PTY 测试错误假设一次读取能消费完整规范回显，且写 Ctrl+C 返回时信号处理已完成。私有重复追踪复现后，改为轮询并消费精确回显、原始输入和回复字节，并在 ppoll 中原子解除 SIGINT 屏蔽来等待实际处理。30 个私有宿主追踪（静态、静态 PIE、动态各10次）均通过，客户系统冒烟也通过，没有跳过断言或兼容行为。

## 范围与保留回归

原生 v1 和 ANOVAPK1 兼容仍是回归要求。V2 Linux 包限静态 ET_EXEC，M9 动态/PIE 运行时独立。权限是准入声明，不是沙箱；没有依赖求解、签名发布者、断电事务、通用 Linux/glibc、原生 std、GDB stub 或交互调试器。本 M13 证据本身不声称 GUI，后续 [M14.4](M14.4.md) 已独立验收，当前总览见 [STATUS](../guides/STATUS.md)。

下方最终命令均退出0，完整 JSON 与输出在 `build/logs/m13-regressions/accepted-results.json` 及引用的运行时、重试和代理结果；最初失败独立保留，不因成功重试而擦除。另通过99宿主测试、严格宿主/原生/内核 Clippy、根/用户/模板格式、247用途、doctor、差异检查和内核构建。13场景要求真正到达故障、panic、挂起和 OOM，不凭横幅或退出码判断。工具在 WSL 从源码或校验锁定官方分发准备，客户系统测试未将编译请求委托宿主。

公网 Cargo 通过 `ANOVA_CARGO_TEST_PROXY=http://10.0.2.2:18099` 验收，使用临时匿名、仅回环且只允许 GitHub/crates.io 的 CONNECT 代理。代理不终止 TLS 或提供编译器；客户系统核固定 CA、归档摘要和 Git 提交，并在独立无 NIC 启动后从保留源重建。生成的 public_proxy.py 位于回归日志，门禁后停止。

直接公网传输**未证明**：初次直连在获取前块设备超时，之后一次 DNS 解析线程无法启动。接受的代理保持 M12 边界，短暂 Git TLS EOF 由未修改 Cargo 成功重试。原非致命缓存锁警告继续保留，未伪造锁实现或绕过 TLS。CI 已配置新门禁，但此本地验收未执行远端 Actions。
