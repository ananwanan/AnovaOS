**状态：M17.1 有界五启动配置已通过本地验收；M17.2 的声明 PTY/GCC 配置已本地验收，M17.3 已实现最小文件/编辑闭环；完整存储故障验收及 M17.4–M17.5 待完成。** 本计划接续

## 目标与前置条件

让日常应用开发能够通过桌面完成：编辑、保存、编译、运行、查看失败原因、
修改源码，并在重启后保留工作成果。
使用已有的 guest GCC/G++/Rust/Cargo 种子工具。
从源码重建这些编译器属于独立工作，不是开发桌面的前置条件。

历史 [GUI 运行时](M14_RUNTIME.md) 已验证有界原生 GUI 客户端和 echo/pwd 终端。
该终端仅接受这两类命令，最多捕获 128 字节输出；
它并不是已经能够运行编译器的图形 shell。
M17.2 现另行提供[真实 PTY 终端](M17_PTY.md)；可靠图形源码编辑及全 GUI 流程仍属于 M17.3/M17.5。

以 M16 声明的资源、VFS 和 ext4 工作盘配置为起点，保留已有 ext2 配置。
先测量选定的桌面与构建工作负载。
验收前声明 RAM、堆、任务、描述符、节点、inode、文件和 GUI 配额；
单独增加 QEMU RAM 不会扩大内核已有的有界资源。
Rust 合成器与桌面策略继续放在隔离的用户进程中。

## M17.1：受监督的桌面会话

提供受监督的用户态会话，包含应用启动、窗口焦点、移动、关闭和有序退出。
明确合成器退出、客户端退出、重启次数限制及清理责任。
保留独立的 COM1 shell。持久工作成果存放在工作盘；
会话重启不得清除这些数据。

仅在测量内存与 IPC 边界并补齐失败处理后，扩展当前四客户端及私有窗口配额。
继续显式执行可执行文件准入。
修改运行时前，先定义必要的版本化 C ABI 扩展及 C/C++/Rust 等价行为；
不得悄悄改变已冻结的记录布局或句柄语义。

验收：在声明的显示配置中，同时启动并操作三个独立实现的 GUI 客户端，
检查焦点、关闭后重新启动及资源复用。本阶段使用已有客户端；终端/编辑器/文件浏览器的
集成待 M17.2/M17.3 完成后在 M17.5 验收。
耗尽声明的客户端或 surface 配额，拒绝陈旧或越权句柄，注入客户端故障；
其他客户端和串口恢复 shell 必须继续工作。
重启会话后重新打开持久数据，不宣称尚未实现的 surface 或未保存缓冲区自动恢复。

## M17.2：图形 PTY 终端

通过 PTY 将真正的图形终端连接到选定的 Linux-musl shell 和 guest 构建工具。
传递 stdin、stdout、stderr、终端尺寸与前台中断。
实现有明确文档的 ANSI 子集、有界回滚缓冲、长输出处理和取消，
不得因此阻塞 GUI 事件循环。

显式解决原生 GUI 终端与 Linux shell、编译器进程的准入问题。
使用已声明的启动模块条目，或独立实现并验收的软件包、服务准入策略；
GUI 启动进程不会自动解除原生与 Linux 持久盘的既有限制。
保留不可变 ABI 标记、显式 personality 和 GUI 权限检查，不得仅凭 ELF 猜测 ABI。

验收：输入 shell 命令、编辑输入，显示 stdout 和 stderr 夹具各自不同的已知内容，
并报告子进程非零状态。PTY 通常合并 slave 输出流，不能从字节推断原始通道身份。
若需独立日志捕获通道，应单独明确策略并测试。
编译选定应用，用 Ctrl+C 中断长时间运行的子进程，输出过程中调整窗口尺寸，
超过回滚缓冲上限时不得死锁或泄漏内存。
检查 EOF、shell 重启、PTY/任务/描述符耗尽后的恢复，
并确认独立 COM1 shell 仍能响应。仅演示 echo/pwd 不能通过本阶段。

## M17.3：文件与可靠源码编辑

最小文件/编辑闭环现已实现，见 [M17 文件](M17_FILES.md)及
[本地验证范围](../validation/M17.3.md)。下述完整存储故障退出条件仍待完成，
不能由最小交付推断已通过。

提供目录导航、文件打开、创建、重命名、删除及源码编辑器。
编辑器应显示未保存状态、明确保存失败，并检查覆盖和未保存内容。
限制路径、文件大小和缓冲区增长，准确报告存储耗尽。
明确编辑器与终端如何共享选定工作盘的命名空间。

定义实际支持的保存策略：临时文件创建、文件 fsync、rename，
以及在已经实现并测试的前提下执行父目录持久化。
若暂不支持更强策略，准确说明当前保证，
并在所选策略承诺保留旧副本时确保旧副本可用。
rename 成功或打印 fsync 日志，都不能证明 ext2 或新 ext4 配置具有
任意场景下的原子持久性或断电恢复能力。

验收：创建、修改 C、C++ 和 Rust 源码，保存后重新打开并核对精确字节，
重命名后从图形终端读取相同路径。
测试文件大小、inode、磁盘满、写入及 flush 失败；
报告错误，不得把失败的缓冲区标为已保存。
检查声明的旧副本策略及正常关机、重启后的精确内容；
对没有实际执行的突然断电场景单独标记未验证。

## M17.4：观测与受控恢复

显示构建日志、命令退出或故障状态，以及可取得的全局磁盘、inode、
内存、任务与描述符观测值，注明单位和采样范围。
仅增加有真实内核或文件系统接口支持的指标；无法取得的值必须明确显示。
既有全局故障快照不能证明逐进程 CPU 时间、RSS、所有权统计或精确资源峰值。

提供带身份检查、访问规则和生命周期清理的任务终止与服务重启。
区分停止应用、重启合成器和重启整个会话。
保留诊断证据与用户数据；
显示、输入准入不得变成仅凭路径即可获得权限的策略。

验收：观察已知构建失败，查看保留日志及子进程状态，
终止指定的失控测试任务，确认其他进程继续推进。
重启故意失败的 GUI 服务，使用新会话重新连接客户端。
对照底层接口核对显示的全局容量，
验证陈旧任务标识不能终止复用相同位置的替代任务。

## M17.5：完整图形开发流程

对声明的 C、C++、Rust 应用，仅通过桌面输入完成：
编辑 → 保存 → 构建 → 运行 → 引入真实源码错误 → 查看诊断 →
修复 → 重新构建 → 运行 → 正常关机 → 重启 → 重新打开并运行。
记录源码、工具与 SDK 身份、命令行、输出哈希及退出状态。
构建被拒绝后保留先前可用的可执行文件；
发布新产物必须遵循明确的失败安全策略，不能先截断旧产物。

声明的构建运行期间，让另一个 GUI 客户端持续接收输入。
执行前设定交互延迟上限，保留带时间戳的输入和呈现证据及超限情况；
截图本身不能证明响应性。
注入客户端崩溃和合成器退出，检查隔离及显式重连，
验证串口恢复与正常关机不会丢弃已经保存的工作成果。
继续保留适用的运行时、存储、工具链及 GUI 回归门禁。

验收必须包含重启后精确源码与输出保留、真实编译成功与失败、
并发交互测量、资源清理及声明的恢复结果。
分别记录实现、本地 QEMU 验收、远端 CI 和真实硬件；
单次成功演示不能证明这四个层次都已通过。

## 故障边界与后续工作

在内核、存储和输入、显示通路仍可用时，
桌面应能诊断普通应用、构建、文件和服务故障。
内核 panic、启动失败、显示或输入损坏、不可恢复的存储故障，
仍需要串口诊断、QEMU 控制或宿主辅助恢复。

M17 之后，可单独定义 M18，推进经测量的编译器源码阶段和 guest 内镜像生成。
完整 GCC/Rust/LLVM 自举、原生 libc/std、SMP、内核抢占、通用 GPU 加速、
USB、NVMe/AHCI 及广泛 Linux GUI 兼容仍是独立工作线，
各自需要前置条件与验收，不能隐含为本开发桌面的要求。

M17.2 实现契约见 [M17_PTY](M17_PTY.md)，实际两次启动证据见 [M17.2](../validation/M17.2.md)。历史 M14 echo/pwd 示例继续独立界定范围。
