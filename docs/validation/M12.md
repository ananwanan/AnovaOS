## Runtime and ownership boundaries

`rust-cross-test` passed actual guest checks for:

- Alternate-stack delivery/return, SA_ONSTACK, rejected in-handler stack changes,
  too-small registration and inaccessible pointers.
- Detached-thread self-unmap followed by exit; a real invalid executable return
  still terminates its child with SIGSEGV when that signal was blocked/ignored.
- 200-byte ext2 names and Linux getdents; 256-byte components and 513-byte paths
  are rejected. Host tests preserve native v1 directory wire size and cursor
  position when an extended name cannot be represented.
- O_NOFOLLOW, relative dirfd file removal, empty-directory deletion, retained
  open directory identity, busy cwd rejection and repeated inode reuse.
- Full-duplex AF_UNIX sequenced packets, message truncation, atomic backpressure,
  bad receive pointers without dequeue, zero-length messages, EOF and reuse.
- Replaced open-file retention, pread/pwrite offset preservation, ftruncate
  shrink/zero-growth/bounds, mode_t file-type masking, rejected special bits,
  OFD flock contention and final-close release.

All previous memory ownership, guard/W^X, scheduler/FPU, OOM rollback, terminal,
storage/device-error, network/package/TLS and C/C++ development gates remain green.
No directory transaction journal, power-loss recovery, persistent shared mmap,
SMP or general Linux/glibc compatibility is claimed. Exact limits and the bounded
busy-directory policy are in M12_RUST.

Cargo emits a nonfatal global-cache last-use warning because POSIX fcntl record
locks are unsupported. This housekeeping is independent of the accepted frozen
vendor build. Optional timestamp/accelerated-copy probes also return real errors;
copying succeeds through actual file I/O. Advisory flock is implemented separately.

### Changes and failures found by the regression

- Cargo now builds `m12-macro`, whose ordinary and build dependencies both use
  `m12-macro-support`. Its build script generates source and environment consumed
  by the actual procedural macro. Host dependency rlibs use PIC so their static
  data can be linked into the macro shared object. Applications retain static
  linkage.
- The first full build exhausted the original 128-inode disk while creating an
  itoa temporary archive and returned real ENOSPC/Cargo status 101. Linux
  development images now allocate 512 inodes. The successful final filesystem
  uses 146 of them, demonstrating why 128 is insufficient. Native geometry,
  16 MiB volume size, 128-byte inodes and the 1 MiB file bound are retained.
- Rust preparation strips tools in separate scratch storage before copying the
  selected outputs into the candidate sysroot. Preparation retries exposed
  temporary ELF siblings in this host cache; normal installed-file digests were
  verified before removing those generated files and regenerating the inventory.
  Subsequent complete inventory and executable ELF checks pass. No hidden-file
  exclusion or weakened integrity check was added.
