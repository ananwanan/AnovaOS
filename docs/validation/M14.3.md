## Actual native GUI gate

`cargo xtask gui-test` boots the `graphics,gui,gui-test` image three times:
standard VGA and i8042, no VGA, and disabled i8042. Its real UART shell starts
`gui-test`; that user supervisor spawns a Rust compositor and independent red
and blue native processes. The compositor owns private user pages, software
surfaces, focus, movement, resizing, window ordering and damage composition.
The kernel supplies authenticated copied IPC, physical events and checked
scanout only. Existing native v1 syscall numbers and memory bounds are retained.

The primary session compares **every pixel in seven 800 by 600 screenshots**:
initial overlap, red focus, movement, resize, blue focus, red client failure
and a fresh compositor session. QMP injects actual PS/2 movement, buttons and
physical A/B/X/F11/F12 transitions. Red moves from `(80,80)` to `(160,130)`
and resizes from `240x160` to `280x130`; the previously occluded blue window
redraws correctly. The host reference specifies geometry/decorations independently
of the compositor implementation. Its own tests reject corrupt background,
window and cursor pixels, malformed or duplicate marker fields, unexpected
fault identities/vectors, timeout and fatal diagnostics.

X deliberately executes UD2 inside the focused red process. The host accepts
only that recorded PID and vector 6, requires its real wait status, checks that
its window disappears, and sends further physical input to the surviving blue
process. F12 separately executes UD2 in the first compositor; every connection
is invalidated. The supervisor reaps its actual fault status, starts a fresh
server and client, and the host verifies new session/identities and renewed
physical input. F11 then exits the restarted compositor and its client normally.
The host requires exactly these two expected faults; unrelated failures are fatal.

The no-controller boot displays both windows and compares another complete
480,000-pixel screenshot before the bounded test-mode server reports the missing
input path and the supervisor reaps its clients. The no-display boot reports
explicit unsupported display without pretending to show windows. All three
boots execute a COM1 recovery command, then require clean ACPI shutdown and
QEMU exit 0. Each boot has a 90-second watchdog. Eight screenshots therefore
cover **3,840,000 compared pixels** in total.

## Actual boundary and recovery checks

- Unauthorized native clients cannot bind, receive server packets, obtain physical
  input or present display pixels. Empty/oversized packet lengths and a real
  bad user pointer are rejected.
- Requests with wrong protocol versions/sessions, invalid dimensions, bad upload
  stride, stale handles, foreign handles and duplicate per-client surfaces fail
  through real native IPC before mutation.
- Four real client processes fill the kernel connection quota and a fifth is
  rejected. Closing/reaping them permits reconnect without restarting the server.
- A non-consuming client fills the sixteen-reply mailbox, is evicted without
  stalling other clients, and reconnects. A bad POLL output pointer leaves the
  actual reply queued for a subsequent valid copy.
- Each test boot independently exhausts the real kernel heap, calls production
  connection allocation and requires `NO_MEMORY`, no partial connection or
  retained allocation, then releases pressure, admits connections again and
  restores the exact heap baseline. This is separate from client quota pressure.
- Eleven pure GUI policy tests cover fixed wire layout/full-field round trips,
  malformed requests/buffers, generation/session/owner checks, quotas, private
  storage zeroing, overlap/damage/cursor restoration, movement, resize, capture
  and reset. Host tests do not substitute for native isolation or QMP delivery.
  The native gate checks input destinations and reconnect delivery; exact held-key
  reset/release ordering is implemented/reviewed but not separately asserted by QMP.

## Accepted limits and next stage

This is bounded CPU composition on standard VGA 800x600x32 with polled PS/2,
one BSP, four connections/windows and one 32x24 through 320x240 private RGB
surface per client. Upload chunks commit separately; presentation completion
means checked CPU copy/MFENCE, without vblank or atomic page flips. Queue
backpressure explicitly disconnects stalled clients. No writable shared mapping,
GPU rendering, USB, physical hardware, peripheral IRQ routing or Linux GUI
compatibility is established. Recovery recreates surfaces after a fresh session;
old handles never acquire authority in a replacement session.

M14.4 remains open for the actual Rust GUI runtime, text/fonts/widgets, graphical
terminal, clipboard and versioned C/C++/Rust GUI SDK with independent guest
compilation. M14.5 remains open for proven GPU rendering with CPU fallback.
Remote CI is configured but no remote result is claimed by this local record.
