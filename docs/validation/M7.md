This record describes actual local checks for modern virtio-blk, the declared
ext2 profile, source editing, shutdown/reboot persistence and retained regressions.
It does not imply remote CI, general ext2/Linux compatibility or crash safety.
Recorded 2026-10-21 (Asia/Shanghai).

identifies the M7 implementation. Design and exact limits:

## Real guest device and filesystem checks

Ordinary and test images identify PCI `00:02.0`, device `1af4:1042`, and report
32,768 sectors, eight split descriptors, one DMA page, modern VERSION_1,
FLUSH and polled completion. The last sector reads successfully; capacity and
u64-overflow requests fail before submission. Read-only features are honored.

The native fs-test disk suite executes through SYSCALL with inherited/shared
offsets across dup/fork, a write crossing the twelfth direct block, zeroed
sparse space, seek/size limits, bad user buffers, fsync target rejection,
open-unlink lifetime, final-close release and immediate file/block reuse:

```text
[BLK:BOUNDS] last_sector=ok capacity=reject overflow=reject flush=ok
[DISK:MOUNT] /persist=ext2:rw profile=4k-single-group native=anova.native.v1
[DISK:TEST] offsets=true fork=true indirect=true sparse=true unlink=true reuse=true negatives=true
[BLK:RESET] acknowledged=true dma_released=true
```

The normal smoke classifier requires these real markers, rejects mount failure
or DMA quarantine, and still requires exact free-frame/heap restoration after
the entire init/VFS/process suite. All historical M2–M6 negatives remain enabled.
The 13 cases retain success 33, panic/OOM 35, exception 37 and a reached timeout;
the host requires the injection diagnostics as well as the failure result.

## Persistence scenarios

All six use ordinary images, actual COM1 input and no test exit device. Every
session has a 60-second watchdog. The successful data image is retained under
`build/disks/persistence-<unique>.ext2`, separately from default temporary disks.
Transcripts/results are `build/logs/disk-*.serial.log`, `*.qemu.log`,
`*.result.txt` and `persistence.result.txt`.

| Scenario | Required observations |
| --- | --- |
| disk-save | Guest disk syscall suite; editor append/replace/delete/print/save; fsync success; install ELF; native execution returns 7; redirection/append; actual clean S5 exit 0 |
| disk-reboot | Same image reattached; source/text exact; saved ELF matches original byte-for-byte in guest; tmpfs file absent; saved executable runs again and returns 7; clean S5 exit 0 |
| disk-read-only | Device negotiates RO; write returns READ_ONLY, existing text still reads, normal shutdown succeeds |
| disk-bad-feature | Unknown INCOMPAT bit rejects mount with INVALID_FILESYSTEM; writes fail; initramfs shell and shutdown work |
| disk-write-error | blkdebug write EIO completes with virtio status 1; create/sync/retry/shutdown return IO_ERROR; descriptors remain usable and shell status is 0 |
| disk-flush-error | blkdebug FLUSH EIO completes with virtio status 1 during attach checks; disk mount is refused, reset releases DMA, `/persist` cannot be written and shell can shut down |

The final edited source is exactly:

```c
int main(void) { return 42; }
```

The redirected note is `durable\nappend\n`. The host independently remounts
the clean image after each of the first two boots and compares source bytes,
note bytes and the saved executable's SHA-256 with the actual built C ELF:

```text
4c813fb2d7bc7007502d20fb9ea0146568db4a9daa90095f933bb2c148b38367
```

This hash identifies this environment's C build; debug paths can change it.
The test computes the expected hash from the current ELF rather than hardcoding
it. Source editing is performed in the guest; the ELF is compiled on the host
then copied/installed in the guest. No guest compiler is claimed.

S5 success requires all writers stopped, final orphan closes, actual FLUSH,
clean-superblock flush and acknowledged queue reset. `[POWER:OFF]` alone is
insufficient: the host also requires QEMU to exit successfully. Error scenarios
never count a failed storage operation as successful durability.

## Limits and untested paths

The stack remains 64 KiB and heap 2 MiB. ext2 scratch buffers use fallible heap
allocation; one coherent DMA32 frame belongs to the device until reset. The
normal regression verifies its reclamation. Two-second timeout and failed-reset
quarantine paths are implemented; an actually stalled device or a reset that
never acknowledges was not injected in this validation.

There is no journal, atomic save/rename, live recovery, general-purpose AML,
hotplug, asynchronous block layer, device IRQ, SMP, Linux ABI or guest compiler.
Forced termination during mutation can corrupt a non-journaled filesystem;
dirty images are refused and require offline recovery. The editor is limited
to 16 KiB ASCII and canonical serial lines. Full supported geometry and
filesystem limits are in the design document. Remote Actions execution has
not been performed for this M7 change.
