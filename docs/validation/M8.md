## Host traces

`cargo xtask trace-compat` passed for musl and BusyBox echo/ls/cat/sh. Actual
QEMU-user `-strace` logs and output are under build/logs/compat-host-*.
Native ptrace was prohibited in this environment; these are QEMU-user traces
against Linux, explicitly not full native strace. Same-architecture exec may
leave QEMU-user, so individual applet traces supplement the parent shell trace.

Observed musl calls include arch_prctl, set_tid_address, ioctl, writev, mmap,
brk, the PROT_NONE brk guard, munmap, open, write, lseek, read, fstat, close,
unlink and exit_group. BusyBox ls additionally uses CLOEXEC open/fcntl,
getdents64 and lstat. ash adds identity/cwd/stat, signal queries/updates/masks,
pipe, fork, dup2, execve and wait4/WNOHANG. These observations drove the adapter.
Unsupported ioctls and custom signal actions remain real errors in AnovaOS.

## Actual guest checks

`cargo xtask test-compat` passes only with the full historical boot regression,
real Linux test markers and QEMU's isa-debug-exit status 33. The workloads are
independent Ring 3 ELF programs, not kernel functions or prewritten log output.

| Case | Required evidence |
| --- | --- |
| Freestanding Linux | argc/argv/envp/auxv; unknown number -> ENOSYS; EBADF/EFAULT/ENOENT; zeroed anonymous pages; FS base/invalid base; private fork and Linux wait status |
| Transactional exec | Missing executable leaves the caller alive; successful exec receives environment; CLOEXEC slot disappears, inherited shared description remains usable |
| SIGPIPE/random/time | A real broken pipe kills the default child with signal 13; ignored SIGPIPE returns EPIPE; checked RDRAND output; bad random pointer rejected; relative nanosleep returns |
| musl 1.2.4 | Real libc initialization and PT_TLS; volatile compiler TLS value; errno; 200,000-byte malloc/free; create/write/seek/read/fstat/close/unlink |
| BusyBox echo/ls/cat | Exact echo output; successful `/etc` directory listing; actual motd bytes; each process returns zero |
| BusyBox ash | Real fork/exec/wait pipeline and redirection; `/tmp/bb` checked byte-for-byte; 5,000-byte pipeline checked independently from VFS after the shell exits; false status expands to 1 |
| Memory negatives | Injected partial anonymous-map OOM rolls back; overlap does not publish a prefix mapping; after destruction frames and heap exactly match baseline |
| Reclamation | Every Linux workload exits, leaves no processes/descriptions/pipes, and restores frame and heap counts |

The gate requires these actual observations:

```text
[LINUX:MEMORY] partial_oom=rolled_back overlap=retained frames_restored=true heap_restored=true
[LINUX:PROBE] errno=true mmap=true TLS=true fork=true wait=true exec=true env=true CLOEXEC=true SIGPIPE=true random=true sleep=true
[LINUX:MUSL] TLS=true malloc=true errno=true file=true
[LINUX:BUSYBOX] applet=echo passed=true
[LINUX:BUSYBOX] applet=ls passed=true
[LINUX:BUSYBOX] applet=cat passed=true
[LINUX:SHELL] bytes=12 redirection=true verified=true
[LINUX:SHELL] bytes=5000 redirection=true verified=true
M8-status-1
```

Custom handler registration produces `[LINUX:ENOSYS] nr=13` in ash; this is an
expected documented limitation, not proof that signal handlers work. Other
unselected applets, ash trap/job control, Ctrl+C, threads, dynamic musl, glibc
and compilers remain unverified or unimplemented.

## Regression results

- Formatting and purpose inventory reviewed; host/kernel/application Clippy with
  warnings denied. 61 host tests, including shell parser tests, pass.
- Full `cargo xtask verify`: boot succeeds with exit 33; panic and heap OOM are
  classified as panic; timeout reaches injection; UD/GP/PF/DF/stack guard/RO/NX/
  direct-map NX/unmapped fault scenarios reach the expected real exception.
  All 13 scenarios pass their classifiers; no failure is ignored.
- `cargo xtask terminal-test`: two ordinary boots pass. The first also launches
  linux-musl and `/linux/sh` over actual UART, creates/reads a redirected pipeline
  file, sees output M8-UART and native status 0, then verifies EOF shell restart.
  The second verifies the original tmpfs file is absent after reboot.
- `cargo xtask persistence-test`: all six M7 scenarios pass: editor save, reboot
  and byte/SHA comparison, native ELF execution after reboot, clean e2fsck,
  read-only disk, unsupported features and actual write/flush EIO. Normal ACPI
  shutdown is required, not just a shutdown banner.
- CI has been updated with musl/make/QEMU-user prerequisites and host trace
  collection, but no remote Actions result is claimed.

Local logs remain in build/logs/. CPU/device/storage limitations from M7 remain;
this milestone adds selected static CLI compatibility, not a guest toolchain.
