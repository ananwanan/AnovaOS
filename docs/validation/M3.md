Every negative image reached its specific injection and was rejected as smoke.
M3 protection cases require vector 14 on IST2, CR2 equal to the actual injected
address, the expected present/write/instruction error bits and QEMU exit 37.
The OOM gate requires a 4 MiB request against the 2 MiB heap, the actual default
allocation error panic and QEMU exit 35. A generic panic cannot satisfy it.

The boot test repeatedly maps/touches/unmaps 256 pages and returns all leaf
and empty-table frames. It exhausts every free physical page, verifies a partial
map failure in an unused PML4 slot with only one spare frame, then restores
exactly the original free count. It rejects a reserved metadata page release,
wrong owner, unaligned/invalid frame and double release. Container stress
returns heap usage to zero, then successfully allocates the whole 2 MiB heap
as one block, proving coalescing.

Final review caught executable inherited HHDM aliases. The implementation now
marks the complete direct-map root range NX before activation, checks its
actual effective permissions and includes the direct-no-execute fetch above.
The final 13-case gate was run after that correction. Full exhaustion/stress is
compiled only into test images; the normal no-debug-exit run checks ownership
and protection without these pressure paths.

Full local transcripts/classifications remain under `build/logs/`; CI uploads
that directory even on failure. Historical M0/M1/M2 evidence remains unchanged
apart from links explaining the new current boundary.

## Limits and next task

M3 is accepted only for the stated BSP reference machine. Heap capacity remains
2 MiB; bootloader/firmware reservations are not reclaimed. Dynamic huge-leaf
editing, contiguous DMA, user address spaces, SMP shootdown and scheduling are
pending. Kernel-image HHDM aliases remain privileged writable/NX; full physical
immutability is not claimed. M4 adds the first isolated Ring 3 ELF application,
native syscall/user-copy boundaries and runtime/SDK, including CPU state required
by user SSE2. See [M3_MEMORY.md](../M3_MEMORY.md).
