## Actual device and recovery evidence

`cargo xtask graphics-test` exits 0. It builds a real graphics-feature kernel
and ISO, boots with standard VGA, captures QMP `screendump` P6 output and compares
all **480,000 pixels at 800×600** to the software reference. Independent known
pixels and a literal FNV-1a RGB checksum pin the reference rather than merely
letting an identically wrong renderer and comparator agree.

The device mode is 800×600×32, pitch 3,200; canonical RGB checksum is
`0x9ed06ea9b3ba5f91`. The kernel compares every visible byte read back after
volatile presentation and MFENCE. Its success marker also records supervisor,
NX and WC mapping validation. `[GRAPHICS:RECLAIM] heap_restored=true` follows
release of the temporary software buffer before any user process starts.

Limine returns exactly `0x80000000..0x801d4c00` as the framebuffer reservation.
The last page is partial: admission checks the actual byte span and separately
rejects page-rounded overlap with live RAM/firmware. The rounded mapped tail is
never written or read. The first trial conservatively rejected this valid map;
its genuine failure remains in `build/logs/graphics-initial-unrounded.serial.log`,
`graphics-initial-unrounded.result.txt` and `m14-graphics-initial-unrounded.log`.
The final device test exercises the corrected boundary on each run.

A second independent boot with `-vga none` requires
`[GRAPHICS:FALLBACK] reason=no-framebuffer`, rejects an unexpected PRESENT
marker and checks temporary heap restoration. Both scenarios execute
`echo M14-SERIAL-RECOVERY` through the actual UART shell, then `shutdown`.
Both exit 0 with `[POWER:OFF] synced=true clean=true dma_reset=true`.
A 30-second watchdog rejects hangs; fatal guest markers, early/nonzero exits,
missing/corrupt screenshots, bad checksums and fake shutdown do not pass.

Evidence remains in `build/logs/`:

- `graphics-test.result.txt`: aggregate success, invalidated before each build.
- `graphics.result.txt`, `graphics-no-display.result.txt`: exact QEMU invocation,

- `graphics{,-no-display}.serial.log`, `.qemu.log`, `.qmp.log`: actual guest and
  QMP traffic, including the host screendump command and correlated reply.
- `graphics.ppm`: real P6 scanout. SHA-256:
  `7311c0e55cd1ba490ff9c22fa764bfbcc2d64a5ad7617b15ddb11c4cc48a1d23`.
- `m14-graphics-command.log`: complete command output of the accepted graphics run.

## Host boundary and negative tests

The new dependency-free `anova-graphics` crate passes **19 host tests**:
checked dimensions/resource caps; unsupported channel sizes/overlap/shifts/bpp;
short pitches and length overflow; RGB/BGR and all byte-channel permutations;
24-bit packed/padded rows; non-byte-aligned valid 32-bit channels; buffer
canaries; extreme signed coordinates; independent rectangle/blit reference
models; invalid source rejection before mutation even when fully clipped;
short/mismatched presentation buffers; and pinned pattern pixels/checksums.

Five graphics host-tool tests cover strict P6 dimensions/format/header/raster
bounds, preservation of raster whitespace, corrupt pixels, false success,
timeout/fault/exit/shutdown rejection and actual UnixStream QMP framing with
asynchronous events, request IDs, explicit errors and oversized messages.
Real missing-display fallback is covered in QEMU; allocator-failure and malformed
hardware-mode/mapping fallback are not separately injected into a running guest.

## Limitations and next stage

M14.1 supplies CPU pixel/rectangle/blit presentation and COM1 text recovery.
Only standard VGA at 800×600×32 is accepted as an actual device mode; the other
bounded RGB formats are host-tested. No vblank/page-flip interface is available,
so the CPU copy promises no tear-free animation. Video memory stays reserved,
supervisor-only and outside both ordinary RAM allocation and application APIs.
There is no GPU rendering, graphical text/font terminal, input dispatcher,
window server, GUI SDK or new public GUI/kernel ABI. M14.2 input/cursor is next;
M14.3–M14.5 keep their independent gates. `run --graphics` uses GTK and is provided
for manual preview; interactive GTK/WSLg behavior has not been exercised here.
